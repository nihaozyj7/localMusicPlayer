# 铅字盘 · atlas

> 第三方播放界面样式包（契约 v3，`apiVersion: "3.0"`，`order: 280`）。
> **不与播放器源码耦合**：只走 `ctx` 契约，零项目 import。

**极限轴**：空间 / 装箱 —— 整个播放界面是一块**铺满的活字盘**，摄像机在盘面上巡游。

**一句话**：整篇歌词被拆成一根根长短不一的**铅字条**（横排 / 竖排打乱），在一片
「宽 = 2 × 最长句、高不限」的条带里按天际线**尽量密集地咬合铺满**；镜头跟着正在唱的
那一根移动，那一根会**沿自己的方向放大 1.45 倍**、字逐个**落版**（凹痕里升起来 +
一圈墨晕开）；曲末镜头拉远，把整块盘子还给你看一眼。

---

## 1. 包结构

```
atlas/
├── skin.json                  清单（能力 / 配色 / 帧预算 / 图标）
├── skin.js                    入口：mount / update / destroy + 两层画布与帧循环
├── skin.css                   舞台外壳、纸纹暗角、HUD（正文一个字都不在这里）
├── assets/icon.svg            样式卡片图标（遮罩友好）
├── lib/
│   ├── pack.js                世界：文本度量 → 造条 → 天际线装箱（纯逻辑，无 DOM）
│   ├── camera.js              摄像机：取景、阻尼、切镜、航线（纯逻辑，无 DOM）
│   └── timing.js              播放钟、逐字时间轴、落版进度（纯逻辑，无 DOM）
├── README.md
└── tests/
    ├── atlas-logic.test.js       纯逻辑自检（node --test，37 项）
    └── atlas-check.mjs           浏览器自检（自带静态服务 + 假宿主 + 无头 Edge，57 项）
```

子模块用 ``import(`./lib/<file>${Q}`)`` 加载，`Q = new URL(import.meta.url).search` ——
宿主的样式包是同源路由 `/skins/<id>/<file>?t=<token>`，丢了查询串会 403，
而且报错挂在**入口**上（自检里有一条静态扫描盯着）。lib 之间**不许互相 import**：
那会二次加载并丢掉 token，依赖一律当参数注入（`measure` / `split` 都是注入的）。

## 2. 画面结构（DOM 层次）

```
ctx.root（舞台）                              ← 清单声明 background:true，舞台铺满整窗
└─ .at                                      纸面（JS 写 --at-* 配色变量）
   ├─ .at__cv--wall   底图 canvas            整块盘子：纸底 + 盘边 + 航线 + 除当前条外的所有条
   ├─ .at__cv--live   活动 canvas            只有当前那一根条：挡板 + 凹痕 + 逐字落版 + 墨晕 + 悬停框
   ├─ .at__hud        两排读数（让开安全区）  行号 / 提示 / 曲名 / 密度 / 时间码
   ├─ .at__empty      空态（虚线底盘 + 一句话）
   └─ .at__poster     海报形态（showLyrics:false ⇒ 只剩曲名）
整窗背景层 ctx.backgroundRoot
└─ .at-bg                                     垫底色（舞台铺满整窗时它只是保险）
```

**为什么是两层 canvas**：当前条的逐字落版每帧都要重画，而它只占一根条。
底图那层（几百根条 + 航线 + 盘边）只在自己那一份「签名」变化时才重画 ——
静止时签名不变，**一个像素都不碰**（自检里量过：暂停后帧还在跳，`draws` 冻住）。

## 3. 数据映射

| 输入 | 驱动 | 落在哪 |
| :--- | :--- | :--- |
| `lyrics.lines[].text` | 条长（实测宽度，em）+ 竖排长度（Σ max(0.66, 单字宽)） | 装箱世界 |
| `lyrics.lines[].trans` | 条厚 +0.8em（副行带） | 双语条 |
| 空行 / 纯空白行 | 占位条（最少 1.1em）—— **不能丢**，丢了整篇行号错位 | 装箱世界 |
| `progress.position` | 当前行（二分）+ 摄像机目标 + 逐字点亮 | 全部 |
| `lyrics.lines[].words` | 逐字素的落版起点（增强 LRC） | `.at__cv--live` |
| `options.lyricsFontSize` | `emPx`（1em = 几像素）—— **只喂摄像机与绘制** | 视图 |
| `options.showLyrics:false` | 海报形态（`data-poster="1"`） | `.at` |
| `options.interactive:false` | **一个监听器都不挂**（点/滚轮都不生效） | `.at` |
| `options.animations:false` / `env.reducedMotion` | 不起帧；落版给终态、摄像机切镜；补丁来了画一帧 | `.at[data-anim="0"]` |
| `options.performanceMode:"performance"` | 逐字落版退回**连续填充扫描**、砍掉墨晕、按清单 30fps 限帧 | `.at[data-perf="1"]` |
| `env.width < 620` | HUD 收边、隐藏提示（盘面本身靠取景自适应） | `.at[data-narrow="1"]` |
| `ctx.spectrum().bands[0..13]` | **只调绘制参数**：墨光基线 ±8%、盘面薄雾 ±4% | 当前条光晕 |
| 点击某根条 | `screenToWorld` → `hitTest` → `ctx.actions.seek(那一句的 time)` | — |
| 滚轮 | 手动取景偏移（1.2s 后自动回中，与宿主歌词视图的 1200ms 暂停口径一致） | 摄像机 |
| 封面 | 取一个专色当强调色（太暗则退回清单 accent）→ `reportBackdrop`（400ms 防抖） | 航线 / 盘边 / 光晕 |

### 可观测读数（都写在 `.at` 的 `data-*` 上，自检与现网对账共用）

`data-bars` 条数 · `data-cols` 世界宽(em) · `data-h` 世界高(em) · `data-density` 密度 ·
`data-line` 当前行 · `data-lit` 当前行已落版字数 · `data-glyphs` 当前行字素数 ·
`data-drew` 本帧画了几根 · `data-culled` 本帧剔了几根 · `data-bass` 低频读数(0-100) ·
`data-idle` 停帧 · `data-playing` · `data-finale` · `data-mix` · `data-anim` · `data-perf` ·
`data-empty` · `data-poster` · `data-narrow` · `data-over`

## 4. 几个不显然的设计决定

### 4.1 条的长度为什么必须"实测"，不能用字符个数

中文一字 ≈ 1em，拉丁字母 ≈ 0.55em，而 `"WWW"` 比 `"aaa"` 宽一倍。按字符个数算长度，
遇到拉丁行会把宽度算小、装箱直接排不下。所以长度一律走注入的 `measure(text) -> em`
（浏览器里是 `measureText / 100`，`REF_PX = 100`），**装箱结果与用户字号无关** ——
拖歌词字号滑杆只换 `emPx`，世界一个像素都不重排（自检里断言 `W/H` 不变）。

容器宽 `W = 2 × (最长条 + 留缝)`。这个 "2" 的含义是「**任意两根横条都能共享一行**」
（每根 ≤ W/2）——"最长的两根并排刚好填满一行"永远成立，这是密集度的地基。

### 4.2 天际线装箱，不是货架

歌词里短行、空行极多。货架（shelf）只能一行行铺、留大片空隙；天际线能把**竖条塞进
横条留下的缝里**，这才是"密集"的来源。实测 120 行样本：天际线 54.47em 高 /
密度 0.929，货架 60.63em —— 省下 10% 的高度。

代价是**顺序被打散**：第 30 根条可能在世界最上面。所以盘面上画了一条**航线**
（把时间顺序的条心连起来，唱过的留余温、当前→下一句最亮），这是观众唯一能看见
"歌怎么走"的地方。

### 4.3 朝向打乱是 hash 驱动、且有价格上限

`mix = 0.5`：按 `hash01(序号)` 决定"想不想翻"，但只在**次优朝向的顶边不贵超过
0.5 × mix** 时才真翻。于是纹理乱了、密度几乎不掉（300 行样本：密度 0.933 不变，
翻向 45 根）。**不用 `Math.random`** —— 布局必须是位置/序号的纯函数，否则每次重算
画面都会跳（自检里断言同一份输入两次装箱逐字节相同）。

### 4.4 摄像机是 cover（铺满），不是 contain（缩在中间）

盘子宽只有 `2 × 最长句`，如果按"整块塞进来"取景，画面两侧会空掉一大半
（实测只占 73% 宽），密集装箱这件辛苦事就白做了。所以取景倍率取
`max(按宽铺满, 按高铺满)`：长歌按宽铺满、纵向靠巡游；短歌按高铺满、横向裁一部分。
上限 `K_MAX = 3.2`（再放大就只剩一行字，不像"盘"了）。
平移用临界阻尼（τ≈220ms，**永不过冲**），目标离得超过 1.6 个视口就**切镜**；
`progress` 一次跳 1.5 秒以上（= 用户拖了进度条）也认定是 seek，一样切镜。

### 4.5 "还没唱到的字"必须是读得清的

这一款是**歌词展示器**，观众永远在提前读下一句。最初把凹痕做成 8% 透明度的
"淡淡印子"，在深底上只有约 1.5:1 —— 好看，但等于把歌词藏起来。改成 **50%**：
压在挡板上是 4.8:1（自检**按像素**量，不是算公式），"落版"的表现力改由
**抬起来**承担 —— 没唱的字暗一半、压低一点（像陷在纸里），唱到就升起来变满、
晕开一圈墨。同理，各根条的明暗下限锁在 0.62：过去/将来靠**色相**区分
（唱过的偏强调色），不靠明暗，否则远处的句子就没法读了。

### 4.6 频谱绝不进几何

频谱只调**墨光基线**（±8%）与盘面薄雾（±4%）。一旦让它参与装箱或行高，
"换帧重排"会把帧预算烧光，画面也会随频段抖动而抽筋。
自检里有一条直接的断言：把低频从 0 拉到满，世界的 `W/H` 与每一根条的
`x/y/dir` **一个数都不许变**。

## 5. 性能与省电

- **两层画布的脏签名**：底图层只在「摄像机 / 当前行 / 曲末扫描 / 频谱包络 / 视口剔除 /
  悬停」变化时重画；活动层只在「行号 / 落版进度 / 抬起量 / 机位」变化时重画。
  暂停后机位到站、落版走完 ⇒ 两个签名都不再变 ⇒ **零绘制**（实测：帧循环还在跳，
  `draws` 从 36 冻在 36）。
- **视口剔除**：420 行的长歌一帧只画 16 根、剔掉 403 根（`data-drew` / `data-culled`）。
- **竖排条走离屏位图**：横竖交错的盘面上，竖条常常是"整根不动"的，而逐字 `fillText`
  一根 12 字的竖条要 12 次调用。缓存后每帧一次 `drawImage`。**只有在机位倍率稳定时
  才用缓存** —— 缩放动起来时每帧重建几十张位图比直接画还贵。
- **一个 rAF**，`budgetFps` 限帧（性能档 `min(清单, 24)`）；暂停 6s 停帧；
  `close` / `env.foreground:false` 立刻停帧；`animations:false` 一帧都不起。
- 实测一帧（420 行、切镜后整块重画）：**0.67ms**；首次冷缓存（要建竖排位图）约 17ms。

## 6. 自检

```powershell
# 纯逻辑（37 项）：装箱、摄像机、时间，以及 skin.js / skin.css / skin.json 的静态纪律扫描
node --test "plugins/style/atlas/tests/*.test.js"

# 浏览器（57 项）：自带静态服务 + 假宿主 + 无头 Edge（--shots 额外落几张截图供肉眼复核）
node plugins/style/atlas/tests/atlas-check.mjs

# 真机（33 项）：真 WebView2 + 真 CSP + /skins/ token 路由 + 真频谱 + 真歌词
node .tmp-skin-live.mjs --skin atlas        # 需要 bin/lmplayer.exe 与一个没有占用单实例锁的环境
```

浏览器自检为什么要把 `requestAnimationFrame` 换成定时器：headless 下合成器不给
BeginFrame（rAF 一次都不来，`document.hidden` 还是 `false`），样式自己的帧循环会
一帧都不跑。

### 自检抓出来的、只有真机才会暴露的三个坑（都已修）

| # | 现象 | 根因 |
| :--- | :--- | :--- |
| 1 | 真机上一直在跑**性能兜底档**（逐字落版整个消失），而浏览器自检全绿 | 契约里 `performanceMode` 是**字符串** `"smooth" \| "performance"`，`Boolean("smooth")` 恒真。自检当时喂的是布尔值 —— 现在自检喂字符串，并断言 `"smooth"` 不许被判成性能档 |
| 2 | 真频谱永远是 0（辉光基线一动不动） | `ctx.spectrum()` 返回的是**快照对象** `{bands, at}`，不是数组；写成 `sp.length` 永远读到 `undefined` |
| 3 | 真机自检的「亮像素不许减少」过不了 | 底图 canvas 原本是透明的，亮像素数反映的是"镜头刚好扫到多少字"，机位一动就抖。改成**不透明的纸**（先整块铺底色）：既符合"这是一张纸"的物理直觉，也让装饰层可以放心压在画布上面 |

## 7. 明确不做的（以及为什么）

| 不做 | 理由 |
| :--- | :--- |
| 整盘缩放动画（跟着频谱呼吸） | 会让装箱结果每帧重排／位图缓存全废，帧预算扛不住 |
| 逐字素 DOM span | 整篇歌词是 canvas 画的；一行 300 根条 × 每根 10 个字素 = 3000 个节点，只为动画服务不值 |
| 段落分块装箱（每段一块，减少航线跨屏） | 用户的验收口径是"尽量排版密集"，单区装箱的密度更高；航线已经解决了"顺序被打散"的表达问题 |
| 译文在竖排条里也画 | 竖排的双语条要再切一条窄列，密度会掉一档；竖排条只画正文，横排条带副行 |

## 8. 装到播放器里

把整个目录拷到 `%APPDATA%\LocalMusicPlayer\player-skins\atlas\`（或从客户端的
「添加播放界面样式」里拉 `plugins/style/index.json` 这一项），然后在播放详情页的
样式切换里选「铅字盘」。改完源码要重新拷过去再「重新扫描样式」。
