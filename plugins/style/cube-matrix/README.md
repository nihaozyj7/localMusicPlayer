# cube-matrix — 律动方块

一句话：**一台铺在透视地面上的 3D 频谱分析仪。**

15 × 11 根柱子按画家算法从远到近画（真的 3D：顶面亮、两个侧面暗、柱脚有接地阴影）。
两个轴都有明确语义：

- **横向 15 列 = 频率轴**：最左是最低频段，最右是最高频段。宿主给的 128 段对数谱
  按列等分取均值，再做高频倾斜补偿（`LEVEL.tiltBase`）与 gamma —— 不做补偿的话
  右半边永远贴地，看着像「只有左边在动」。
- **纵深 11 行 = 时间轴**：最后一行（最靠近观察者）是**最新**的谱，越往后越旧，
  每行相差 `HISTORY.samplesPerRow` 个频谱样本（≈66ms）。于是纵深滚动的是
  **真实的频谱历史**（瀑布图），而不是造出来的波浪。

色相 = 基础漂移 + 列的彩虹跨度 + 高度推色 + 重拍冲量，于是整幅画面在
**紫 → 青 → 绿 → 橙**之间持续流动。节拍来时整场泛亮一下。

> ★ **不要再往高度里加「节奏感」的正弦**。第一版就是这么干的（柱高 = 频段 ×
> `(0.45 + 0.55·sin)`，再加一条常驻待机正弦），结果画面在自己起伏、和音乐无关 ——
> 用户一眼就看出来了。现在柱高**只**由频段能量决定，自检里有一条
> 「谱固定 + 色相冻结 → 画面必须静止」的断言专门钉这一点。

## 它是怎么动起来的

只有一个输入：`ctx.spectrum()` 给的 128 段对数全谱（拉取式，清单里声明了
`capabilities.spectrum`）。

1. **采样 → 列电平**：`fillColumnLevels()` 把 128 段按列等分取均值，乘高频倾斜、
   做 gamma，得到 15 个 0..1 的列电平。
2. **包络**：每个频段跑三条**快升慢降**的包络（`SMOOTH`：快 8/70ms、主 20/150ms、
   慢 120/900ms）。柱高吃「主」那一套 —— 对称平滑会把鼓点削平，看着像原地游动。
   一条包络都不额外叠加与音频无关的振荡。
3. **历史推进**：只有在 `spec.at`（采样时刻）变化时才推进，每攒够
   `HISTORY.samplesPerRow` 个样本滚动一行；暂停后历史按 `HISTORY.idleDecay` 慢慢
   落回地面。**按帧推进是错的**（帧率会把时间轴拉伸）。
4. **高度**：`base + 电平 × specAmp`，再乘一个**随年龄固定**的衰减
   （`CUBE.ageFalloff`，越旧越低，给纵深层次；它与时钟无关，所以谱不动时画面完全静止）。
5. **颜色**：色相 = `时间 × 9°/s` + `质心 × 110°` + `列的彩虹跨度 190°` + `高度 × 70°`；
   能量越高越亮越饱和，一记重拍（频谱通量超阈值，0.32s 冷却）再把色相顶 26°。
6. **镜头**：常驻 0.16 rad 的侧看偏角（正对着看时柱子侧面几乎看不见）+ 46 秒周期的
   0.26 rad 左右摆动。每帧按网格四角的包围盒做横向居中补偿、按前沿地面做纵向收缩，
   所以宽窗口 / 窄窗口都不会「矩阵偏在一边」或「地板掉出画外」。
7. **帧循环**：只有一条 `requestAnimationFrame`。有频谱时按 `budgetFps`（45）画，
   待机时降到 26fps，连续 18 秒没有活动就彻底停帧（任何一条宿主补丁都会把它拉起来）。
   设置里关掉动效（或系统要求减少动效）时只画一帧静态画面（按当前谱直接摆好）。

## 想改效果，先改这里

全部数值都在 `lib/config.js`：

| 常量 | 管什么 |
| :--- | :--- |
| `GRID` | 列（频率轴）× 行（时间轴）、格间缝隙 |
| `CAM` | 透视强度、常驻偏角、摆动幅度与周期、俯视角、高度伸缩、地面位置、适配尺度 |
| `CUBE` | 底座高度、频谱增幅、待机幅度、高度上限、快升慢降时间常数、年龄衰减 |
| `LEVEL` | 128 段 → 列的映射：高频倾斜、取样宽度、gamma |
| `HISTORY` | 一行几个样本、暂停后的衰减系数 |
| `SMOOTH` | 快 / 主 / 慢三档包络的上升与下落时间常数 |
| `COLOR` | 色相漂移速度、彩虹跨度、每行偏移、高度推色、三面明暗差 |
| `PERF` / `BEAT` | 目标帧率、待机帧率、停帧时间；打击阈值与冷却 |

改完跑一次 `render-shot.mjs` 出图看效果（它会打印 PNG 路径）。

## 自检

```powershell
# 纯逻辑（零依赖，不需要浏览器、不需要起服务）
node --test "plugins/style/cube-matrix/tests/*.test.js"

# 画布像素 + HUD 几何 + destroy 静止（无头 Edge，自带假宿主，最后出图）
node plugins/style/cube-matrix/tests/render-shot.mjs
```

`render-shot.mjs` 验的都是**量出来**的东西：

- 方块真的画出来了（非背景像素数）；
- **横向就是频率轴**：低频满时左半区起柱、高频满时右半区起柱；
- **画面不会自己起伏**：谱固定 + 色相冻结时，两次隔 1.3s 的像素统计必须一致
  （旧版掺了正弦假节奏，这条会红）；颜色放活后像素签名必须变（色相在走）；
- HUD 的 `padding-top ≥ --skin-inset-top`、歌词底边 `≤ 舞台高 - --skin-inset-bottom`；
- 点歌词触发一次 `ctx.actions.seek(本句时间)`；
- `destroy` 之后两次取像素完全一致（帧循环停干净了）。

> headless 下合成器不给 BeginFrame（`requestAnimationFrame` 一次都不来），
> 所以脚本把 rAF 换成定时器来驱动帧循环；整屏 `Page.captureScreenshot` 也可能
> 拿到空白图（合成器不出帧），因此画布内容走 `canvas.toDataURL` 导出 —— 与合成器无关。
> 测「形状静止」时脚本会把 `CAM.yawAmp` 与 `COLOR.hueSpeed` 临时清零（同一模块实例），
> 否则相机摆动与色相流动本身就会让像素变，测不出柱高有没有乱动。

## 安装

```powershell
Copy-Item plugins\style\cube-matrix "$env:APPDATA\LocalMusicPlayer\player-skins\" -Recurse -Force
```

然后设置 → 播放界面样式 → 「重新扫描样式」。也可以在设置里点「导入样式」，
直接选中 `plugins/style/cube-matrix` 这个目录。

## 已知限制

- 只画 2D canvas（`alpha: false`），软件光栅下开销主要来自「柱数 × 3 个多边形」：
  165 根柱 ≈ 660 个路径/帧。想更省就减 `GRID` 或降 `PERF.budgetFps`。
- 真机上的帧耗时没有自动化断言（headless 的 rAF 被定时器替换了），只在
  1440×900 / 1280×800 / 900×620 三档画面上人眼验过。
- 歌词只显示**当前一句**（按产品决定）：没有逐字点亮，也没有前后句淡出。
