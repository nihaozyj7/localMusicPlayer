# 拓印 rubbing

> 第三方播放界面样式（**不是内置样式**，本体只在本仓库的 `plugins/style/` 下管理）。
> 视觉极限轴：**图像数据化 + 粒子物理** —— 先在纸上压出一行灰字，再用这张封面的多色颗粒一粒一粒把它填满。

```
rubbing/
├── skin.json              清单（id / order 220 / capabilities / colors / budgetFps 45）
├── skin.js                入口：帧循环、灰字底层、字形掩码、逐粒填充时刻表、封面取色、自适应降级
├── skin.css               全部视觉（画布、HUD、刻度、背景层内容）
├── assets/icon.svg        样式按钮图标（单色线稿，宿主当 alpha mask 用）
├── lib/
│   ├── palette.js         封面像素 → 色阶（纯函数）+ 颜料兜底
│   ├── glyph.js           文字 → 掩码 → 目标点 → 字素时间窗 → 逐粒填充时刻表（纯函数）
│   └── field.js           粒子池（SoA）+ 填充/抖动/下沉 + 帧预算/自适应降级（纯函数）
```

## 1. 安装

播放器**不读本目录**，它只认数据目录里的样式包：

```powershell
$dst = "$env:APPDATA\LocalMusicPlayer\player-skins\rubbing"
New-Item -ItemType Directory -Force -Path $dst | Out-Null
Copy-Item -Recurse -Force plugins\style\rubbing\* $dst
```

然后在播放器里「设置 → 播放界面样式 → 重新扫描」。客户端里也可以直接「添加播放界面样式 →
从仓库获取」（读的是 `plugins/style/index.json`，见 `plugins/README.md`）。

## 2. 它长什么样

**核心模型（一句话）**：画布上先有一行**灰字**，粒子是**填**上去的；一个字的粒子在**这个字的时间窗内**
逐粒起飞、逐粒落定，唱到哪就填到哪。粒子位置**只是歌曲位置的纯函数**，没有弹簧、没有累积状态。

| 画面元素 | 做法 | 数据来源 |
| :--- | :--- | :--- |
| 灰字底层 | 当前这句离屏渲染成 420~1280 × 150~460 的掩码，取字色 `--rb-fg` 的 **0.52 透明度**画在最下面 | `lyrics.lines[].text` |
| 粒子目标点 | 掩码墨点膨胀一圈后随机抽 4000~16000 个点，映射到舞台（与灰字**同一套几何**，逐像素重合） | 同上 |
| 粒子颜色 | 每粒按**自己的相对位置**去 64×64 封面采样取像素 → 色相吸附到 6 档**彩色阶梯**；灰阶封面/无封面走 6 色颜料兜底 | `ctx.media().cover` |
| 逐粒填充 | 每粒一个 `inkAt`（起飞时刻）+ `fly`（飞行时长 150~240ms），`e = easeOutCubic((pos-inkAt)/fly)` —— 同一个字内每粒错开，**一粒一粒**填进去 | `lyrics.lines[].words` |
| 逐字/逐行 | 有 `words` → 每个字素一个窗口（第 k 个字的结束 = 第 k+1 个字的开始）；没有 → 整行共用一个窗口铺满 | 同上 |
| 亮度分层 | 灰尘 0.18 / 飞行中 0.8 / 已落定 1.0（批次 = 色桶 × 亮度档 = 18 次 `fillStyle`），亮度只表达"填到没有"，颜色只表达"哪一色" | 同上 |
| 颗粒大小 | 按档位分三级（`field.GRAIN`）：灰尘 1 / 飞行 1.25 / **落定 1.85** —— 落定的颗粒按面积 ×3.4，整句唱完时**盖掉 65% 的笔画**（原来的 1.85px 方点只能盖 30%，是"撒彩砂"而不是"填满"）；调用次数不变 | — |
| 抖动 | 每粒回位弹簧 + 相位错开的随机力，抖动幅度随落定收敛（灰尘 1.0 → 落定 0.06） | — |
| 湍流 | 频谱 0..12 段均值 → 每粒的随机加速度（相位错开，不会整体漂移） | `ctx.spectrum()` |
| 撒沙 | 切句时给每粒一次随机冲量，同时 `--rb-flux` 让整块画布"扬起"420ms | 行号变化 |
| 暂停 | 灰尘整体压到地板上堆积（**不是冻结**，已落定的粒子纹丝不动、灰字仍可读），6 秒后才停帧 | `ctx.playback().playing` |
| 指针磁铁 | `pointermove` → 半径 74px 内的粒子被推开；`interactive:false` 时监听都不挂 | `ctx.options().interactive` |
| 整窗背景 | 封面第二份 `blur(34px)` + 面纱 + CSS 点阵砂纸颗粒 | `ctx.media().cover` |
| HUD | 曲名 / 艺人·专辑 / 试听角标 / 时间码 / 48 格进度刻度（只在变化时写 DOM） | `ctx.track()` `ctx.playback()` |
| 宿主壳配色 | `reportBackdrop({bg, fg, accent})`（400ms 防抖）+ 清单 `colors` 兜底 | 封面取色 |

> **不要按"粒子聚成字"去理解这一款。** 2026-10 之前它是"粒子飞过来聚成字形"：字要靠粒子堆出来，
> 而弹簧的沉降时间（~2.5s）比一个字（200~300ms）长得多 —— 结果是**永远追不上节奏**，而且粒子聚拢的
> 中途根本看不出是哪个字。现在是反过来：**字一直在那里（灰的），粒子只是把它盖成彩色的**。
>
> **"填满"是量出来的，不是感觉出来的**：粒子数按舞台面积算（1100×700 → 4968 粒），而一句歌词的
> 笔画面积有 ~5.7 万像素 —— 1.85px 的方点只够盖 30%，所以落定的颗粒要 ×1.85（面积 ×3.4），
> 整句唱完时覆盖率 ~65%（`rubbing-check.mjs` 有一条整句尺度的断言直接量这个比值，低于 50% 就红）。
> 剩下的 35% 是颗粒之间的缝，灰字从缝里透出来 —— 这正是"拓印"要的质感，不是缺陷。
>
> **配色口径（2026-10 修订）**：上报给宿主的 `bg`、以及 HUD 自己用的 `--rb-fg` 所依据的底，
> **不是封面本身**，而是「封面 → `.rbbg__img` 的 `blur(34px) brightness(0.46)` → `.rbbg__veil` 暗纱」
> 之后的**合成色**（再亮的封面压完也是近黑）。换算在 `lib/palette.js#backdropUnderCover`，
> 参数与 `skin.css` 同源（纯逻辑自检会比对两侧）。
> 早期版本拿未压暗的封面主色当选色依据 —— 封面比 ~0.17 亮就选出深色字，压在近黑的底上
> （实测 ~1.1:1），宿主壳（标题栏 / 底栏 / 侧栏）与 HUD 一起看不见。`accent` 现在也一起上报：
> 宿主壳的进度条 / 音量条 / 播放键 / 播放模式按钮走 `--accent` 家族，不报就会永远停在清单里
> 那个静态专色上、与封面无关。
>
> **粒子颜色不再是封面亮度**。以前直接拿封面像素当粒子色，深色封面 → 深色颗粒，压在近黑的底上等于没画。
> 现在亮度只由"填充层级"决定（灰尘 / 飞行 / 落定三档），色相从封面像素取、**强制吸附到可见彩度带**
> （`palette.vividRamp`：饱和度 0.36~0.82、亮度 0.5~0.72），再叠 34% 的随机抖动 —— 所以是
> **多色**的，而且暗封面也照样看得见。灰阶封面或没有封面时退回 6 色颜料（朱砂 / 藤黄 / 石青 / 石绿 / 赭石 / 米白）。

封面是 data URL 或同源 `/online/cover` 代理，`drawImage` + `getImageData` 不会被污染（无需 `crossOrigin`）。

## 3. 契约用法（对照组）

| 用到的 | 说明 |
| :--- | :--- |
| `ctx.root` / `ctx.backgroundRoot` | 舞台与整窗背景层的容器。**背景层的内容是本包填的**，`destroy` 时自己清空并隐藏 |
| `ctx.options()` | `animations` / `interactive` / `performanceMode` / `showLyrics` |
| `ctx.env()` | `width` / `height` / `dpr` / `reducedMotion` |
| `ctx.track()` / `ctx.media()` / `ctx.playback()` | 曲目、封面、歌词、进度 |
| `ctx.spectrum()` | 128 段对数谱（拉取式，宿主已节流到 ~30Hz，**音量后取谱**） |
| `ctx.actions.reportBackdrop` | 把**合成底 + 字色 + 封面强调色**上报给宿主壳 |
| `ctx.sdk.splitGraphemes` / `html.*` | 字素切分（必须与 `words` 下标同一份切法）/ 空态文案、封面兜底 |

**没有用**的东西（都是坑，见 `pending-designs.md` §1.3）：`ctx.assets`、`ctx.log`、
`capabilities.paintSelf`（宿主解析了但没有消费者）、`sdk.createFxLyrics` / `createLyricsView`
（要宿主骨架样式表）。粒子是自己画的：`<canvas>` + 定长类型化数组。

> `ctx.actions.seek` 已经**删掉**了：画面上只有当前这句歌词，灰字与粒子都只跟"当前句"有关，
> 点它跳到本句开头没有任何意义（而且会与进度条的拖动互相打架）。`capabilities.interactive: true`
> 现在只为指针磁铁服务。

## 4. 降级矩阵（都是实测过行为的，不是"应该会"）

| 条件 | 表现 |
| :--- | :--- |
| `options.animations === false` 或 `env.reducedMotion === true` | 只算一次几何并把粒子瞬移落定，**只画一帧**、**一次频谱都不读**；CSS 过渡一并关掉 |
| `options.showLyrics === false` | 画布隐藏、灰字清空、整池退回灰尘（不做逐字跟踪） |
| `options.performanceMode === "performance"` | 粒子数 ÷3、帧循环按清单 `budgetFps: 45` 限帧、画布不再叠 `contrast()` 滤镜 |
| `options.performanceMode === "smooth"` | 不限帧（交 rAF）；写 DOM 前做过差值判断 |
| 画布耗时连续两帧超预算 | 自适应退档 `data-lod` 0→3（粒子 ×1 / ×0.66 / ×0.45 / ×0.30，后两档同时半分辨率，8 秒后不再退） |
| 暂停 / 无音频 | 灰尘下沉到地板堆积，已落定的粒子留在字上（灰字仍可读），6 秒后停帧（`[data-idle]`） |
| `visibility: {foreground:false}` | 立即停帧；回到前台且仍在播放时自动恢复 |
| `close`（详情页收起） | 停帧 + 隐藏整窗背景层 |
| 无封面 | 6 色**颜料**兜底（不是单色沙），不取色、不报错 |
| `lyrics.lines[].words` 缺字 / 与字素数不一致 | 该行退回"整行一起亮"（否则下标串位会点错字） |
| 无歌词 / 无歌 | 显示 `sdk.html.lyricsEmptyText()`，整池退化成灰尘（画面不是白屏） |
| 非 16:9 视口 / 极窄窗口 | 字形带按舞台宽度等比缩放（`fitPoints` 不变形），画布按 dpr 重设 backing store |
| 拖动进度条 | 画面**跟着变**而不是错位：`e` 完全由歌曲位置算出来，跳到哪里就填到哪里 |

## 5. 自检

```powershell
# 纯逻辑 + 契约静态体检（不需要浏览器，~0.2s）
node --test "plugins/style/rubbing/tests/*.test.js"

# 浏览器里的真实观感（自带静态服务 + 假宿主 + 系统自带 Edge）
node plugins/style/rubbing/tests/rubbing-check.mjs
```

`rubbing-check.mjs` 覆盖（87 项）：挂载无报错、画布上真的出现了**非背景像素**、
**灰字底层确实画出来了**（按 alpha 0.32~0.7 + 近灰 + 够亮三层条件从画布上量出来，并与粒子层分开）、
灰字与粒子目标点是**同一套几何**（`data-base` 报出的 x/y/字号 与掩码中心映射点一致）、
**逐粒填充严格单调**（`data-fill` 在同一字窗内 5 次采样逐次增加）、**整句唱完时灰字被盖掉 ≥50%**、
灰字被逐渐盖掉但全程都在、亮像素的质心随进度往右推（不是整行一起亮）、暂停后灰尘继续下落、
`animations:false` 时零帧零取谱、`data-lod` 在慢帧下真的退档、`showLyrics:false` / 无歌词 / 空态三种退化、
窄窗口不横向溢出、`destroy` 后舞台与整窗背景层都干净
（这是第三方样式最容易漏的地方：背景层容器是宿主的，宿主不会替你清）。

加 `--shot <目录>` 可以额外截 4 张整页 PNG（灰字刚压出来 → 第一个字快填满 → 逐字推进 → 整句填满），
给"逐粒填充"留一份肉眼可核对的证据：

```powershell
node plugins/style/rubbing/tests/rubbing-check.mjs --shot .tmp-rubbing-shots
```

## 6. 已知边界

- 一万多个 `fillRect` 是这一款最贵的地方：1080p 大约 5000 个粒子，4K + dpr2 会顶到 16000 上限。
  低端机上靠自适应降级退到 30%（画面变稀、覆盖率下降，但字仍然成形 —— 因为灰字一直在）。
- 覆盖率与粒子数直接挂钩（4968 粒 / 5.7 万笔画像素 ≈ 65%）：把窗口拉得特别大（4K + dpr2）时
  粒子数被 clamp 在 16000，覆盖率反而会比 1080p 低一些 —— 颗粒更粗、缝更宽，但灰字仍然读得清。
- 逐字进度依赖 `words` 的千分位精度；纯 `[mm:ss]` 的行级歌词只能整行一起亮。
- 掩码渲染用的是系统字体栈（`Segoe UI` / `Microsoft YaHei`）：同一句歌词在不同机器上
  笔画粗细会有差别（目标点跟着笔画走，所以观感一致，只是颗粒疏密不同）。
- 换封面会重算色桶（一次 64×64 采样 + 一次目标点重建）。目标点与分组现在是**按文本+尺寸派生**的
  确定性随机流，所以重建后目标点逐粒相同、画面不会跳，只有颜色换掉。
- "几何"与"时刻表"必须一起换（`computeTargets` 里 `applyGeometry` 后面紧跟 `applyInk`）：
  只换几何不重排时刻表，粒子会按**旧的随机分组**飞，表现是每个字都有几粒提前落定、整行一起亮。
