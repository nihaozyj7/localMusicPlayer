第六个公开版本。这一版修掉了「**在线歌曲下载之后，再点试听就找不到歌曲**」的缺陷，
给搜索结果加上**「已下载」标注**（标注之前会重新确认文件还在不在），
并给试听缓存补上**空闲清理**与一份**来源台账**；两份 README 也改用**真实应用截图**重拍。

> 命名：仓库 / 项目全名 **localMusicPlayer**，中文名 **本地音乐播放器**，
> 应用标题与可执行文件是 **LMPlayer** / `lmplayer.exe`。

## 修复

- **下载过的在线歌曲，再点试听会「找不到歌曲、无法播放」**。
  根因是下载把试听缓存**搬走**了（`MovePath`）：音频文件从缓存目录移进下载目录，
  而播放链路仍然按缓存路径解析（缓存索引里那条记录还在，文件却没了）。
  现在下载改成**复制**（`CopyPath`）——下载目录拿到一份，缓存**原地留着**，
  于是「下载之后回头再听」照旧走缓存，也顺带不会为同一首歌重复消耗流量。
  复制路径与缓存路径都由 `internal/onlinecache` 的原子落盘保证完整。

## 新增

- **搜索结果的「已下载」标注**。下载过的歌曲在搜索列表里带一枚标注，
  鼠标悬停显示下载到了哪个目录，按钮从「下载」变成「再下载」。
  关键是标注**不是缓存的结论**：显示之前会拿台账里的路径**重新 stat 一次**，
  文件被用户删掉（或移走）时标注与「再下载」一起消失，不会误导人以为本地还有。

- **在线来源台账**（`%APPDATA%\LocalMusicPlayer\online-sources.jsonl`）。
  一行一条 jsonl，记录每条试听缓存与每个下载：bvid、标题、歌手、扩展名、路径、
  来源（缓存 / 下载、来自哪儿）、时间。它是**追加写**的（进程被杀死最多丢半行，
  半行会被跳过而不是让整份台账失效），同一 (bvid, kind) 后者胜。
  「已下载」标注与清理的引用判定都读它；存在性一律在读取时 stat，不写死在文件里。

- **试听缓存的空闲清理**。缓存放系统临时目录，是可丢弃的派生数据；这一版给它加了
  一套**保守**的回收判据 —— 删错一份用户就得重下一次，所以每条判据都偏保守：

  | 判据 | 取值 | 为什么 |
  | :--- | :--- | :--- |
  | 多久没声音才算空闲 | 5 分钟 | 一首歌 3~5 分钟；再短会在「暂停一下去倒水」时动手 |
  | 多久检查一次 | 1 分钟 | 明显短于空闲门槛，见下面那条修复 |
  | 启动后的宽限 | 3 分钟 | 启动期在扫库、算响度、解包 ffmpeg，不凑热闹 |
  | 闲置多久才允许删 | 7 天 | 一周没被碰过、又不在任何引用里，才是真正的长尾 |
  | 磁盘压力条款 | 缓存超预算时降到 24 小时 | 真占满了才放宽，平时保持保守 |
  | 两次清理的最小间隔 | 30 分钟 | 清理不是越勤越好 |
  | 一次最多删 | 64 个文件 / 128MB | 空闲不等于可以长时间占磁盘，剩下的下一轮再说 |

  **三处引用，缺一处都不删**：① 歌单与「我喜欢」（后端配置）；② 播放队列
  （队列只存在前端，所以前端在队列变化时把在线 id 推给后端）；③ 当前装载 / 正在播放的
  那一首 —— **暂停不算空闲**，否则你点一下继续就得重新下载。

- **清理的检查间隔必须是 1 分钟（顺手修掉的一个时序缺陷）**。这一条来自实测：
  两个计时器起点不同（`lastActive` 在构造时起算、ticker 在 `Start` 时起算），
  间隔原本也取 5 分钟时，「启动后的第一跳」几乎正好落在「空闲满 5 分钟」那一刻，
  判据是严格小于才跳过，差几毫秒就跳过这一跳，而下一跳要再等一整个 5 分钟 ——
  实测出现**应用空闲 9 分钟、缓存一个字节都没回收**。现在间隔取 1 分钟
  （最坏只多等 1 分钟），并加了不变量测试 `TestCleanupTickLeavesMarginBelowIdleThreshold`
  与边界测试 `TestCleanupTickAcceptsExactlyIdleThreshold` 把这件事钉住。

## 系统要求

- Windows 10 1809+ / Windows 11（x64）
- [WebView2 运行时](https://developer.microsoft.com/microsoft-edge/webview2/) —— Windows 11 与较新的 Windows 10 已预装

首次运行会在数据目录解包内嵌的 FFmpeg：

```text
%APPDATA%\LocalMusicPlayer\             配置、曲库缓存、歌词与封面缓存、在线来源台账
%LOCALAPPDATA%\LocalMusicPlayer\bin\    解包出来的 ffmpeg.exe（可以直接替换）
%TEMP%\LocalMusicPlayer\online\         在线试听的音频缓存（可随时删除，空闲时会自动回收）
```

## 从旧版本升级

直接覆盖 `lmplayer.exe` 即可，配置、歌单、曲库缓存与下载都在原处，不受影响。

两点变化值得知道：

1. 以前「下载」会把试听缓存搬走，现在只复制一份 —— 下载目录里那首歌的位置不变，
   只是缓存不再消失（占用仍在 `%TEMP%` 下，并且会被上面的空闲清理回收）；
2. 第一次启动 0.2.0 时台账是空的，**旧的已下载歌曲不会立刻带上「已下载」标注**；
   在设置里重新下载一次、或重新试听一次，台账就会记下它 —— 之后标注与清理都以台账为准。
