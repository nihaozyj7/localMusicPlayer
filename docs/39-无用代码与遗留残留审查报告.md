### 重要方法学澄清（决定了本报告的真实性）

审查过程中出现了若干**看似是死代码、实际不是**的情形，已在报告中剔除，此处集中说明，以免读者被静态计数误导：

1. **`audio.js#audioGraphState` — 不是死代码。**
   它在本仓库源码内确实零引用，但被 3 个自检脚本通过浏览器侧动态导入调用：
   `tools/e2e.mjs:196`、`tools/loudtest.mjs:149`、`tools/playtest.mjs:155`（形如 `await import('/js/audio.js')` 后调 `mod.audioGraphState()`）。静态文本分析抓不到这种用法。
2. **`internal/audioplay/effects_reverb.go`（混响）— 不是死代码，切勿删除。**
   v0.1.4 提交信息写「移除混响音效」，容易被理解为整个模块已废弃。实际是该提交只移除了 `live`（现场感）/`hall`（大厅混响）两个**独立档位**；12 个提交后的 `2624e6d`（重写 3D 环绕）把混响**重新启用为 `surround` 档的子组件**。当前 `effects.go:339` 为 `enableReverb: true`，热路径 `:929 / :1004 / :1068` 均会执行 `ch.rev.processStereo(...)`。
   → **删除它会直接改变 3D 环绕档的听感。**
3. **`frontend/dist/assets/probe-*.js` — 不是孤儿产物。**
   它无 HTML 直接引用，但由 `main.js:652` 的 `await import("./probe.js")` 懒加载（`?probe=1` 自检入口），主 chunk 内含引用串。
4. **`internal/meta#ReadPictures`、`services_cover.go#itoa` — 一度疑似死代码，核对后为活代码**（分别被 `services_cover.go:571`、`:797` 调用），已更正为「非发现」。
5. **`boot_frame_windows.go` 的 `sizeImage`/`xPelsPerMeter`/`clrUsed`/`clrImportant`、`window_reveal_windows.go` 的 `hrInit`/`addTab`/`deleteTab` — 不是死代码。**
   前者是 `BITMAPINFOHEADER` 的 **ABI 布局必需字段**（`GetDIBits` 按 `unsafe.Sizeof` 解析），后者是 **COM vtable 的槽位**（按偏移取函数指针）。删掉能编译通过，但运行期会静默崩溃。
6. **`Go` 与 `JS` 双份 AI 厂商清单 — 不是冗余，是刻意设计。**
   `ai_vendor.go#aiVendorCatalog` 与 `frontend/src/js/ai-vendors.js#AI_VENDORS` 必须一致，且由 `TestAIVendorCatalogMatchesFrontend`（读取前端文件比对 id 顺序）强制守住。**该清单整体保留**；仅其中两个无人调用的函数是死代码（见 2.1）。
7. **`_internals` 导出 — 项目约定的测试接口，不计为死代码。**
8. **`frontend/dist/**` 经全量重建实测为最新**，非陈旧构建：重建前后 45 个文件 SHA-256 逐一相同，`git status` 干净。
9. **`frontend/bindings/**` 与 `frontend/dist/bindings/**` 完全一致**：34 个文件 SHA-256 全部相同（含 `aaf847e` 对两份拷贝的同步修改）。

## 1. 结论摘要

审查结论：**这是一个清理质量相当高的代码库。** 两次较大的功能移除（窗口原生材质 Mica/Acrylic、混响档位）与一次皮肤精简（arcade/stage）在源码层面**没有留下功能性残留**；生成产物与绑定双侧一致；无孤儿模块；无死组件；无未使用依赖；构建/CI 配置无死条目。

发现的问题集中在三类，且**全部是 ESLint 与编译器无法察觉**的类型（未使用的*导出*、不可达分支、只写字段、注释/文档失效、陈旧断言）：

| 类别 | 数量 | 典型来源 |
| --- | --- | --- |
| A. 无用代码（导出/函数/字段零引用） | **约 70 处** | Lit 迁移（`788b446`）遗留空壳、局部重构未收口 |
| B. 移除功能残留（含注释/文档失效） | **6 处** | `32762e8` 混响档位移除遗漏的注释 |
| C. 只写字段 / 死分支 / 重复逻辑 | **约 20 处** | 部分重构 |
| D. 陈旧断言与死配置 | **3 处** | 工具脚本断言了已删除的 DOM id |
| E. 磁盘冗余（非代码） | **约 200 MB** | 临时目录、解压的 ffmpeg 源码、无引用图片 |

**最值得优先处理的三件事**（按实际影响排序）：

1. **`tools/.tmp-*.mjs` 共 10 个一次性探针脚本被 git 跟踪**，根因是 `.gitignore` 的 `.tmp-*/` **尾斜杠只匹配目录**（详见 2.5）——这是唯一一个「清理动作曾经做过但失效了」的问题。
2. **`frontend/packages/player-skins/README.md:117` 的第三方皮肤示例写 `apiVersion: 1`，而 `contract.js:54` 已是 `SKIN_API_VERSION = 2`** ——照抄该示例的皮肤会被 `defineSkin` **直接抛错拒绝**（真实功能缺陷，不只是死代码）。
3. **`tools/check-playerbar-tools.mjs:160-161` 仍在断言已删除的 `#btn-desktop-lyrics` / `#btn-desktop-wallpaper`** ——该断言永远无法通过，是一条恒假的自检。

## 4. 总体评价

**做得好的方面（经实测确认，非客套）：**

1. **两次功能移除的清理质量很高** —— Mica/Acrylic 与 arcade/stage 皮肤在源码层面**零残留**，连未使用的 import 都处理干净了。这在此类项目中并不常见。
2. **生成产物与绑定双侧一致**，且 `dist` 经全量重建验证为最新 —— 说明构建流程纪律良好。
3. **无孤儿模块、无死组件、无未使用依赖、CI 无死配置**，前端 84 个模块全部可达。
4. **大量「单点真源」设计**（如 `TestAIVendorCatalogMatchesFrontend` 用测试强制 Go/JS 清单一致、皮肤契约有 `apiVersion` 校验、档位收敛有测试守住）——这些正是防止「移除功能留残留」的机制，本次审查发现的残留都发生在**这些机制覆盖不到的地方**：注释、文档、导出符号、不可达分支。

**问题的性质高度集中：**

本次发现的约 70 处无用代码里，绝大多数可归因于 **Lit 迁移（`788b446`）** 与 **局部重构**：
- 迁移把渲染职责搬到 Lit 组件后，**旧模块的导出函数失去了最后的调用方**，但导出关键字让 ESLint 的 `no-unused-vars` 完全看不到（这正是「ESLint 全绿 + 206 项测试全通过」与「仍有约 70 处无用导出」可以同时成立的原因）。
- 重构产生**孪生函数只删一半**的情况（`totalOrDefault` vs `perOrDefault`、`isPlaceholderCover` vs `isPlaceholderCoverUrl`、`naturalCompare` 走后留下孤儿 `collator`）。
- 空函数体（`syncDesktopModeButtons`、`buildTitlebarSearch`）是迁移时留的「兼容空壳」，作者注释已写明「不再需要」，只是没删。

**因此建议的长期机制**（超出本次审查范围，供参考）：
- 给 `eslint.config.js` 增加 `import/no-unused-modules` 或等价规则，把「无用导出」纳入门禁 —— 这是本次约 70 处问题的**唯一共同根因**。
- 把手动运行的验收脚本补进 `docs/19-开发说明.md` 的工具清单，并让 `.tmp-*` 类探针脚本**永远不进入版本库**（修好 `.gitignore`）。
