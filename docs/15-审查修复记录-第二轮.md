## 5. ★ 新测试发现的**额外**缺陷（三份报告都没提到）

写 `save_race_test.go` 之后它立刻失败了 —— 但失败原因不是报告里那条 map 别名，而是**另一个独立缺陷**：

```text
Save: rename loudness-cache.json.tmp: The process cannot access the file
      because it is being used by another process.
```

排查发现仓库里有 **7 处**手写「临时文件 + 改名」的落盘逻辑，而其中只有 1 处是对的：

| 位置                             | 临时名         | fsync | rename 重试 |
| -------------------------------- | -------------- | ----- | ----------- |
| `internal/bootstrap/config.go`   | 带序号 ✅      | ✖     | ✅          |
| `internal/loudness/loudness.go`  | 固定 `.tmp` ❌ | ✖     | ✖           |
| `internal/library/library.go`    | 固定 `.tmp` ❌ | ✖     | ✖           |
| `internal/metacache/store.go` ×3 | 固定 `.tmp` ❌ | ✖     | ✖           |
| `internal/ffmpeg/ffmpeg.go`      | 固定 `.tmp` ❌ | ✖     | ✖           |

固定临时名意味着两个 goroutine 同时落盘会互相覆盖同一个文件；Windows 上 `os.Rename` 还会直接失败
（ERROR_ACCESS_DENIED / ERROR_SHARING_VIOLATION）。**这不是理论问题**：`services.go` 有 4 处
`LoudnessService` 方法会调 `mgr.Save()`，「播放时按需测量」与「后台全库测量」完全可能同时落盘，
用户看到的是响度结果没保存。

修法：新增 `internal/atomicfile` 包，把三者中最优的实现合到一起（**唯一临时名** + **fsync** +
**rename 退避重试**，与 `config.go` 已在生产验证过的退避序列一致），并把上面 6 处迁移过去。

> 过程中还发现：光有唯一临时名**仍然不够** —— Windows 上并发 `Rename` 到同一目标照样会失败，
> 所以退避重试必须一起搬过来。这一点是实测出来的（第一版只改了临时名，测试依然红）。

## 10. 明确**未**修复的项

这些是报告里记录过、但本轮有意不动的。理由分两类：**需要改数据契约/架构**，或**风险大于收益**。

### 需要改契约或架构（建议单独立项）

1. **P0-1 封面仍走 IPC 的 data URL**。实测真实曲库 59 首里 40 首有内嵌封面，base64 后 5.57MB
   （平均 143KB/首）；`Songs()` 原样下发，而每次 `scan:done`（含文件夹监听触发的增量重扫）都会
   重新拉一遍整库。5,000 首约 484MB/次。修法要动 Go↔JS 的数据契约（列表不再下发 `cover`）+
   新增一个同源封面端点，属于会横跨后端、桥接层、渲染层的改动，不适合和本轮的一堆小修混在一个 diff 里。
2. **P0-2 曲目表真正的窗口化渲染**。本轮只加了 `content-visibility`（见 §7 实测：DOM 节点数不变）。
3. **P0-3 中「扫描期间每 40 个文件一次 `commit()`」** —— 记忆化已经把它从「每次全量重算」降到
   「命中缓存直接返回」，但事件本身的合并（节流到 ~200ms）没做。
4. **S3-4 `settings.js` 的 `handleSettingsAction` 拆分**（单 switch、约 440 行、约 50 个 case）。
   纯机械但涉及面广，混在本轮会让 diff 不可审。
5. **P1-8 `discoverThemes()` 串行 N+1 次 IPC**（且在首帧关键路径上）。
6. **桌面歌词位置、主题等跨窗口推送的收尾优化**：`desktop-wallpaper.js` 的令牌表 diff、
   频谱数组复用、逐帧 IPC 失败退避（`docs/14` 的 H10/M8/M21）。
7. **皮肤层的合成开销**：`magia` 暂停后仍跑 rAF 重绘 canvas（H4）、`anime/arcade` 关闭后不停相机（H5）、
   `arcade` 用 `drop-shadow` 按频谱速率驱动（H6）、`H7` 的 `background-position` 无限动画。
   这些都在皮肤包的渲染循环里，改动需要逐个皮肤回归验证（仓库有 `tools/verify-lit.mjs` 等自检脚本可用）。
8. **无障碍（`docs/14` 的 M10–M14）**：弹层焦点陷阱与 `inert`、滑条 `aria-valuenow`、
   曲目行的键盘可达性、两个共享歌词渲染器的 roving tabindex。属于产品级改动，需要单独验收。
9. **构建工具的重复**：约 30 份复制粘贴的 CDP 脚手架、5 份漂移的 Wails runtime shim、
   33 个硬编码端口、`tools/cdp-check.js` 的 `send()` 无超时。抽公共模块是独立的清理工作。

    真正的漏洞是重定向不校验（已修）；把 `http` 一律拒掉有可能破坏现在能用的封面来源，
    属防御纵深的取舍，不适合在没有封面来源回归测试的情况下改。
13. **`bootstrap.saveLocked` 的「rename 失败后直接覆盖写」兜底**保留原样：
    它有一个极短的非原子窗口，但那是作者刻意的取舍（有注释），换成纯报错会让「点赞」这类操作在
    杀软短暂占用文件时直接失败。
14. **`byPath`（`loudness.go`）**保留：生产代码只写不读，但 `loudness_test.go` 依赖它。
15. **`internal/bilibili` 与 `internal/executil` 无测试、根包覆盖率 28.1%**。
    本轮新增的 4 个测试只针对被修的具体函数；补整体覆盖率是独立任务。
