# 38 · 跳过首尾静音与切歌间隔

> 需求原文：
>
> > 帮我添加一个功能，跳过音乐尾部的无声片段、首部的无声片段的功能，在设置中按需开启，
> > 分别为跳过头部、尾部的静音区域，同时可以设置歌曲切换时两首歌曲之间的间隔，默认为 1.5 秒

本文件记录实现方案与几处关键取舍。

---

## 一、需求拆解

三件事，彼此独立：

| # | 功能 | 设置项 | 默认 |
|---|---|---|---|
| 1 | 跳过**开头**无声片段 | 设置 → 播放器 → 跳过开头无声片段 | 关闭 |
| 2 | 跳过**结尾**无声片段 | 设置 → 播放器 → 跳过结尾无声片段 | 关闭 |
| 3 | 自动切歌的**间隔** | 设置 → 播放器 → 切歌间隔 | **1.5 秒** |

需求明确要求「**分别**为跳过头部、尾部」，所以是两个独立开关，不是一个「跳过静音」总开关。
两者也解决不同的问题：

- **开头静音** —— 现场录音、转录文件前面常有几秒空白，点播放却迟迟不出声，像播放器卡了；
- **结尾静音** —— CD 抓轨与整轨转录的尾部拖十几秒空白，自动下一首会白等完那一段。

**为什么两个跳过开关默认关闭**：它们会改变用户听到的音频（把头尾掐掉）。
与「响度均衡」同一立场 —— 任何改动音频本身的处理都必须由用户明确开启。

---

## 二、为什么检测放在后端 PCM 上

### 2.1 检测对象：解码后的 PCM，不是原始文件

原始文件（mp3 / flac / ape…）里要判断「这段是不是静音」必须先解码。
而本项目的音频链路**本来就已经**把任意格式转成固定布局的 PCM WAV
（44 字节头 + 16bit/44.1kHz/立体声，见 `internal/ffmpeg`）并落盘缓存。

在同一份 PCM 上扫描一遍：
- 不需要引入解码器；
- 不需要为每种容器格式再写一套解析 —— **一份实现覆盖全部格式**。

### 2.2 检测参数（`internal/audioplay/silence.go`）

| 参数 | 值 | 理由 |
|---|---|---|
| 门限 | **−50 dBFS**（≈ ±104） | 太高会把弱奏/淡入淡出当静音掐掉；太低则黑胶、老磁带的底噪永远判不成静音 |
| 最短静音长度 | **200ms** | 音乐里到处是几十毫秒的近静音瞬间（乐句呼吸）；不设下限会「每次播放开头都被咬掉一口」 |
| 取样步长 | **64 帧**（≈1.45ms） | 一段静音至少 8820 帧，每 64 帧取一个窗口不可能整段漏掉；扫描量降到 1/64 |
| 判定方式 | 窗口**峰值** | 平均值会把「长静音 + 一个短促咔哒」抹平，于是那声咔哒被掐掉 |

扫描只覆盖**头尾各最多 60 秒**：中间部分与结论无关，全文件扫描是纯浪费。

### 2.3 结果按文件缓存

扫描是 O(n) 的（5 分钟的歌有 1323 万个采样点），每次装载都重扫会让切歌明显变慢。
文件内容不变则结论不变，所以按「**路径 + 大小 + 修改时间**」缓存：

- 同名文件被换成另一首歌时，大小或修改时间必然变 → 缓存自动失效；
- 不做内容 hash —— 那要再读一遍全文件，而扫描本来就是为了省下这一次读。

## 三、掐点如何作用到播放上

### 3.1 引擎只认区间，不读配置

`Engine.Load(path, startFrame, endFrame, gain)` 接收**算好的**边界。
引擎不读配置、不扫静音 —— 只负责「按给定区间播放」，这样它的行为能被单独测试。

`PlanSilenceTrim(info, skipHead, skipTail)` 负责把「文件事实」换算成「本次决策」：

```
文件:  [  1s 静音  ][   6s 声音   ][  3s 静音  ]      总长 10s
开关:  跳过开头 ✓     跳过结尾 ✓
结果:  StartFrame = 1s 的位置，EndFrame = 7s 的位置
       → 用户听到的是一首 6 秒的歌
```

事实（`SilenceInfo`）可以缓存复用，决策（`SilenceTrim`）随开关变化 —— 分开才不会让缓存带上开关状态。

### 3.2 语义：**自动跳过 ≠ 把歌变短**

> 用户澄清：
>
> > 实际上可以理解为跳过静音开头和跳过静音结尾，实际上还是会从头开始播放和播放结束，
> > 只不过是自动跳过了而已

这条澄清改变了时间轴的处理方式。一首 4:12 的歌（开头 3 秒静音、结尾 20 秒静音），
两个开关都开时的正确表现是：

| | 值 | 说明 |
|---|---|---|
| **时长** | 4:12（整首） | 进度条按整首歌铺开 |
| **起播位置** | 0:03 | 用户听到的第一声就是音乐 |
| **结束位置** | 3:52 | 不去听那 20 秒空白，直接切下一首 |

也就是说：**掐掉的只是「会被播放的区间」，不是「这首歌的时间轴」**。

#### 为什么位置必须是原时间轴上的绝对位置

位置若从 0 重新起算（即「把歌变短」的写法），会有三处对不上：

1. **歌词** —— 歌词按原曲时间轴打轴，位置从 0 起算会让**所有歌词整体提前**，
   开头静音多长就偏多少，越往后越对不上；
2. **记忆播放进度**（设置里的「保留歌曲播放进度」）—— 存的是原曲位置，
   恢复时要能对得上；
3. **用户拖进度条**时的心理刻度也是原曲时间轴。

所以 `Position()` 的形状是：

```go
// 分母恒为文件总长：进度条要覆盖整首歌，包括被跳过的首尾
return frameToMs(frame), frameToMs(e.pcmSize / FrameSize)
```

起播点单独通过 `TrimStart()` 暴露（诊断与前端提示用），
**不参与**时长/位置的计算。

> **踩过的坑**：最初我实现成「把歌变短」——时长 = 掐完的长度、位置从 0 起算，
> 还在测试里把这个行为当成正确语义钉住了。用户指出后改为「自动跳过」。
> 现在 `frontend/tests/skip-silence.test.js` 有两条**反回归**断言
> （断言分母必须是 `pcmSize`、位置不能减 `trimStart`），
> 注入「变短」写法时会立刻失败。

### 3.3 尾部截断：不能让回调拿到短缓冲

开了「跳过结尾」时，位置走到 `EndFrame` 就按播完处理，**不去等文件真正读空**。
但本缓冲内**多出来的样本要就地清零**，不能直接丢掉：

> 返回短缓冲在 WASAPI 下会被当成欠载处理，听感是「卡带」。
> —— `ringBuffer.read` 的注释里已经记着这一条

### 3.4 整首静音时的兜底

如果掐完什么都不剩（整首都是静音），**退回「不掐」**：

- 零长度区间会让位置/时长计算失效（前端拿 `duration=0` 做除法就是 `NaN`，进度条直接坏掉）；
- 用户看到的是「点了完全没反应」。

放一段静音至少是「有反应」。

## 四、切歌间隔为什么在音频线程上计时

间隔的语义是「这一首结束了，但下一首要等一会儿才开始」。
它跑在**音频回调**里（`GapScheduler`），每次回调按实际输出的帧数推进：

```go
// onData 的最前面（★ 必须在「是否在播放」判断之前，见下）
if e.gap != nil && e.gap.Active() {
    for i := range out { out[i] = 0 }   // 间隔 = 什么都不放
    e.gap.Tick(int(frameCount))
    return
}
```

**为什么不用 `setTimeout` / Go timer**：间隔的时长必须由音频时钟度量。
在前端等，网页一卡（或窗口最小化被节流）间隔就会变长；在 Go 侧另起 timer，
系统一忙也会漂。用音频回调推进，**设备缓冲大小变化、系统负载、界面卡顿都不影响它**。

### ★ 踩到的坑：间隔推进必须排在「是否在播放」判断之前

`markEOF` 会把 `playing` 置成 `false`（这首歌确实结束了）。
如果间隔的推进写在 `if !e.playingNow() { ... return }` **之后**，就永远走不到 ——
表现为**配了切歌间隔之后「播完再也不切歌」**，整个自动切歌链路卡死。

这个 bug 是被 `TestPlayerServiceTrackGapDelaysEOF` 抓到的（超时 6 秒没等到 EOF）。

### 可取消性

间隔进行中，下面每一个动作都必须能取消它：

| 动作 | 为什么 |
|---|---|
| 手动切歌 / `Seek` | 那是明确的即时意图，不该还等剩下的半秒 |
| `Pause` | 暂停表达「先别放」，而间隔走完会触发下一首 —— 叠加的后果是「暂停之后歌自己切走了」 |
| `Unload` / `Close` | 卸载后还挂着的计时器会让下一次装载立刻收到过期的「播完了」，表现为自动跳过一首歌 |

## 五、前端这一半只做两件事

1. **把开关同步下去**（`applyPlaybackOptions()`）；
2. **把跳过量显示对**（读 `Load` 响应里的 `skippedHeadMs` / `skippedTailMs`）。

前端**不做**静音检测：它没有 raw PCM，真做起来要把音频再解一遍，
等于把刚搬到后端的工作又搬回来。这一条有测试拦着
（`skip-silence.test.js` 的「前端不做静音检测」）。

启动顺序也有要求（`main.js`）：

```
await probeBackend();
startAudioEvents();
applyPlaybackOptions();   // ← 必须在 startRuntime 之前
...
startRuntime();           // 第一次 run 就可能装载并起播
```

跳过静音的方案是在**装载时**算好的 —— 推晚了第一首歌会用默认值（不跳过）播出。

## 六、验证

| 层次 | 覆盖 |
|---|---|
| 纯逻辑（`internal/audioplay/silence_test.go`） | 扫描形状、短静音不误伤、底噪算静音、弱奏不算静音、整首静音、头尾不重叠、缓存失效、开关组合、区间不为负、间隔计时/取消/重复 Arm |
| 引擎（同上） | `TrimRange`、**时长恒为整首 + 位置留在原时间轴**、`TrimStart`、`endFrame=0` 表示全文件、seek 钳到跳过区间终点 |
| 桥接层（`services_player_test.go`） | 开关关闭时不碰文件、只开头/只结尾/都开、**原时间轴不变式**、掐点触发 EOF、整首静音仍可播、间隔推迟 EOF、间隔为 0 立即切、非法值钳制、诊断字段、Unload/Seek 取消间隔 |
| 配置层（`internal/bootstrap/skipsilence_test.go`） | 默认值、**0 是合法值**、越界钳制、JSON tag、旧配置回填、两开关独立 |
| 前端契约（`frontend/tests/skip-silence.test.js`） | 默认值、`SYNCED_KEYS`、`applyPatch` 分支、启动顺序、滑条量程、**两条时间轴反回归断言** |
| 真实界面（`tools/verify-skip-silence.mjs`） | 三个控件渲染、默认值显示、开关独立、重绘后状态保持、0 秒可达、10 秒可达 |

> 时间轴的两条**反回归**断言做过「注入错误实现」验证：
> 把 `Position()` 改成「时长 = 掐完区间、位置从 0 起算」时，
> 这两条会立刻失败；还原后通过。断言不是摆设。

界面自检用**每次全新的浏览器 profile**：这些开关是持久化的（正是本功能的要求），
复用 profile 会让上一次自检拨过的状态留到下一次，于是「默认值」断言会莫名其妙地失败 ——
脏状态必须从隔离上解决，而不是改断言。

```bash
npm run verify:skip-silence      # 界面自检（需要 Edge / Chrome）
go test ./internal/audioplay/ ./internal/bootstrap/ .
npm test
```
