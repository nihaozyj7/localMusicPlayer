# 界面设计方案 v1

> 依据：`docs/01-需求原始记录.md`
> 技术形态：Go + Wails3（WebView2 前端为原生 HTML/CSS/JS，无框架）
> 视觉基调：黑白极简 + 毛玻璃拟态（Glassmorphism）

---

## 1. 设计原则

1. **样式与结构彻底分离**：HTML 中不写任何内联 `style`，不写 `<style>` 块。所有视觉来自 `frontend/src/styles/`。
2. **主题即 CSS 文件**：一个主题 = 一个 CSS 文件，只声明设计令牌（design tokens），通过 `:root[data-theme="文件名"]` 生效。用户丢进目录即可用。
3. **布局固定**：窗口骨架为固定三区（顶栏 / 内容 / 底栏），任何界面切换都不改变骨架位置，避免「页面跳动」。
4. **一份控件到处用**：底部播放控件在主界面与三个播放界面中共用同一个 DOM 组件，只有尺寸变量不同。
5. **毛玻璃只用变量控制**：模糊强度、透明度、边框高光全部令牌化，主题作者可逐项覆盖，不需要碰组件 CSS。

## 2. 窗口骨架

窗口：无边框（frameless）自绘标题栏，最小尺寸 1000×680，默认 1280×820。

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ ① 标题栏 Titlebar  (36px, 可拖拽, 右上角自绘最小/最大化/关闭)                  │
├───────────────┬──────────────────────────────────────────────────────────────┤
│ ②             │ ③ 主内容区 Main                                             │
│  侧边栏       │ ┌──────────────────────────────────────────────────────────┐ │
│  Sidebar      │ │ 内容头部 ContentHeader：标题 + 工具条(搜索/扫描/视图切换) │ │
│  232px 固定   │ ├──────────────────────────────────────────────────────────┤ │
│  毛玻璃        │ │ 内容主体 ContentBody（滚动区域）                          │ │
│               │ │  · 所有歌曲  → 曲目表格                                   │ │
│  · 所有歌曲    │ │  · 播放列表  → 曲目表格（可拖拽排序 / 移除）               │ │
│  · 播放列表    │ │  · 歌单      → 曲目表格                                   │ │
│  · 歌单                                        │ │  · 设置      → 设置面板                                   │ │
│    - 我喜欢    │ │                                                          │ │
│    - 自定义…   │ │                                                          │ │
│  · ＋ 新建歌单  │ │                                                          │ │
│               │ │                                                          │ │
│  · 设置        │ │                                                          │ │
├───────────────┴──────────────────────────────────────────────────────────────┤
│ ④ 底部常驻播放控件 PlayerBar (88px 固定)                                      │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 层级（z-index）

| 层        | 内容                                                         | z-index |
| --------- | ------------------------------------------------------------ | ------- |
| 背景层    | 渐变光斑 / 封面虚化                                          | 0       |
| 主内容    | 侧边栏 + 内容区                                              | 10      |
| 底部控件  | PlayerBar                                                    | 40      |
| 播放界面  | PlayerView（绝对定位铺满窗口，**只留出标题栏与 PlayerBar**） | 30      |
| 弹窗/菜单 | 模态、右键菜单、主题选择器                                   | 60      |
| 标题栏    | Titlebar                                                     | 70      |

> 播放界面为「铺满整个窗口的绝对定位层」：`position: fixed; inset: 36px 0 88px 0`，
> 左右到窗口边缘、整块盖住侧边栏与主内容区，因此底部控件与标题栏天然常驻（满足 C5）。
> 它是 `.app` 里的兄弟节点，不参与文档流，打开/关闭都不影响任何既有布局。

## 3. ① 标题栏

- 高 36px，左侧应用名 + 当前视图名（如 `音乐播放器 · 沉浸`），中部可拖拽，右侧窗口按钮。
- `-webkit-app-region: drag` 由 Wails3 frameless 支持；按钮区域 `no-drag`。
- 右侧顺序：**主题切换（☾/☀）→ 设置（⚙）→ 最小化 → 最大化 → 关闭**。
- **标题栏不设自己的背景色**：主界面渐变由 `.app::before` 提供（高度 = 标题栏高度 +
  淡出延伸），因此从标题栏到内容区是连续过渡；沉浸模式下连这层也去掉，让封面虚化图透上来。

## 4. ② 侧边栏

- 宽 232px，独立滚动，毛玻璃面板。
- 结构：
  - **曲库**：所有歌曲（含曲目数徽标）、播放列表（含队列数徽标）。
  - **歌单**：列表；`我喜欢` 固定第一项，`data-locked="true"` → 无删除按钮、禁用右键删除。
    分组标题右侧有一个 `＋` 用于新建歌单。
- 选中态：整行高亮 + 左侧 3px 主题色指示条 + 背景毛玻璃加深。
- 拖拽：歌单可拖动排序（自定义歌单之间），「我喜欢」不可拖动。
- 底部原本的「＋ 新建歌单 / 设置」两个入口已移除：新建歌单留在分组标题的 `＋`，
  设置移到标题栏主题切换右侧。
- 打开播放详情页时侧边栏**整块淡出**（只改透明度、不改宽度），因为详情页是铺满
  整个窗口的绝对定位层，会把它完全盖住；若不让它淡出，侧边栏会刚好贴在详情页
  左边缘，看起来像漏了一条没盖住。淡出时长与详情页滑入完全一致。

## 5. ③ 主内容区

### 5.1 内容头部 ContentHeader

- 高 64px，粘性（sticky），下滑时以毛玻璃遮住下方内容。
- 左：视图标题 + 副标题（如「所有歌曲 · 1,248 首」）。
- 右：工具条，按视图动态显示：
  - 搜索框（所有歌曲 / 歌单）
  - **重新扫描** 按钮（B2，所有歌曲视图常显）
  - 排序下拉（标题 / 歌手 / 专辑 / 时长 / 添加时间）
  - 视图密度切换（舒适 / 紧凑）（可选）
  - 播放全部 / 随机播放

### 5.2 曲目表格 TrackTable（所有歌曲 / 播放列表 / 歌单 共用）

列（固定布局，百分比 + 定宽混合）：

| 列            | 宽度     | 说明                                                        |
| ------------- | -------- | ----------------------------------------------------------- |
| 拖拽手柄      | 28px     | 仅播放列表视图显示（B4）                                    |
| 序号 / 播放态 | 40px     | 悬停变播放按钮；正在播放显示跳动音柱                        |
| 封面（小）    | 40px     | 32×32 圆角                                                  |
| 标题          | flex 1fr | 主行标题，次行歌手                                          |
| 专辑          | 1fr      | 可隐藏                                                      |
| 时长          | 72px     | 右对齐等宽数字                                              |
| 爱心 ♥        | 44px     | **所有歌曲视图**必显（B7）；歌单视图高亮显示「已在该歌单」  |
| 更多 ⋯        | 40px     | 菜单：加入播放列表 / 加入歌单 / 从列表移除 / 在文件夹中显示 |

- 行高：舒适 56px / 紧凑 44px。
- 斑马纹关闭，改用极低对比分隔线；悬停整行毛玻璃高亮。
- 正在播放行：左侧主题色指示条 + 标题主题色。
- 拖拽排序：HTML5 draggable 或指针事件实现，拖动时显示半透明浮层 + 插入位置指示线。

### 5.3 设置面板（弹出层）

实现已从「视图」改为**弹出层**：从标题栏下沿铺满到窗口底边（**标题栏必须露出来**，
窗口按钮与拖动区在设置打开时依旧可用），点击遮罩或右上角关闭。层里是一块固定高度的
面板：顶部标题栏 + 中间滚动内容 + **底部紧凑播放控件**。

内容为**分区 + 卡片**结构，不换页：

1. **音乐文件夹**（A1/A2）
   - 路径列表：路径 + 状态（监听中 / 不存在 / 无权限）+ 曲目数 + 移除按钮。
   - `添加文件夹`（调用系统目录选择）、`立即重新扫描`。
   - 开关：`启动时自动扫描`、`实时监听文件夹变化`。
2. **过滤规则**（A3/A4）
   - 规则行：`类型(大小/正则) | 条件(<,>,=) | 值 | 作用(排除/仅包含) | 启用开关 | 删除`。
   - 预置示例：「排除小于 10KB 的文件」「排除匹配 `\.mp4$` 的文件」。
   - 支持规则组合预览：下方显示「当前规则将过滤 N 首中的 M 首」。
3. **外观**（A5/A6/A8）
   - 主题模式：浅色 / 深色 / 跟随系统。
   - 主题文件选择卡片列表（自动扫描主题目录，展示主题名 + 色板缩略）。
   - 毛玻璃强度滑杆（模糊半径）、透明度滑杆、动画开关、过渡速度（快速 0.2s /
     适中 0.35s / 缓慢 0.5s，一律写进 `--dur` 令牌，全站动效共用）。
   - `打开主题文件夹` 按钮。
4. **播放**：默认循环方式、音量记忆、淡入淡出、无缝衔接（可选）。
5. **响度均衡**：模式（关闭 / 逐曲 / 同专辑）、目标响度、真峰值保护、批量预热。
6. **在线歌曲**：下载目录、在线封面、把封面/歌词写进歌曲文件（含「写入缓存到文件」）、缓存目录。
7. **歌词**：来源优先级、字号、居中高亮行数。
8. **关于 / 数据**：曲库缓存位置、清空缓存、版本信息。

导航条（`音乐文件夹 … 关于`）是 **sticky** 的：点它跳转，滚动内容时高亮跟着走。
「当前分区」记在渲染之外（`settings.js#activeSection`）—— 设置内容是一整块
`innerHTML` 重绘的，状态若只存在渲染结果里，点任何开关都会把选中态打回第一个。

#### 5.3.1 设置层里的紧凑播放控件

需求：设置弹出层里也要有播放器控件，并且要避开标题栏。因此它长在面板底部
（与底栏同一个位置关系），是**精简版**：曲目信息 / 上一首 / 播放暂停 / 下一首 /
进度 / 音量 / 播放模式。收藏、添加到歌单、播放列表、全屏仍然只在底栏，
避免两处状态重复。动作全部来自同一套 store，所以这里点播放，底栏与详情页会立刻跟上。

这里**没有**歌词按钮：需求是歌词不提供隐藏入口（见 7.4）。

## 6. ④ 底部常驻播放控件 PlayerBar

高 88~92px（`--h-playerbar`），固定底部。**不自己铺底色**：主界面渐变由
`.app::after` 统一提供（高度 = 播放控件高度 + `--chrome-fade`），这样从内容区到
底栏是连续过渡；沉浸模式下这层渐变会让位给封面虚化图。

```
┌──────────────────────────────────────────────────────────────────────────────────────┐
│ 01:23 ─────────────────────────●────────────────────────────────────────── 04:05      │  ← 上排：整行进度条
├──────────────────────────────────────────────────────────────────────────────────────┤
│ ┌────┐ 歌名        ♥  ＋        ┌─────┐              🔊 ────  ⇄  ☰  ≣⁵  ⛶          │  ← 下排
│ │cover│ 歌手 · 专辑             │ ⏮ ▶ ⏭ │                                          │
│ └────┘                         └─────┘                                              │
└──────────────────────────────────────────────────────────────────────────────────────┘
   ① 左区                          ② 中区（严格居中）      ③ 右区
   封面 / 曲目信息 / 喜欢 / 加入歌单   上一首 播放 下一首      音量/模式/歌词匹配/桌面歌词/列表
```

顺序（从左到右，与需求一致）：
**封面 → 歌曲名与歌手·专辑 → 喜欢 → 添加到歌单 → 上一首 / 播放暂停 / 下一首 →
音量 → 播放顺序模式 → 手动匹配歌词 → 桌面歌词 → 播放列表**

三块的定位方式（这里踩过一个坑）：

```css
.playerbar__row {
  position: relative;
  --transport-zone: 168px;
}
.playerbar__now {
  max-width: calc(50% - var(--transport-zone));
}
.playerbar__tools {
  max-width: calc(50% - var(--transport-zone));
}
.playerbar__center {
  position: absolute;
  left: 50%;
  top: 50%;
  transform: translate(-50%, -50%);
}
```

- 中间那块用**绝对定位 + translate(-50%,-50%)**，所以它严格落在窗口中线上，
  与左右两侧内容宽度无关。曾经用「flex 三段均分 + space-between」，
  那种居中只保证左右剩余空间相等 —— 左边曲目信息比右边工具窄时，
  传输控制就会被推到偏左的位置（实测偏了约 70px）。
- 两侧各留出 `--transport-zone`（中间块半径 + 余量）的空白带，
  任何宽度下两侧内容都不会盖到中间那块上。
- 窄窗口时 `calc(50% - …)` 可能被裁成 0 导致内容回挤，因此
  `--transport-zone` 要随断点一起调小（1240/1060/960 三档）。
- `--transport-zone` 定义在 `.playerbar__row` 上，两侧子元素通过继承拿到它。

- **上排进度条**：已播时间 + 可拖动轨道 + 总时长；悬停轨道加粗并显示气泡时间。
- **封面**：点击 = 进入/退出播放详情页（同一个按钮来回切，图标 hover 时提示）。
  没有内嵌封面时显示内置默认封面（内联 SVG 唱片 + 音符），不会出现浏览器破碎图标。
- **喜欢**：切换「我喜欢」，按下态立刻回写（`commit(..., { immediate: true })`）。
- **添加到歌单**：弹出歌单菜单，可直接把当前曲目加进去，菜单底部有「新建歌单…」。
- **播放顺序**：顺序 → 列表循环 → 单曲循环 → 随机（循环点击，单曲循环显示角标 1）。
- **歌词**（`#btn-lyrics`）：打开「歌词工作台」——一个三 tab 的右侧抽屉面板（在线匹配 /
  微调 / 手动编辑）。完整设计见 `docs/08-歌词工作台设计方案.md`，要点：
  - **在线匹配**：搜索候选 → 应用到当前歌曲（与改造前完全一致）；
  - **微调**：整首歌的时间轴整体提前/延后（±10s），边听边拧、当场生效，
    点「应用到歌词」才烙进时间戳并保存；
  - **手动编辑**：粘纯文本歌词 → 一边播放一边按空格打轴，当前播放时间写进当前行
    并自动进入下一行；支持撤销、逐行清除、点行跳转、复制 LRC。
  - 抽屉从标题栏下方挂到底栏上方：打轴时必须能看见并操作底栏的播放控件。
- **桌面歌词**（`#btn-desktop-lyrics`）：在桌面上**单独开一个透明窗口**显示歌词。
  窗口可拖动，**位置会被记住**（`config.desktopLyricsX/Y`，拖动去抖 400ms 落盘，
  关窗口时补写一次）；换显示器/改分辨率后若存档落在屏幕外（可见面积不足 1/3）
  自动回默认位置。设置 → 歌词 里有「重置位置」。
  它与「桌面背景歌词」（`#btn-desktop-wallpaper`）互斥，见 7.9。
- **播放列表**：在底栏上方浮出队列面板（队列项可直接点播 / 移除，可反转、清空）。

**这里没有歌词显隐按钮，也没有全屏按钮**：需求明确「歌词不提供隐藏入口」，
所以两个歌词语义不再共用按钮，而是只留下「手动匹配歌词（内容来源）」与
「桌面歌词（独立窗口）」这两件与歌词显隐无关的事；想改歌词显隐只走设置 → 歌词。
全屏按钮按需求移除（`F` 快捷键保留）。

## 7. 播放界面 PlayerView（八种样式）

进入方式：点击底栏封面/歌名、底栏 ⛶ 按钮、双击曲目。

统一结构：`PlayerView{ Header(返回 + 标题 + 样式切换) / Stage(样式区) }`，底部仍是共用 PlayerBar。

### 7.1 经典 Classic

```
┌────────────────────────────────────────────────────────────┐
│  ← 返回                        经典 | 沉浸 | 简约           │
│  ┌──────────────────┐   ┌────────────────────────────────┐ │
│  │                  │   │  歌词滚动区（右对齐/居中）      │ │
│  │   ● 旋转唱片      │   │  当前行高亮放大 + 主题色        │ │
│  │   320 ~ 420px    │   │  上下行渐隐                     │ │
│  │                  │   │                                │ │
│  └──────────────────┘   └────────────────────────────────┘ │
│  ─────────────── PlayerBar ───────────────                 │
└────────────────────────────────────────────────────────────┘
```

- 左：唱片 = 封面上叠一层黑色黑胶纹理 + 中心轴孔，`animation: spin 24s linear infinite`，暂停时 `animation-play-state: paused`（C2）。
- 右：歌词滚动，靠左对齐更利于阅读；当前行字号 ×1.25、字重加粗、主题色，其余行透明度 0.4。

### 7.2 沉浸 Immersive

```
┌────────────────────────────────────────────────────────────┐
│  ← 返回                        经典 | 沉浸 | 简约           │  ← 标题栏无底色
│                                                            │
│      [ 封面铺满整个窗口 + 高斯模糊 + 暗化遮罩 ]              │
│                                                            │
│                    中间显示歌词（纯文字，无卡片）             │
│                    当前行高亮                                │
│                                                            │
│  ─────────────── PlayerBar（无底色）───────────────         │
└────────────────────────────────────────────────────────────┘
```

- 背景层：同一张封面 `object-fit: cover` 铺满**整个窗口** → `filter: blur(48px) saturate(1.4)`
  → 叠一层 `rgba(0,0,0,.35)`（浅色主题为 `rgba(255,255,255,.35)`）保证文字对比度（C3）。
- 背景层是 `.app` 的直接子元素（`#immersive-bg`），**不在 `.playerview` 里**：
  `.playerview` 有 transform 进出动效，会把内部 `position: fixed` 的包含块变成它自己，
  导致背景被裁在详情页范围内、盖不住标题栏与播放控件。
- 歌词居中，行间距放大；**歌词容器没有任何卡片背景 / 边框 / 阴影**，纯文字浮在虚化图上。
- 沉浸模式下标题栏、侧边栏、播放控件的底色与毛玻璃全部清空，chrome 只剩内容与一层
  极淡的描边，避免任何一块实色面板压住封面虚化图。
- 「显示歌词」（设置 → 歌词）关掉时，歌词区整体收起，沉浸模式只剩封面虚化图 +
  左上角的曲目信息。**界面上没有歌词显隐按钮**：需求是歌词不提供隐藏入口，
  这个开关只在设置里。

### 7.3 简约 Minimal

- 无封面、无背景图，只有居中歌词 + 底部控件，主背景为主题底色（C4）。
- 可选显示一行「歌名 · 歌手」小字。

### 7.4 歌词区通用规则

- 当前行自动滚到容器垂直中央；用户用滚轮 / 触摸板 / 拖动滚动条时自动滚动让位，
  停手 1.2 秒后再自动接管（回读当前行位置）。
- 首次定位（刚打开 / 刚换歌）用瞬时定位，之后的播放推进用平滑滚动 ——
  否则"打开详情页"时歌词会从最上面慢慢滑下来，看起来像没定位到。
- 歌词行是 `div[role="button"][tabindex]` 而不是 `<button>`：button 在部分情况下按空格会
  触发滚动，并且需要大量重置样式。
- 无歌词时展示占位：「暂无歌词」+「打开所在文件夹」。
- 点击某行 → 跳转到对应时间点。

### 7.5 背景与 chrome（本次调整）

标题栏与播放控件**不各自铺底色**，改用两层从边缘向中间消散的极淡渐变：

```css
:root {
  --chrome-fade: 52px;
  --bg-chrome-top: linear-gradient(180deg, rgba(255, 255, 255, 0.055), rgba(255, 255, 255, 0.018) 42%, transparent);
  --bg-chrome-bottom: linear-gradient(0deg, rgba(255, 255, 255, 0.05), rgba(255, 255, 255, 0.016) 46%, transparent);
}
.app::before {
  top: 0;
  height: calc(var(--h-titlebar) + var(--chrome-fade));
  background: var(--bg-chrome-top);
}
.app::after {
  bottom: 0;
  height: calc(var(--h-playerbar) + var(--chrome-fade));
  background: var(--bg-chrome-bottom);
}
```

- 「第一段」正好是标题栏高度，往上再慢慢淡掉，因此标题栏和内容区之间不会切出一条硬边。
- 沉浸模式下（`.app[data-mode="immersive"][data-view="player"]`）两层渐变 `opacity: 0`。
- 这两个伪元素挂在 `.app` 上而不是 `.titlebar` / `.playerbar` 上，是因为
  `.app` 是一个 stacking context，`z-index: var(--z-bg)` 能让它们稳定地位于所有内容之下，
  同时不随 `data-view` 变化而跳动。

### 7.6 播放详情页的进出动效

- 打开：从下方 `translateY(38px)` + `opacity: 0` → `none` / `1`，260ms，`--ease-slide`。
- 关闭：反向滑出，动画结束后才 `hidden = true`（`renderPlayerView` 里用 260ms 定时器收尾）。
- 由于 `.playerview` 用 `transform` 而不是改 `top`/`left`，位移期间它会被播放控件与
  标题栏裁掉，视觉上就是从底栏背后推上来（它现在是铺满窗口的层，所以整块面板一起上移）。
- **打开详情页不改动窗口骨架**：详情页是 `position: fixed` 的兄弟层，直接叠在
  侧边栏与主内容之上（`inset: var(--h-titlebar) 0 var(--h-playerbar) 0`），
  左右到窗口边缘。侧边栏只做透明度淡出，宽度与位置不变，所以全程零重排。
- 因为是整窗铺满，超宽屏上内容会散开，因此给内容加了宽度上限：
  经典视图 `max-width: 1180px`，单行歌词 `--lyric-measure: 760px`，都居中。

### 7.7 样式重算的坑（切主题时文字颜色不同步）

主题令牌来自 `@import` 进来的样式表。实测在 WebView2/Chromium 上**只改根节点的
`data-theme`**，已经存在的元素不会重新解析 `var(--…)`：它们的计算样式停在旧主题上，
而新建的元素是正常的。症状是切到浅色主题后，侧边栏文字仍是深色主题的浅灰，落在
浅色背景上几乎看不见。

`theme.js` 的 `forceStyleRefresh()` 通过改一下 `body` 上一个不参与任何样式的
`data-style-epoch` 属性来让整棵子树失效重算，不重建 DOM，因此不丢焦点、不闪屏。

## 7.8 实现补充说明（编码阶段确认的细节）

1. **CSP 与动态样式**
   `index.html` 的 CSP 为 `style-src 'self' 'unsafe-inline'`。
   原因：Chromium 会把「JS 动态创建 `<style>`」「`<style>.textContent`」「`blob:` 样式表」以及部分 CSSOM 写入判定为内联样式并拦截，而本项目的主题切换、毛玻璃强度滑杆、用户自定义主题都需要运行时改样式。
   即便如此，代码仍保持「结构里不写样式」：HTML 中零 `style` 属性，所有视觉都在 CSS 文件里，动态部分只改**设计令牌**与滑杆位置这类必要值。
   运行时令牌统一走 `js/runtime-tokens.js` 的 `setRuntimeToken()`（往预置的空 `<style id="runtime-tokens">` 里 `insertRule`），不要直接 `element.style.setProperty("--x", …)`。

2. **毛玻璃强度与主题的关系**
   模糊半径由主题令牌 `--glass-blur` 决定（深/浅极简 22px、封面取色 26px）。
   只有用户**手动拖动**过设置里的滑杆后，才用运行时令牌覆盖为自定义值（`config.glassBlurCustom` 标记），否则切主题时会被配置值「拉平」，主题自身的差异就看不出来了。

3. **「面板不透明度」滑杆**
   当前写入 `--glass-alpha` 令牌，属预留能力（内置主题未消费）。要真正生效需要在主题里用 `color-mix()` 消费该令牌，等主题规范定型后再接。

4. **窄窗口策略**
   窗口最小 1000×680。侧边栏 1120px 起收窄、1040px 起变纯图标；曲目表格按优先级隐藏列：专辑 → 拖拽手柄/更多 → 封面/爱心，行内用 0 宽度列而不是 `display:none`，保证表头与数据行始终对齐。已在 1000×608 实测无横向溢出。

5. **正在播放的音柱动画**
   通过行上的 `data-playing` 与 `aria-current` 两个属性控制 `animation-play-state`，暂停时音柱定格，不做额外 JS 动画。

6. **第二轮反馈后的界面调整**（对应需求「以上是目前发现的问题，请分析后解决」）

   | 位置             | 调整                                                                                                                                                                                         |
   | ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
   | 播放详情页顶部栏 | 「封面」与「轮播」合成**一个按钮组**（`#playerview-cover-group`），外观与右侧的样式按钮组（`#playerview-mode`）完全一致；样式组的按钮按注册表**动态渲染**，加第三方样式就多一个按钮          |
   | 封面面板         | 输入区只留「关键词」一个框（歌手/专辑框去掉）；候选卡片点击即勾选（默认全选）、底部「应用(N)」一次追加多张；下方是多封面管理条（设为当前 / 删除 / 收进缓存）与两个开关（写入歌曲文件、轮播） |
   | 底栏「定时停止」 | 从一串预设菜单改成**面板**：0~300 的滑条（拖完才生效）+ 15/30/60/90 预设 + 关闭；倒计时显示在按钮角标与提示上                                                                                |

   | 曲目列表         | 选中态与当前播放彻底合并：`state.currentId` 是唯一真源，列表只负责画出来（`aria-current` + 音柱），不再维护第二份选中状态                                                                    |

   设计上的两条约束（避免重新长出「两份真相」）：

### 7.9 新增的五个内置样式

在原来的三种（经典 / 沉浸 / 简约）之后，样式按钮组里再追加五个**整窗背景型**样式。
它们都由「宿主提供数据、样式只负责呈现」的同一条接口驱动，区别只在视觉语言与动效：

| id          | 名称              | 视觉语言                                            | 运镜                                     | 文字动效                                                                     |
| ----------- | ----------------- | --------------------------------------------------- | ---------------------------------------- | ---------------------------------------------------------------------------- |
| `anime`     | 二次元手绘        | 漫画分镜格 + 半调网点纸 + 手绘太阳 / 山丘 / 花瓣    | 轻手摇 + 换歌时「分镜推进」脉冲          | 逐字弹跳（缩放 X/Y 不一致，落地回弹）+ 马克笔扫光 + 会自己画出来的下划线     |
| `cosmos`    | 深邃宇宙          | Canvas 透视星场 + 星云 + 带环行星 + 远景行星        | 幅度最大的轨道漂移，切歌时一次跃迁拉伸   | 逐字从纵深浮出（大模糊 → 清晰）+ 星尘扫光 + 相邻行景深失焦                   |
| `wasteland` | 科幻末世          | 废墟天际线 + 透视网格地面 + 雷达扫描 + 危险警示条   | 手持感最强（旋转幅度最大）+ 换歌故障抖动 | 等宽字逐字「解码」闪入 + 当前行 RGB 分离 + 正在唱的字反色                    |
| `arcade`    | 游戏风            | 合成波网格 + 带横条大太阳 + 8-bit 浮动像素 + 扫描线 | 轻微手抖 + 行推进小震屏 + 换歌大震屏     | 对话盒逐字打字（steps 步进）+ 闪烁方块光标 + 已唱字变绿 / 正在唱的字高亮方块 |
| `magia`     | 魔法阵 · 手绘次元 | 手绘夜景 + 巨大魔法阵 + Canvas 粒子                 | 时间驱动的自主漂移 + 换行脉冲 + 换歌切镜 | 逐字错峰入场 + 逐字点亮 + 行内进度                                           |

实现上的两条约定：

- **运镜**统一走 `fx-camera.js`：两条不可通约正弦叠加成「手摇呼吸」，切歌时叠一个
  `sin²(π·te)` 包络（两端值与速度都为 0，落点静止）。只写 `transform`，
  页面不可见时停掉 rAF，`prefers-reduced-motion` 或用户关掉界面动画时完全不启动。
- **文字动效**统一走 `fx-lyrics.js`：按字素拆分（优先 `Intl.Segmenter`），
  逐字入场是一次性 CSS 动画，逐字点亮只重写**当前行**的 `data-hold`，
  不给每个字素加 `will-change`（实测逐字提升合成层会让整片文字糊掉）。

另外，底栏「桌面歌词 / 桌面背景歌词」两个按钮原来被包成一个单选按钮组
（`.mode-group`，带一块共享底色）。实测夹在一排圆形图标按钮中间不好看，已拆成两个
各自独立的按钮；互斥关系仍然由 `desktop-mode.js` 一处把关，按下态改用 `aria-pressed`。

### 8.3 为什么这样能满足 A7/A8

- HTML 里没有任何 `style`/`<style>`；组件 CSS 里没有硬编码颜色，全部 `var(--…)`。
- 新增主题 = 新增一个 CSS 文件 + 一条 `@import`（或由 Wails 后端把主题目录挂载后动态 `link` 注入，便于真正「丢文件即生效」）。
- 主题文件只声明变量，改不动布局，因此「布局固定」不会被主题破坏。

## 10. 本次待你确认的设计点

1. 侧边栏「重新扫描」是否只保留在内容头部（推荐）还是侧边栏也放一份。
