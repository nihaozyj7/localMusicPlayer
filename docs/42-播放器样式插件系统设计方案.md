# 播放器样式插件系统设计方案（契约 v3 · 可重写）

> 需求原文（本次）：**播放器样式是一个插件系统；应用只提供接口和事件供样式插件使用，
> 不应该和播放器本身耦合。** 宿主提供：音频频谱、歌词、播放状态（是否暂停 / 播放
> 时间）、进度跳转等接口与运行环境；插件用这些环境完成**播放详情页**的界面渲染。
>
> 已知的一处耦合：**宿主控件栏的颜色会被插件本身控制**（两条通道见 §2），
> 解决思路：**要求插件在声明里给出一个前景色和一个背景色**，宿主据此保证自己的
> UI 在任何插件配色下都可读。
>
> 结论：本方案允许**重写现有契约（v2 → v3）**。现在没有第三方样式在野
> （`contract.js` 里也写着「既然还没有第三方皮肤，直接升版本」），是重写成本最低的窗口。

---

## 1. 目标与非目标

### 1.1 目标

| # | 目标 | 判定标准（可测） |
|---|------|------------------|
| G1 | 宿主只提供**环境 + 接口 + 事件**，不认识任何具体样式 | 宿主源码/CSS 里搜不到任何样式 id；删掉任意一款样式不需要改宿主代码 |
| G2 | 内置样式与第三方样式**同构** | 同一份校验、同一条加载路径、同一个目录结构；内置样式目录可以直接拷进数据目录使用 |
| G3 | 插件**自包含** | 一个目录 = 一款样式（入口 + CSS + 自带图标 + 自带私有模块）；不需要构建步骤、不需要触碰包内文件 |
| G4 | 插件**无法破坏宿主 UI**（可视性 / 布局 / 其它界面） | 插件 CSS 改不动宿主壳规则（§6.2 的 `@layer` 机制）；插件配色由声明 + 宿主派生兜底（§5） |
| G5 | 契约**可演进** | 版本语义化（major 严格、minor 兼容）；未知字段/未知事件不炸；废弃有流程 |
| G6 | 契约**自洽且可验证** | 契约文档 = 唯一的字段来源；有 `check-skin` 静态校验 + 真机冒烟探针按注册表驱动（不再硬编码样式 id） |
| G7 | 插件够不到宿主内部 | 插件零 import（只允许自己目录内相对 import）；数据只从 `ctx` 拿；动作只走 `ctx.actions` |

### 1.2 非目标（明确不做，避免设计失控）

- **不做 iframe / Worker 级沙箱**：CSP 下插件与宿主同源同文档，隔离靠「不给接口 + `@layer` + 静态校验」。
  真正的隔离需要把 `ctx` 变成 postMessage 协议，插件只剩 canvas，视觉能力会大幅缩水。若将来要做，
  契约层已经预留（`ctx` 是纯数据 + 命令，天然可序列化）。
- **不做远程样式市场 / 签名校验**（后续可选，见 §11 P5）。
- **不规定视觉风格**：本方案只规定边界与接口。
- **不接管设置界面 / 曲库列表的皮肤**：插件只作用于「播放详情页 +（可选）整窗背景层」。

## 2. 现状：插件到底是怎么碰到宿主的（要解决的问题）

### 2.1 通道 A：色彩域整块投影（`--pv-*` → 宿主浮层）

```css
/* 插件 CSS 里声明自己的色板（现在的事实契约） */
.playerview[data-skin="x"][data-theme] { --pv-bg: …; --pv-text: …; --pv-surface-1: …; }
```
```js
// playerhost.js#mirrorPlayerSurface + SURFACE_VARS（15 个令牌）
// 把插件那套 --pv-* 抄到所有 [data-surface-owner="playerview"] 的浮层上：
//   --text-1/2/3、--surface-1/2/3、--surface-hover/active、
//   --glass-bg/glass-bg-strong/glass-border、--divider、--border-2、--accent
```

后果：播放队列面板、播放选项面板、定时停止面板、歌词面板的**全部颜色由插件决定**。
宿主对这些颜色没有任何约束，插件给一套低对比度配色（例如深灰底 + 深灰字）时，
这些面板就会「看不清」，而宿主无从发现、也无从纠正。

### 2.2 通道 B：插件 CSS 直接写宿主壳选择器

`settings.js` 里给第三方样式作者的提示词（第 335 行）明确写着：

> skin.css 里每一条选择器都必须以 `.playerview[data-skin="<样式id>"]` 开头；
> **需要影响详情页之外的外壳（标题栏、底栏）时可另加 `.app[data-mode="<样式id>"]`。**

即：插件被**邀请**去改标题栏、控件栏（底栏）的样式。这是最直接的耦合 ——
宿主壳（chrome）本不该由插件负责。

### 2.3 顺带发现的三处契约漂移（本次一并修掉）

| # | 位置 | 问题 |
|---|------|------|
| D1 | `contract.js` vs `playerhost.js:789` | `ctx.spectrum`（函数）实现里有，契约 `SkinContext` 里没有 |
| D2 | `contract.js#SkinLyrics` vs `playerhost.js:671` | 歌词对象实际 6 个字段（多了 `status` / `statusText`），契约只写了 4 个 |
| D3 | `contract.js#SkinTrack` vs `settings.js:319` | 契约说只给 5 个字段（正确，`trackView` 就是这么裁的），但 AI 提示词告诉作者「有 path / online 等」 |
| D4 | `contract.js` vs `desktop-wallpaper-window.js:102` | v2 已删除的 `ctx.audio` 在那份"第二宿主"里还留着（`audio: null`） |

另外 `ctx.push`（注释写明「宿主内部使用」）也挂在插件拿到的同一个对象上，插件可以拿它伪造补丁。

## 3. 分层模型：壳 / 舞台 / 插件

```
┌──────────────────────────────────────────────────────────────┐
│ 宿主壳 chrome（宿主拥有，插件只能"影响颜色"，不能改结构/规则）│
│  · 标题栏、底栏（播放控件栏）、侧边栏                            │
│  · 浮层：播放队列 / 播放选项 / 定时停止 / 歌词面板               │
│  · 配色来源：宿主主题令牌 + 从插件 colors 派生的 --chrome-*（§5）│
├──────────────────────────────────────────────────────────────┤
│ 播放舞台 stage（宿主提供容器与尺寸，内容完全由插件画）           │
│  · .playerview[data-skin="<id>"] → ctx.root                    │
│  · 整窗背景层（可选能力）→ ctx.backgroundRoot                   │
├──────────────────────────────────────────────────────────────┤
│ 插件 plugin（纯渲染 + 交互）                                    │
│  · 只读 ctx；只走 ctx.actions；零 import（自己目录内除外）        │
└──────────────────────────────────────────────────────────────┘
```

三条边界规则（本设计的地基）：

1. **宿主壳的结构与规则永不暴露**：插件改不动（§6.2），也拿不到引用。
2. **插件只声明"我的画面长什么样"，不声明"宿主该长什么样"**：`colors` 是**给宿主的提示**，
   不是宿主的样式来源；宿主有权忽略、纠正、派生。
3. **舞台内的一切归插件**：宿主不查舞台内部 DOM、不假设类名（现在 `probe.js` 假设
   `#pv-lyrics .lyrics__scroll` / `.lyric[aria-current]`，P4 要归位）。

## 4. 插件包格式（自包含）

### 4.1 目录结构

```
<数据目录>/player-skins/<id>/      ← 第三方（用户放置，可写）
<安装目录>/resources/player-skins/<id>/  ← 内置（随包分发，只读）
    skin.json          清单（必需）
    skin.js            入口（必需；清单的 entry 可改）
    skin.css           样式（可选，清单 styles 可列多个）
    assets/            自带图标 / 贴图（可选）
    lib/               自带私有模块（可选；只允许插件目录内的相对 import）
```

内置与第三方**只有一个区别**：来源根目录不同（`builtin` 标记、卡片上不显示「移除」按钮）。
除此之外走完全相同的发现 → 校验 → 加载 → 挂载流程。

### 4.2 `skin.json` 全字段

```json
{
  "id": "aurora",
  "name": "极光",
  "version": "1.2.0",
  "apiVersion": "3.0",
  "author": "…",
  "description": "一句话说明",
  "entry": "skin.js",
  "styles": ["skin.css"],
  "icon": { "sprite": "disc" },
  "order": 200,
  "capabilities": {
    "spectrum": 32,
    "background": true,
    "interactive": true,
    "paintSelf": true
  },
  "colors": { "bg": "#0b1020", "fg": "#f2f4ff", "accent": "#7aa2ff" },
  "performance": { "budgetFps": 45 }
}
```

| 字段 | 必需 | 说明 |
|------|------|------|
| `id` | ✅ | 必须与目录名一致；反向域名式前缀（`com.example.aurora`）留给市场阶段，现阶段小写短横线 |
| `name` | ✅ | 显示名 |
| `version` | ✅ | 插件自身版本（排错用） |
| `apiVersion` | ✅ | 契约版本，语义化 `major.minor`（§7） |
| `entry` / `styles` | ✖ | 默认 `skin.js`；`styles` 缺省时自动带上目录内**顶层**所有 `*.css`（不递归，避免把 `lib/` 里的片段也注入） |
| `icon` | ✖ | `{"file":"assets/icon.svg"}`（自带，推荐）或 `{"sprite":"disc"}`（用宿主图标，兼容旧样式）；缺省 `disc` |
| `order` | ✖ | 按钮排序；内置 10~90，第三方 ≥ 200 |
| `capabilities` | ✖ | 能力声明，宿主据此决定采样与容器（§6.4） |
| `colors` | ✅（见 §5.4） | **宿主 UI 的可见性依据**：`bg` / `fg` / `accent?` |
| `performance` | ✖ | `budgetFps`：performanceMode 下的目标帧率上限 |

### 4.3 `skin.js` 形状（保持现在的"纯对象"写法）

```js
// 插件零 import：校验与工具都由宿主在挂载时通过 ctx.sdk 提供
export default {
  id: "aurora",
  name: "极光",
  mount(ctx) {},        // 必需
  update(ctx, patch) {}, // 可选，等价于 ctx.on("*")
  destroy(ctx) {}        // 可选
};
```

> **为什么不给 `defineSkin(...)`**：浏览器原生 ESM 无法解析裸包名
> `@localmusicplayer/player-skins`（没有 importmap 就报错），而给宿主加 importmap
> 会让插件能够 `import` 宿主内部文件（正是现在的毛病）。
> 所以：**校验/工具从 `ctx.sdk` 拿**（`ctx.sdk.createLyricsView(...)` / `ctx.sdk.parseLrc(...)` /
> `ctx.sdk.fit(...)` / `ctx.sdk.util.*`），插件文件本身保持零 import —— 现在 AI 提示词
> 已经在教作者这么写了，改成契约即可。

## 5. 颜色契约（本次需求的核心）

### 5.1 要解决的问题

插件决定自己画面的配色 → 宿主控件栏/浮层叠在它上面时，对比度可能不足以阅读；
宿主无法预知插件的配色，因此无法保证自己的 UI 可读。

### 5.2 方案：插件声明两个色，宿主负责派生与兜底

插件在清单里声明：

```json
"colors": { "bg": "#0b1020", "fg": "#f2f4ff", "accent": "#7aa2ff" }
```

- `bg` —— **插件画面的主底色**（"我的画面大体是这个颜色"）。
- `fg` —— **插件画面上主要文字/图标的颜色**（"我的画面上的前景大体是这个"）。
- `accent` —— 可选；缺省时宿主用自己的主题强调色。

宿主**不把它们当样式来源**，而是当"环境描述"，据此算出自己壳层用的一小组变量：

```
--skin-bg        = colors.bg（校验后）
--skin-fg        = colors.fg
--chrome-fg      = 对比度达标的前景色（见 §5.3 的纠正规则）
--chrome-fg-dim  = color-mix(in oklab, var(--chrome-fg) 62%, transparent)
--chrome-bg      = color-mix(in oklab, var(--skin-bg) 82%, transparent)   /* 半透明 + 宿主毛玻璃 */
--chrome-bg-soft = color-mix(in oklab, var(--skin-bg) 65%, transparent)
--chrome-hover   = color-mix(in oklab, var(--chrome-fg) 10%, transparent)
--chrome-active  = color-mix(in oklab, var(--chrome-fg) 16%, transparent)
--chrome-border  = color-mix(in oklab, var(--chrome-fg) 18%, transparent)
--chrome-accent  = colors.accent ?? var(--accent)
```

**消费者是谁**：宿主壳的底栏（播放控件栏）、标题栏、以及四个「属于播放界面」的浮层
（队列 / 选项 / 定时停止 / 歌词面板）。它们**只读 `--chrome-*` 与宿主主题令牌**，
不再读插件的 `--pv-*` → §2.1 的投影机制整体下线。

> 设计取舍：浮层是否应该完全用宿主主题色（放弃"跟随播放界面"）？不采用 ——
> 播放界面打开时浮层贴着深色舞台，用浅色主题的浮层会很突兀。改用"派生 + 保证对比度"，
> 既保留跟随感，又由宿主掌握可读性。这是这套设计里唯一一处"宿主替插件决定视觉"的地方，
> 但它只作用于**宿主自己的壳**，不侵入插件画面。

### 5.3 对比度兜底（即使插件声明得离谱也不会看不清）

1. 用 WCAG 相对亮度算 `L(bg)`、`L(fg)`，对比度 `CR = (L1+0.05)/(L2+0.05)`。
2. `CR ≥ 4.5` → 直接采用 `fg`。
3. `2.0 ≤ CR < 4.5` → 用同色相、把明度推到对比度达标的变体（`oklch` 调亮度，保持插件气质）。
4. `CR < 2.0` 或 `fg`/`bg` 缺失/非法 → **用黑或白中与 `bg` 对比更高的那个**（`--chrome-fg` 落到
   `#fff`/`#000`），并在设置页给一条「该样式配色对比度偏低，宿主控件已自动纠正」的提示。
5. `bg` 无法解析（拼错、渐变、图片） → 按 `#000` 处理（深壳）并给提示。

于是宿主 UI 的可见性**不依赖插件的自觉**，插件乱写也只是"自己的画面难看"，不会让宿主控件消失。

### 5.4 声明缺失时的策略（已定案）

**降级使用主题配色 + 警告图标**：

- 缺失 / 非法 → 宿主**不猜**、也不拒绝加载：壳层直接用**当前主题**的配色
  （`--chrome-*` 全部回落到宿主主题令牌，等价于"没挂皮肤时的样子"），
  保证任何主题下都可读；
- 同时在**设置 → 播放界面样式**里该样式的卡片上显示一个**警告图标**
  （`data-tip` 写明原因：「未声明 colors，宿主控件栏改用主题配色；建议在 skin.json 补上 bg / fg」），
  并在控制台记一条带插件 id 的 warn；
- `_template` 里默认带上 colors，作者一开始就有值；
- 这条规则同样适用于只声明了一半（有 `bg` 没 `fg`）或颜色无法解析的情况 —— 缺失的那一项按主题走。

> 为什么不做"拒绝加载"：插件是**用户自己**从磁盘丢进来的，契约违规却整款样式被拒，
> 用户看到的只是"我装的样式不见了"；降级 + 卡片警告既能跑起来，又把问题指到具体位置。

### 5.5 动态配色（随封面取色的样式）

清单里的 colors 是**初始值**。需要随封面变色的插件，可以在运行时低频上报：

```js
ctx.actions.reportBackdrop({ bg: "…", fg: "…" });   // 宿主做防抖（≥300ms）+ 只重算 --chrome-*
```

宿主可自检：mount 后采样 `ctx.root` / `ctx.backgroundRoot` 的 `getComputedStyle().backgroundColor`，
与声明值比亮度；差异过大时在设置页提示「声明的配色与实际画面不符」。
（自检失败只提示，不阻断 —— 插件可能用渐变/图片/画布铺底。）

## 6. 宿主提供的环境（契约 v3）

### 6.1 数据面（拉，纯数据，可序列化）

| 方法 | 返回 | 说明 |
|------|------|------|
| `ctx.track()` | `{ id, title, artist, album, duration, kind }` | `kind: "local" \| "online"`；**不给 path / 来源 / 文件信息** |
| `ctx.playback()` | `{ position, duration, playing, volume, muted }` | 毫秒；后端锚点外推后的值 |
| `ctx.lyrics()` | `{ lines, index, status, statusText, source, text }` | 与实现对齐（修 D2）；`lines` 已应用偏移 |
| `ctx.covers()` | `{ list, index, current }` | 轮播用 |
| `ctx.options()` | `{ showLyrics, lyricsFontSize, animations, coverCarousel, coverCarouselInterval, interactive, performanceMode }` | 修 D1：`performanceMode` 挪进 `env` 或保留在此，二者只留一处 |
| `ctx.env()` | `{ themeId, mode, width, height, dpr, reducedMotion, apiVersion }` | 把现在散在 getter / `resize` 补丁里的环境信息集中 |
| `ctx.assets.url("assets/bg.png")` | 绝对 URL | 插件目录内的资源取址；越界（`../`）拒绝 |
| `ctx.log(...)` | — | 带插件 id 前缀的日志，宿主统一收集 |

### 6.2 事件面（推）

统一为一种通道（`update` 退化为 `ctx.on("*")` 的语法糖）：

```js
const off = ctx.on("progress", (p) => { … });   // 返回退订函数
```

| 事件 | 载荷 | 触发时机 |
|------|------|----------|
| `mount` | 全量快照 | 挂载后立即一次 |
| `track` | `{ track, covers, lyrics }` | 换歌（原 `song`） |
| `covers` | `{ list, index, current }` | 封面变化 / 轮播切图 |
| `lyrics` | `{ lyrics }` | 歌词装载完成 / 匹配状态变化 |
| `progress` | `{ position, duration, playing, lyricIndex }` | 宿主按帧节流（现状 250ms 档） |
| `state` | `{ playing, volume, muted }` | 播放/暂停/音量/静音变化 |
| `spectrum` | `{ bands: number[] \| null }` | 已按 `capabilities.spectrum` 声明采样，约 30Hz |
| `options` | `{ options }` | 设置项变化 |
| `theme` | `{ themeId, mode }` | 主题 / 深浅色变化 |
| `resize` | `{ width, height, dpr }` | 舞台尺寸变化 |
| `visibility` | `{ foreground: boolean }` | 详情页打开/关闭、窗口最小化（插件据此停帧） |
| `chrome` | `{ fg, bg, accent }` | §5.5 上报后宿主算好的壳色（供插件自检对拍，可选） |
| `teardown` | `{ reason }` | 即将卸载（`destroy` 之前） |

**一致性保证（现在缺的）**：任何一次推送之后，同类型快照方法（`ctx.playback()` 等）
返回的值必须与刚推的载荷一致；宿主在一次推里只发一次，不重复发送相同内容。

### 6.3 动作面（命令，受控）

| 动作 | 签名 | 说明 |
|------|------|------|
| `seek` | `(ms) => void` | 绝对跳转 |
| `seekBy` | `(deltaMs) => void` | 相对跳转（歌词点句常用） |
| `seekRatio` | `(0..1) => void` | 比例跳转（自定义进度条用） |
| `togglePlay` / `next` / `prev` | `() => void` | 播放控制 |
| `like` / `unlike` / `toggleLike` | `() => void` | 收藏（新；歌词/曲目卡片常要） |
| `openFolder` / `openCoverPanel` / `openLyricsPanel` | `() => void` | 打开宿主能力 |
| `reportBackdrop` | `({bg, fg}) => void` | §5.5 |

动作在"不可交互宿主"（桌面背景歌词窗口）里是**空实现**，且 `ctx.options().interactive === false`
—— 契约里明确写「同一插件可能被挂到多个舞台，且不保证只有一份实例」，插件不得依赖单例。

### 6.4 能力声明（`capabilities`）

| 能力 | 取值 | 宿主行为 |
|------|------|----------|
| `spectrum` | `number`（段数，1~128） | 声明了才采样与推送；未声明一次都不采 |
| `background` | `boolean` | `true` 才创建/显示整窗背景层容器（`ctx.backgroundRoot`） |
| `interactive` | `boolean`（默认 `true`） | `false` → 宿主可把该样式挂到只读舞台（桌面背景歌词） |
| `paintSelf` | `boolean`（默认 `true`） | `false` → 宿主负责画最基本的曲名/歌词兜底（给"只要背景"的样式用） |

宿主不认识的 capability 字段**忽略**（不报错）→ 新能力可以先行落地。

### 6.5 明确不提供

`AudioContext` / `<audio>` / `AudioWorklet`、`store`、宿主 DOM 引用、路由、
其它插件的引用、网络请求（CSP 也拦）、`eval` / `new Function`。

## 7. 版本与兼容策略

- **语义化 `major.minor`**：
  - `major` **必须严格相等**（结构性变更）。
  - `minor`：宿主 `3.2` 能加载声明 `3.0` / `3.1` 的插件；插件声明 `3.2` 在宿主 `3.0` 上**拒绝并说明原因**。
- **未知即忽略**：清单里的未知字段、`ctx.on("未知事件")`（返回 no-op 退订函数）、
  `ctx.actions.未知动作`（**不保证存在** → 插件必须 `typeof` 探测）。
- **废弃流程**：字段/事件先标记 `deprecated`（契约文档 + 运行时一次性 warn），
  两个 minor 之后移除；移除时 bump major。
- **契约单一来源**：`skin.json` 的 JSON Schema + `contract.js` 的 typedef 由同一份
  描述生成（P1 落地），避免又出现 D1~D4 那种漂移。

## 8. 加载、隔离与安全

### 8.1 加载流程（状态机）

```
发现（扫两个根目录）
  → 校验清单（schema / id 与目录名 / 颜色合法性 / apiVersion）
  → 解决依赖（确定性排序：order 升序，order 相同按 id）
  → import(entry URL + token)        ← 失败：卡片标红 + 原因
  → 形状校验（普通对象 / 必需字段 / capabilities 与声明自洽）
  → mount(ctx)                        ← 抛错：宿主渲染错误占位，不白屏
  → 事件流（on/update）…              ← 连续 N 次处理抛错：卸载并回退到上一个可用样式
  → teardown + destroy(ctx)
```

### 8.2 CSS 隔离：`@layer` + 宿主强制包裹（关键机制）

宿主把插件 CSS **包一层**再注入：

```css
@layer skin {
  @scope (.playerview[data-skin="aurora"], .skin-bg[data-skin="aurora"]) {
    /* 插件原始的 CSS 全文 */
  }
}
```

宿主自己的壳层规则放在 `@layer host`（在文档里先声明 `@layer host, skin;`）。

带来的好处：
1. **插件改不动宿主壳**：`skin` 层的规则永远输给 `host` 层，插件写 `.playerbar { … }`、
   `* { … }`、`!important` 都无效 → §2.2 通道被机制性关闭，不再只靠"约定 + 自觉"。
2. **插件不用自己写作用域前缀**：连 `.playerview[data-skin="<id>"]` 都可以省（`@scope` 已经限定了），
   作者心智负担下降，也不可能污染其它界面。
3. 背景层容器一并纳入 scope 根（`.skin-bg[data-skin="<id>"]`），
   解决"背景层在 `.playerview` 之外"的老问题。
4. 仍然保留兼容：老样式若自己写了 `.playerview[data-skin=…]` 前缀，嵌套后语义不变。

> 若某天需要更硬的隔离，`@scope` 可以再加 `to (.playerbar, .titlebar)` 把边界写死。

### 8.3 运行期静态校验（`tools/check-skin.mjs`）

- 清单 schema、`id` 与目录名一致、`colors` 合法、`apiVersion` 可加载；
- CSS 里**禁止**出现：`.app` / `.playerbar` / `.titlebar` / `:root` / `html` / `body` / `*` / `!important`；
- JS 里禁止：`import` 非相对路径、`fetch`、`XMLHttpRequest`、`eval` / `new Function`、
  `document.documentElement`、`window.` 赋值、`setInterval`（轮询）；
- 输出人话报告 + 退出码（可以直接进 CI，作为"样式目录回归"）。

### 8.4 安全边界（诚实说明）

插件是**用户自己放进来的同源 JS**，能拿到与主界面相同的权限（我们只做到"不给接口 + 层隔离 +
静态校验"）。因此：
- 设置界面必须写明「样式是代码，只装你信任的样式」；
- 安装/更新样式不做静默执行（扫描即加载是现状，保持即可，但卡片上要标出来源目录）；
- 未来若要上市场，再做签名/白名单（§11 P5）。

### B. 最小插件示例

`skin.json`
```json
{
  "id": "aurora", "name": "极光", "version": "0.1.0", "apiVersion": "3.0",
  "entry": "skin.js", "styles": ["skin.css"],
  "icon": { "file": "assets/icon.svg" }, "order": 200,
  "capabilities": { "spectrum": 32, "background": true },
  "colors": { "bg": "#0b1020", "fg": "#f2f4ff", "accent": "#7aa2ff" }
}
```

`skin.js`（零 import）
```js
export default {
  id: "aurora",
  name: "极光",
  mount(ctx) {
    ctx.root.innerHTML = `
      <div class="au-root">
        <div class="au-bars"></div>
        <div class="au-title"></div>
        <div class="au-lyrics"></div>
      </div>`;
    this.bars = ctx.root.querySelector(".au-bars");
    this.title = ctx.root.querySelector(".au-title");
    this.lyrics = ctx.root.querySelector(".au-lyrics");
    this.off = ctx.on("*", (p) => this.render(ctx, p));
    this.render(ctx, { type: "mount" });
  },
  render(ctx, patch) {
    const t = ctx.track();
    this.title.textContent = t ? `${t.title} — ${t.artist}` : "未在播放";
    if (patch.type === "lyrics" || patch.type === "mount") {
      const l = ctx.lyrics();
      this.lyrics.textContent = l.lines[l.index]?.text ?? l.statusText ?? "";
    }
    if (patch.type === "spectrum" && patch.bands) {
      this.bars.style.setProperty("--n", String(patch.bands.length));
      // …按 bands 画电平柱
    }
  },
  destroy(ctx) {
    this.off?.();
    ctx.root.innerHTML = "";
  }
};
```

`skin.css`（**不需要**再写作用域前缀，宿主会包 `@layer skin { @scope(…) }`）
```css
.au-root { position: absolute; inset: 0; display: grid; place-content: center; }
.au-title { font-size: 24px; }
.au-lyrics { margin-top: 12px; opacity: .8; }
```

### 13.1 落地与设计的差异（以实现为准）

| # | 设计里写的 | 实际实现 | 理由 |
| --- | --- | --- | --- |
| 1 | `@scope` 支持探测：编译期 tsc + 运行期 computedStyle 双验 | 运行期**特性探测**：`typeof CSSScopeRule !== "undefined"`（`player-skins/index.js#wrapPluginCss`） | 注入的是运行时文本，构建链里没有对它跑 tsc 的环节；特性探测一次就够，失败退化为只包 `@layer` 并 warn 一次 |
| 2 | `--chrome-*` 写在宿主壳元素上 | 写在 **`<html>`** 上（`skinhost.applyChrome`） | 播放队列 / 选项 / 定时 / 歌词工作台是 `#app` 之外的 `fixed` 浮层，继承不到 `.app` 上的变量 |
| 3 | （§2.1 指出的旧通道）`--pv-*` 整套投影 | **整体删除**：`mirrorPlayerSurface()`、`SURFACE_VARS`、`tokens.css` 的 `[data-surface-owner][data-theme]` 规则、面板上的 `data-surface-owner` 属性全部移除；替换为 `:root[data-chrome="on"]` 的令牌映射，值来自 `deriveChrome` | 旧机制的问题就是"宿主颜色由插件的 CSS 决定"；新机制下宿主壳只读宿主算出来的 `--chrome-*` |
| 4 | 插件 CSS 选择器相对舞台根写 | 内置两份 CSS 从 `.playerview[data-skin="x"] …` 全量前缀**改成相对写法**（舞台自身用 `::scope`） | `@scope` 里作用域根通常只能用 `::scope` 匹配，留全前缀会匹配不到 |
| 5 | `data-mode="<id>"` 作为让位钩子 | `.app` 的 `data-mode` 降为**诊断标记**；能力钩子改为 `.app` / `.playerview` 上的 **`data-skin-background`**（由 `capabilities.background` 驱动），宿主壳透明化规则从沉浸样式 CSS 搬进 `layout.css` 的**通用规则** | 设计要求"宿主不认识任何具体 id"；能力属性对所有插件成立 |
| 6 | AI 参考资料含内置样例 | `services_reference.go` **跳过内置**（它们在 embed 里没有磁盘路径），指向用户目录的 `_template` | 给 AI 一堆拼不出来的路径等于误导 |
| 7 | §5.4 警告图标 | 设置页样式卡片新增：**底色/前景两个色块 + 对比度自检提示（`chrome.contrast` / `corrected`）+ `i-warning` 图标**（`missing` 非空时，悬浮看原因） | 定案 1 的可见化 |
| 8 | `ctx.media()` 是否保留 | **保留**为聚合视图（`track/lyrics/covers` 是它的字段级拆分）；`ctx.push` 从插件可见面移除（只留在宿主内部） | 见 §2.3 漂移 D1/D1b |
| 9 | 示例包 `_template` | 升级到 v3：`skin.json`（含 `colors`/`capabilities`/`apiVersion`）、零 import 的 `skin.js`、**不带作用域前缀**的 `skin.css`、新增 `assets/icon.svg` 与 v3 版《皮肤说明.md》 | 新用户拿到的第一份就是对的 |
