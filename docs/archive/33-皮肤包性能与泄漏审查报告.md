## 0. 级联频率事实（后面所有结论的基准）

皮肤能拿到的两类高频数据，频率**远低于** rAF：

| 数据 | 声明位置 | 真实推送频率 | 依据 |
|---|---|---|---|
| `progress` 补丁 | `playerhost.js:1181` | **4 Hz**（250ms 量化） | `audio.js:340` 与 `runtime.js:33` |
| `spectrum` 补丁 | `playerhost.js:1200`（`SPECTRUM_HZ = 30`） | **30 Hz**（详情页）/ **25 Hz**（桌面背景，`desktop-wallpaper.js:357`） | 见引用 |
| 皮肤自己的 rAF | 各皮肤 | 60 fps（arcanum 45/22，anime 由 fx-camera 限 60） | 见 §1 |

`progress` 之所以是 4 Hz：

```
frontend\src\js\audio.js:340
  if (!force && Math.round(rounded / 250) === Math.round(lastPushedPosition / 250)) {
    return;
  }
```

```
frontend\src\js\runtime.js:32-33
    // 250ms 一档：歌词高亮 / 桌面推送不需要更细
    Math.round((state.position || 0) / 250),
```

**这条事实的推论**：magia / arcanum 的「逐字点亮」`paint()` 在 rAF 里每帧跑，
但它读的 `inst.position` **每 250ms 才更新一次**。所以逐字进度实际上是
**4 Hz 的台阶**，却被 60 Hz 的循环反复重算并写 DOM —— 见 P1-1。

## 1. 逐皮肤 rAF 循环一览

| 皮肤 | 跑 rAF？ | 帧率上限 | 暂停时停？ | 页面隐藏时停？ | 空闲时停？ | 每帧布局读取 | 最严重问题 |
|---|---|---|---|---|---|---|---|
| **classic** | ❌ 无 | — | — | — | — | 仅换行时（见 §2） | 无帧循环；`.disc` 用 CSS 动画 |
| **minimal** | ❌ 无 | — | — | — | — | 仅换行时 | 无 |
| **immersive** | ❌ 无 | — | — | — | — | 仅换行时 | `filter: blur(54px)` 整窗（P2-3） |
| **anime** | ✅ 有（`fx-camera.js`） | 60（`maxFps`） | ❌ **不停** | ✅ 停（仅事件，不查初值） | ❌ 不停 | ❌ 无 | 相机永远转；`animations:false` 或 `destroy` 才停（P1-3） |
| **magia** | ✅ 有 | 无上限（纯 rAF） | ❌ **不停** | ❌ **不停** | ❌ 不停 | 仅换行时 | rAF 永不停止 + `mg-line` 常驻 blur（P1-2 / P1-1） |
| **arcanum** | ✅ 有 | 45 / 22 | ✅ **停**（6s 后） | ✅ 停 | ✅ 6s 停 | ❌ 无 | 每帧 2 次对象分配（P2-1） |

「每帧布局读取」一列为 ❌ 表示**帧循环体内没有任何** `scrollTop` /
`offsetHeight` / `getBoundingClientRect` / `scrollHeight` / `clientHeight` 读取。
这是本次审查最重要的正面结论（§2）。

**关键对比**：6 个皮肤里只有 **arcanum** 有真正的暂停 / 隐藏 / 空闲停机路径
（`arcanum.js:71-73` 的三档预算 + `:1091-1095` / `:1101-1107`）。
magia 与 anime 的暂停停机**完全不存在**；classic / immersive / minimal
因为没有帧循环而无需停机。

> 在**桌面背景窗口**里，`close` 补丁永远不会到达（§4.3），
> 因此依赖 `close` 停机的分支在那里是死代码 —— 但 arcanum 不依赖它，
> 它靠 `state` / `progress` 补丁里的 `playing:false` 走空闲计时器，所以仍然会停。

### 2.3 仍然存在的每帧工作：`paint()` 空转

magia 的 `step()` 每帧无条件调用两个歌词函数：

```
frontend\packages\player-skins\src\skins\magia.js:1220-1221
  inst.lyrics.paint(inst.position);
  inst.lyrics.follow();
```

而 `paint()` 遍历当前行全部字素：

```
frontend\packages\player-skins\src\skins\magia.js:955-960
    for (let k = 0; k < row.units.length; k += 1) {
      const seg = segs[k];
      const hold = position >= seg[1] ? "done" : position >= seg[0] ? "now" : "wait";
      const el = row.units[k];
      if (el.dataset.hold !== hold) el.dataset.hold = hold;
    }
```

`position` 每 250ms 才变（§0），**但这段循环 60 Hz 都在跑**。
有 `if (el.dataset.hold !== hold)` 守卫，所以**重复帧不产生 DOM 写入**，
但每帧仍有 N 次 `dataset` 读取（N = 当前行字素/词数，10~40）。
成本不高（每帧几十次属性读），但属于纯空转。**P3**。

作为对照，`fx-lyrics.js` 有提前退出：

```
frontend\packages\player-skins\src\fx-lyrics.js:210-212
    const hold = Math.max(0, Math.min(n, Math.ceil(progress * n)));
    if (hold === holdUnit) return;
    holdUnit = hold;
```

`arcanum.js:811` 同样有 `if (hold === inst.holdCount) return;`。
**magia 是三者中唯一没有这个短路的一处** —— 但因为有 dataset 守卫，
实际开销远小于 `fx-lyrics` / `arcanum` 的那种（它们本来就有短路）。P3。

# 优先化结论

## P1

### P1-1　magia 的 `.mg-line` 常驻 `filter: blur()` 挂在整首歌每一行上

- **位置**：`frontend/packages/player-skins/src/skins/magia.css:1207`
  （同款：`frontend/packages/player-skins/src/lyrics.css:101`）
- **引用**：
  ```css
  .playerview[data-skin="magia"] .mg-line {
    ...
    filter: blur(0.6px);
  }
  ```
- **成本**：一行一个独立模糊渲染层。一首歌 100+ 行（`magia.js:841` 的
  `rows = lines.map(...)` 为**每一行**建一个 `.mg-line`，不是窗口化的）。
- **频率**：常驻 —— 不是 per-frame，而是「只要详情页开着就一直存在」。
  每次换行时 `strip()`/`build()` 会重建其中一行的子节点（`magia.js:904-925`），
  触发的重绘会连带整片带 filter 的区域。
- **用户可见影响**：magia 是 `docs/26`/`docs/28` 里唯一不达标的样式（43 fps）。
  `follow()` 的强制布局**已修**（§2.2 已证实），因此剩余瓶颈极可能落在这里 ——
  100 个模糊层 + `paint()` 空转（§2.3）。
- **修复草图**：把「未唱行」的模糊从 per-line `filter` 改成对滚动容器整体
  做一次 `mask-image` 渐隐（`magia.css:1172` 已经在用 mask 做上下淡出），
  或只给当前行 ±3 行加 filter、其余行纯靠 `opacity`。
- **无法验证**：我没有运行 `tools/perf-skins.mjs`，无法确认这就是 43 fps 的主因；
  这是**基于代码的推断**，不是实测。

### P1-2　magia 的 rAF 永不停止（暂停 / 隐藏 / 空闲都不停）

- **位置**：`frontend/packages/player-skins/src/skins/magia.js:1181-1184`
- **引用**：
  ```js
  function step(now) {
    if (!inst) return;
    inst.raf = requestAnimationFrame(step);
    const dt = inst.last ? Math.min(50, now - inst.last) : 16;
  ```
- **成本**：每帧一次无条件重排 rAF，`step()` 里做运镜正弦、`putVars` 写 7~8 个
  CSS 变量 ×2 个元素（`magia.js:1206-1217`）、`paint()`、粒子 canvas 全清全画
  （`magia.js:643` `g.clearRect` + 逐粒绘制）。
- **频率**：**60 fps，永远**。全文件 `stopLoop` 只在两处被调用：
  `magia.js:1430`（`close` 补丁）与 `magia.js:1522`（destroy）。
  没有 `visibilitychange`，没有 `IDLE_STOP_MS` 等价物。
- **用户可见影响**：暂停后、最小化后、以及**桌面壁纸窗口**里，
  这台循环照转，风扇与电量照烧。对比 arcanum 明确做了三档（`arcanum.js:71-73`）：
  ```js
  const FPS_PLAYING = 45;
  const FPS_IDLE = 22;
  const IDLE_STOP_MS = 6000;
  ```
  且 arcanum 的 `stopLoop()`（`arcanum.js:225-230`、`:1091-1095`、`:1101-1107`）
  在暂停 6s / `document.hidden` 时真的 `cancelAnimationFrame`。magia 完全没有这一层。

  已交叉验证（子代理独立复核）：`magia.js:1183` 的
  `inst.raf = requestAnimationFrame(step);` **无条件重排**，且 `step()` 函数体内
  **从不读取 `inst.playing`**（全文件 `inst.playing` 仅 7 处命中，均在
  `stepBeat` 与三处赋值里）。暂停只让 `--mg-beat` 包络衰减到 0
  （`magia.js:1141-1143`），但由 `t` 驱动的自主漂移照常每帧推进：
  ```js
  magia.js:1200-1201
  const drift = inst.anim ? 1 : 0;
  const camX = drift * (Math.sin(t * 0.23) * 14 + Math.sin(t * 0.071 + 1.2) * 22);
  ```
- **修复草图**：照抄 arcanum 的三档预算：暂停进入 22fps、`IDLE_STOP_MS` 后
  `stopLoop()`，并加一个 `document.addEventListener("visibilitychange", ...)`
  在 `destroy` 里对称移除；`step` 里用 `inst.playing` 选 `minFrame`。

> **关于 arcanum：确认它真的会停。** 子代理独立复核了补丁投递链路 ——
> 暂停时 `desktop-wallpaper.js:315-333` 因为 `playing` 翻转而使 `due` 为真，
> 仍会推一条 `progress`（带 `playing:false`）；此后 `position` 冻结、去重生效，
> 不再推送。因此 `arcanum.js:1324-1325` 的「任何更新都算活跃」
> （`inst.idleSince = nowMs()`）**不会**被无限续期，
> `IDLE_STOP_MS` 能正常到期并 `stopLoop()`。✅
> 唯一例外：声明了 `spectrum` 的皮肤在暂停时会再收到一帧 `bands: null`
> （`desktop-wallpaper.js:390-395`），把计时器多续一次 —— 无害。

### P2-4　3 处 `@keyframes` 动画 `filter: blur()`（触发重绘而非合成）

- **位置**：`frontend/packages/player-skins/src/skins/arcanum.css:1140`（`ar-dissolve`）、

- **成本**：`filter` 动画每帧都要重新栅格化该元素。
  `mg-pop` 挂在 `.mg-unit` 上（`magia.css:1241`），**当前行每个字素各一份**

- **修复草图**：入场用 `opacity` + `transform` 表达「淡入/缩小」，
