## 1. 问题清单

### P1-1 皮肤 id 有两套命名空间（Go 目录名 vs 模块内 `id`），且没有任何一致性校验

- **严重度**：P1
- **位置**：
  - `frontend/packages/player-skins/src/index.js:66-70`（`registerSkin` 用**模块内 id** 作 key）
  - `frontend/packages/player-skins/src/index.js:172-186`（`loadExternalSkin`：`injectSkinStyles(skin.id…)` / `registerSkin(skin)` 全用模块 id）
  - `frontend/src/js/playerhost.js:452-461`（URL 与 `externalSkinIds` 用 **Go 目录 id**）
  - `frontend/src/js/playerhost.js:468-473`（`unregisterSkin(id)` 传的是目录 id）
  - `frontend/packages/player-skins/src/index.js:101-114`（注销）
- **现象**（三种，都可由用户操作触发）：
  1. 目录名 ≠ 模块 id（例如照文档复制 `_template`、把目录改名为 `aurora` 但忘了改
     `internal/skins/template/skin.js:30` 的 `id: "__SKIN_ID__"`）：注册表里键是
     `__SKIN_ID__`，而 `externalSkinIds` 里是 `aurora`。用户删掉该目录后
     `unregisterSkin("aurora")` 执行的是 `registry.delete("aurora")` → **删不到**，
     按钮组里那个样式永远留着，点它还会去 mount 一个磁盘上已不存在的模块。
     `unregisterSkin` 的注释（`index.js:88-100`）明确说这一条就是为了修「删了还在」，
     但只在「目录名 == 模块 id」时才成立。
  2. 第三方模块声明 `id: "classic"`：`registry.set("classic", 外部皮肤)` 直接**顶替内置样式**
     （`index.js:60` 注册内置、`:68` 无条件覆盖）。此后
     `unregisterSkin("classic")` 在 `index.js:105` **提前 return false**（内置保护），
     于是连它注入的 `<link data-skin="classic">` 都不会被摘（摘除逻辑在 `:108-112`，
     在该 return 之后）→ 内置「经典」永久丢失，直到重启进程。
  3. 承接 2：设置界面按 `s.builtin === false` 显示「移除」按钮
     （`frontend/src/js/ui/settings-view.js:765-780`，`builtin` 由 `playerhost.js:1164-1175`
     的 `s.builtin !== false` 给出，而 `loadExternalSkin` 在 `index.js:181` 无条件把它设成 `false`）。
     点「移除」→ `removeSkin` → `backend.deleteSkin(id)`，此时传的是**模块 id**，
     `internal/skins/skins.go:259-273` 的 `Delete` 先 `m.Get(id)` —— 目录名不同就查不到 →
     报「样式不存在」；即使目录名恰好相同、目录删掉了，`unregisterSkin` 仍拒绝注销 →
     `removeSkin` 返回 `{removed:false}`，样式依旧在列表里。
- **根因**：Go 侧以**目录名**为 id（`internal/skins/skins.go:319`、`:349`），
  JS 侧以**模块内声明的 id** 为注册表 key（`contract.js:164` 的 `REQUIRED` 只要求 id 存在），
  两侧没有任何一处校验 `info.id === verdict.skin.id`；而 `unregisterSkin` 的「内置保护」
  又放在了资源清理之前。
- **建议修法**：
  - `loadExternalSkin`（`index.js:172`）里加 `if (verdict.skin.id !== info.id) throw new Error(...)`，
    或强制以 `info.id` 覆盖模块 id（`skin.id = info.id`），让「注册表 key / URL 前缀 / Go 删除对象」三者同源；
  - `unregisterSkin`（`index.js:101`）把 `<link>` 清理与 `injectedStyles` 清理**提到内置判断之前**，
    并把内置保护改成「记录被顶替的内置样式，注销后恢复」而不是直接 `return false`；
  - `discoverSkins`（`playerhost.js:440`）把 `registerSkin` 的返回 id 与 `info.id` 对账，
    不一致时进 `skinFailures`（设置页已有展示位）。
- **测试盲区**：现有 `frontend/tests/player-skins.test.js:181` 只断言
  `unregisterSkin("classic") === false`，等于把这个 bug 固化成「期望行为」。

### P1-2 magia 完全没有实现 `interactive: false` 契约

- **严重度**：P1（契约违反 + 无障碍/降级失效）
- **位置**：
  - `frontend/packages/player-skins/src/skins/magia.js:1323-1328`（`createLyrics(host, { onSeek })`，**没传 interactive**）
  - `frontend/packages/player-skins/src/skins/magia.js:804-808`（无条件挂 wheel/touchmove/pointerdown/click/keydown）
  - `frontend/packages/player-skins/src/skins/magia.js:844-845`（无条件 `role="button"` + `tabindex="-1"`）
  - `frontend/packages/player-skins/src/skins/magia.js:930-936`（当前行被写成 `tabindex="0"`，即**可聚焦**）
  - 宿主把 interactive 置 false 的地方：`frontend/src/js/desktop-wallpaper-window.js:73`、`:389`
- **现象**：桌面背景歌词窗口（垫在桌面图标之下、本来就收不到键鼠）里，magia 的歌词行仍然是
  `role="button"`、当前行可 Tab 聚焦、并挂着 5 个监听器 + 1.4 秒防抖的「用户滚动」状态机。
  对比：`lyrics-view.js:64-125` 与 `fx-lyrics.js:79-141` 都按 interactive 关掉了这些
  （classic/minimal/immersive/anime/arcade 都正确传了 interactive）。
- **根因**：magia 是「原第三方样式并入内置」（README.md:15），它自带一套独立的歌词渲染器
  （`magia.js:767 createLyrics`），并入时没有跟进 `contract.js:104-116` 的 `SkinOptions.interactive`
  约定；`applyOptions`（`magia.js:1256-1273`）只读了 `animations` / `lyricsFontSize`，
  **全文没有任何 interactive 引用**（grep 结果只有 `{ passive: true }` 这种字面命中）。
- **建议修法**：`magia.js` 的 `mount` 里取 `const interactive = ctx.options().interactive !== false`，
  传进 `createLyrics`，并在 `createLyrics` 内部按它守卫 `:804-808` 的监听注册、
  `:844-845`/`:936` 的 role/tabindex 写入；
  顺带在 `magia.css` 里补 `.mg-line[data-passive="1"]` 的样式（去掉 hover/cursor）。

### P2-1 anime / arcade 不归还整窗背景层：残留 DOM + hidden 状态不复位

- **严重度**：P2
- **位置**：
  - `frontend/packages/player-skins/src/skins/anime.js:159`（取 `ctx.backgroundRoot`）、`:179`（`bgRoot.hidden = false`）、`:375-381`（destroy）
  - `frontend/packages/player-skins/src/skins/arcade.js:91`、`:107`（同上）、`:438-444`（destroy）
- **现象**：`destroy()` 只写了 `inst.bg.dataset.anim = "off"`，**没有**清 `backgroundRoot.innerHTML`、
  也**没有**把 hidden 复位。切到 classic/minimal 之后，`#skin-background`
  仍是 `hidden=false`，且里面还是上一个样式的整棵背景树。
- **根因**：这两个皮肤手写背景而不走 `createBackgroundLayer`，于是漏掉了
  `background-layer.js:104-110`（destroy 里 `hidden = true; innerHTML = ""`）那套清理契约；
  magia（`magia.js:1521-1524`）与 immersive（`immersive.js:103`）都做了这件事。
- **证据 / 叠加事实**：
  - `#skin-background` 的 CSS：`background-layer.css:9-17` → `position: fixed; inset: 0; z-index: 25; background: var(--bg-app)`；
    显形条件是 `[data-state="opened"]`（`:42-45`），而 `playerhost.js:972-975` 在换样式
    （`remounted === true`，`:958`）时一定会打上 opened；
  - 层级：`.app` 是 `z-index: 10`（`layout.css:19`）的层叠上下文，`.skin-bg`(25) 高于
    `.app::before/::after`（chrome 渐变，`z-index: var(--z-bg)=0`，`layout.css:26-47`），
    低于 `.playerview`(30)、`.playerbar`(40)、`.titlebar`(70)；
  - 但 `.titlebar`/`.playerbar` 都是 `background: none`（`titlebar.css:16`、`playerbar.css:21`），
    渐变又画在 `.app::before/::after`（z 0，被 `.skin-bg` 压住）→ 上一个样式的残留层会顶掉
    chrome 渐变，并且残留内容会画出来。
  - 残留内容失去作用域：anime/arcade 的背景规则全部写在 `.app[data-mode="anime"]` 下
    （`anime.css:687-693` 等），而 `playerhost.js:762` 在 mount 新样式时把
    `#app[data-mode]` 改成了新 id → 残留节点变成**无样式裸元素**。
  - 【推测，依据是 SVG 默认尺寸/填充 + 上述层级】anime 的残留里有一个内联 `<svg class="an-veg" viewBox="0 0 1440 360">`
    （`anime.js:71`），无 CSS 尺寸时按默认 300×150 渲染，其中 `<ellipse>`（`anime.js:74-76`）
    没有 fill 属性 → 默认黑色填充。因此「用过二次元手绘再切回经典」时，左上角应能看到
    一块约 300×150 的深色图形。arcade 的残留全是零高度的空 div（`arcade.js:94-106`），
    除顶掉渐变外基本不可见。
  - 另一条放大路径：`playerhost.js:771-779` 挂载失败时提前 return，`:786` 的
    `setSkinBackground("closed")` 不会执行，而 `:975` 仍会打 opened。
- **建议修法**：① `anime.js`/`arcade.js` 的 destroy 补
  `if (inst.bgRoot) { inst.bgRoot.hidden = true; inst.bgRoot.innerHTML = ""; inst.bgRoot.removeAttribute("style"); }`；
  ② 更稳的是宿主兜底：`playerhost.js#unmountSkin`（`:808`）里统一
  `host.backgroundRoot.hidden = true; host.backgroundRoot.innerHTML = "";`，把「背景层归谁清理」
  收敛成宿主职责（`createBackgroundLayer` 的注释也承认容器是宿主的）。

### P2-2 挂载失败的皮肤会被当成「已挂载」，之后每帧继续 push，异常被吞进 console

- **严重度**：P2
- **位置**：`frontend/src/js/playerhost.js:747-787`（`mountSkin`）、`:958-975`、`:978`、`:1028`
- **现象**：`mountSkin` 在 `:754-755` 就把 `host.skin` / `host.mountedId` 设成这个皮肤，

### P2-4 `contract.js` 的 typedef 已经落后于宿主实际暴露的字段

- **严重度**：P2（契约不一致，第三方样式无从发现）
- **位置**：

### P2-6 `animations:false` 与 `prefers-reduced-motion` 的归零都不完整

- **严重度**：P2
- **位置 / 证据**：
  1. **magia 的 rAF 与 Canvas 粒子完全不受 prefers-reduced-motion 约束**：
     `fx-camera.js:25-32` 有 `prefersReducedMotion()`，`fx-camera.js:235-239 start()` 用它门禁；
     但 magia 自己那套循环（`magia.js:1160-1216 startLoop/step`）只读用户设置
     `o.animations`（`magia.js:1259`），全文没有 matchMedia；
     全局的 `base.css:237-245` 只能把 **CSS 动画/过渡**压到 `0.001ms !important`，
     管不到 JS 驱动的 rAF 与 canvas 重绘（`magia.js:630-694 frame()`）。
  2. **classic 的唱片自转不响应 animations:false**：`classic.js:81-83 paintSpin()` 只看
     `ctx.playback().playing`，而 `classic.css:50-56` 是
     `animation: spin 26s linear infinite` + `.disc[data-spinning="true"]`。
     classic 皮肤里**没有任何 data-anim 钩子**（grep data-anim 只命中 fx-lyrics.css / anime / arcade / magia），
     所以关掉动画后唱片照转。
  3. 反向确认没问题的部分：anime（`anime.js:300-313`）、arcade（`arcade.js:346-358`）在
     options 补丁里同时写了 `data-anim="off"`，`fx-lyrics.css:186-202` 有
     `[data-anim="off"] .fxl__u { animation: none }`；magia 也写了自己的 `--mg-anim`/`data-anim`
     （`magia.js:1262-1269`）。
- **建议修法**：magia 的 `applyOptions` 里把 `prefersReducedMotion()` 并入 `inst.anim`
  （`inst.anim = o.animations !== false && !prefersReducedMotion()`），并在 `startLoop`（`:1161`）里门禁；
  classic 的 `paintSpin` 加 `&& ctx.options().animations !== false`，
  或给 classic.css 补一条 `.playerview[data-anim="off"] .disc__platter { animation: none }` 并在
  update 的 options 分支里同步该属性。

### P2-7 性能热点（给出规模与频率）

- **严重度**：P2
- **fx-lyrics 的 DOM 规模**：`fx-lyrics.js:177-195` 每个字素一个
  `<span class="fxl__u" style="--i:k;--n:n">`，并且每行再写一个 `data-text="整行文本"`。
  100 行 × 平均 20 字素 ≈ **2000 个带内联样式的 span**，外加把歌词文本存两份
  （文本节点 + data-text 属性）。每次 `setLines`（换歌 / 歌词重载）都
  `inner.innerHTML = parts.join("")` 整体重建这 2000 个节点。
  `fx-lyrics.css:130` 明确不写 will-change（正确，`README.md:34` 也把这条写成了约定），
  但入场动画仍为每个单元建立一条 CSS animation。
- **fx-lyrics 的逐帧路径**：`fx-lyrics.js:259-263 setPosition` 由宿主每帧调用
  （`playerhost.js:1028-1040 syncPlaybackState` → 每帧 `push({type:"progress"})`）。
  它只在行号变化时写 DOM（好），但 `paintHold`（`:200-219`）在 hold 变化时执行
  `el.querySelector(".fxl__text")` + `Array.from(children)`（`:213`）——
  一行 n 个字素 ⇒ 最多 n 次 querySelector + n 次数组分配/行；40 字素的长句翻倍。
- **arcade 的频谱写入**：`arcade.js:203-228 paintSpectrum` 每帧写 30 个 `--h` + 1 个 `--ag-bass`；
  宿主 30Hz 推送（`playerhost.js:1063-1090`，`SPECTRUM_HZ = 30`）⇒ 约 **930 次 setProperty/秒**。
  `arcade.js:222` 用 clip-path 而不是 height 已规避布局（好），但 style 失效仍会发生。
- **magia 的循环没有帧率上限**：`magia.js:1168-1217 step()` 直接 requestAnimationFrame 递归，
  对比 `fx-camera.js:111`（`maxFps: 60`）与 `:226-229`（minFrame 跳帧）。
  在 120Hz/144Hz 屏上就是双倍开销；且每帧 `putVars` 向 shell 与 bg 各写 8 个 CSS 变量
  （`:1193-1204`）、并调用 `inst.lyrics.paint()` + `follow()`（`:1206-1208`），
  其中 `follow()` 每帧直接写 `scroll.scrollTop`（`magia.js:982`）——一个每帧布局写入点。
- **建议修法（具体到函数）**：
  - `fx-lyrics.js#setLines`：把每行的单元节点数组一并缓存（`unitEls[i] = Array.from(...)`），
    `paintHold` 直接用它，去掉 `:213` 的 querySelector + Array.from；
    短行的 `--i/--n` 可以合并到行节点上（`--n` 只写一次），把内联 style 数从 O(字素) 降到 O(行)；
  - `arcade.js#paintSpectrum`：只在 `Math.abs(v - prev) >= 0.004` 时写（0.004 已是 1/250 的亮度差，
    离散方块看不出来），并缓存 `data-live` 避免重复写；
  - `magia.js#startLoop/step`：加与 fx-camera 同款的 maxFps(60) + minFrame 跳帧。

## 6. 一句话结论

皮肤包的**生命周期配平**问题集中在新并入的三个特效样式（anime/arcade 不归还背景层、magia 没做
