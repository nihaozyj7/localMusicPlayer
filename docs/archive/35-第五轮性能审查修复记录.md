## 二、修复过程中被测试/验证抓出的四个真问题（重要）

> 这部分比清单本身更有价值：每一条都是「看起来正确、实际改变了行为」的改动。

### 1. `Songs()` 快照漏标脏 —— 被现有测试抓到

加了排序快照后，`TestDropSongThenRescanFindsItAgain` **立刻失败**：

```
--- FAIL: TestDropSongThenRescanFindsItAgain (0.02s)
    library_test.go:377: 摘掉后应为 0 首，实际 1
```

原因：`DropSong()` 从 `m.songs` 里 `delete` 时**没有**标记快照失效，而快照是拷贝，不会跟着 map 的删除自动更新。
修法：在该处补 `markSongsDirtyLocked()`，并新增 3 个回归测试（`TestSongsSnapshotReflectsDrop` / `IsCopy` / `OrderIsStable`）钉住这一类 bug。

**教训**：任何「拷贝式缓存」都必须穷举**所有**写入点。我一开始只找到 2 处（`Scan`、`RescanPaths`），漏了第 3 处（`DropSong`）。

### 2. 筛选索引的 `\0` 分隔符反被查询串利用 —— 被自写对照测试抓到

索引把 `title\0artist\0album\0ext` 拼成一个串。若**查询词本身含 `\0`**，`includes("\0")` 会命中**所有**歌曲，与逐字段比较的结果不同：

```
MISMATCH q="\u0000" old=[] new=[1,2,3,4,5,6]
```

修法：查询串含 `\0` 时显式退回逐字段慢路径；并新增 `filterByQuery` 的 8 个回归测试（含 1 万首与逐字段实现逐项对齐）。

### 3. `settingsDerived` 的文件夹计数改变了语义（两次）—— 被自写对照测试抓到

第一次我加了 `if (f.path)` 守卫、第二次加了 `?? ""` 归一化，两次都与原表达式**不等价**：

| `f.path` | 原 `songs.filter(s => s.path.startsWith(f.path)).length` | 我的第一版 | 我的第二版 |
|---|---|---|---|
| `""` | **全库**（`startsWith("")` 恒真） | 0 ❌ | 全库 ✅ |
| `undefined` | **0**（按 `"undefined"` 比） | 0 ✅ | 全库 ❌ |
| `null` | **0** | 0 ✅ | 全库 ❌ |

修法：**不做任何归一化**，直接 `s.path.startsWith(f.path)` 传给原生语义。最终 7 个边界用例（含嵌套 / 空 / `undefined` / `null` / 重复路径）全部与原始表达式一致。

**教训**：重构派生计算时，「看起来更健壮」的守卫（`?? ""`、`if (x)`）恰恰是最容易改变语义的地方。

### 4. PowerShell 文本往返破坏了 UTF-8 —— 已回滚重做

用 `Get-Content -Raw` / `Set-Content` 批量插入代码时，中文注释被按系统编码重写，`gofmt` 报 `illegal UTF-8 encoding`。
修法：`git checkout` 还原该文件，改用 `edit` 工具（保留 UTF-8）逐处修改。**教训：本仓库的 Go/JS 源码含大量中文注释，禁止用 PowerShell 做文本替换。**

## 三、关键改动的语义等价性验证

### 筛选（`filterByQuery`）

对照「原逐字段实现」跑了 17 个查询（空串、trim、大小写、Unicode、分隔符、跨界用例）**全部一致**；另加 1 万首规模下与逐字段实现逐项比对。跨界用例确认分隔符确实阻止了 `["ab","c"]` 与 `["a","bc"]` 的混淆。

### 文件夹计数（`settingsDerived`）

7 个文件夹样例（嵌套 / 空串 / `undefined` / `null` / 重复路径 / 前缀相近但不同目录）与原始表达式**逐项一致**。

### 歌词面板（`lyrics.js`）

`s.position` 移出 deps 后，位置相关的两个更新（微调预览跟随、编辑器当前行高亮）改由 `subscribe()` 驱动。两个 paint 函数**本来就带**节流（`paintNowRow` 200ms）与「行号跑出窗口则整体重绘」的判定，所以行为不变 —— 只是触发路径从「整模板重渲染」换成「增量绘制」。

### 皮肤循环（magia / anime）

magia 的绘制侧（`putVars` 脏检查、sprite 粒子、单次 `clearRect`）**一行未动**，只补循环生命周期；`inst.playing` 本来就在 `:1416` 维护，只是从未被 `step()` 读取。anime 只把 `setEnabled(on)` 的入参从 `animOn` 改成 `animOn && playing`。

### loudness 的 stderr 上限为什么用 64KB 而不是 8KB

这条路径要从 stderr **解析 loudnorm 的 JSON**，而 `ParseLoudnormJSON` 是「找第一个 `{` 到最后一个 `}`」—— **不能从中间截断**。本机实测（ffmpeg 8.1.2、`-nostats`）：

| 样本 | stderr 总长 | JSON 位置 |
|---|---|---|
| 6 秒 | 1,426 B | 939~1211 |
| 60 秒 | 1,427 B | 同量级 |

**输出不随音轨长度增长**（进度被 `-nostats` 关掉），64KB 有约 45 倍余量；且做了端到端验证（真实 WAV → 测量 → JSON 解析成功，`input_i=-12.55`）。万一将来超限，表现为明确的「ffmpeg 未返回响度数据」错误，而不是静默给出错误数值。

## 六、给后续维护者的四条提醒

1. **`Songs()` 的排序快照必须穷举所有写入点。**
   凡是对 `m.songs` 做增删改的地方，都要调 `markSongsDirtyLocked()`（且必须持写锁）。漏一处就是「界面少一首 / 删了还在」这类静默 bug —— 本次已在 `Scan`/`RescanPaths`/`DropSong` 三处标记，并有 3 个回归测试兜住。

2. **`filterByQuery` 的 `\0` 分隔符有前提。**
   查询串含 `\0` 时必须走慢路径（已实现）；新增字段进索引时，分隔符必须保持 `\0`（不能用路径里可能出现的字符）。

3. **`settingsDerived()` 的失效键是「引用 + 长度」。**
   依赖 `songs`/`allSongsRaw`/`folders`/`filterRules` **整体替换**这一 store 约定。若将来改成原地修改数组，必须同步改失效逻辑。另外：**不要**给文件夹计数加 `if (f.path)` 之类的「健壮性」守卫（见 §二.3）。

4. **`loudness` 的懒加载要求新入口也调 `ensureLoaded()`。**
   已有 8 个入口接了。新增任何直接访问 `m.items`/`m.albums` 的公开方法时，必须在开头补 `m.ensureLoaded()`，否则会读到空表（表现为「设置页显示 0 条，但文件里明明有」）。
