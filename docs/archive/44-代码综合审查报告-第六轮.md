## 0. 摘要

### 0.1 一句话结论

这是一份**可以放心继续迭代**的代码库：工程门禁（lint / tsc / gofmt / vet / `-race`）全部真实可跑且当前全绿，`frontend/dist` 能从源码逐字节重建，路径穿越、SSRF、响应体上限、原子写盘这些「最容易翻车的地方」绝大多数已经做对并写进了注释与测试。

但它距离「无致命缺陷」还差一步：**有 1 个任何用户都可能触发的崩溃（< 1 秒的音频文件 → 整数除零 → 进程退出）**，2 个能造成「整库被清空 / 播放永久卡死」的功能级故障，以及 13 条高危缺陷。这些点都不是设计缺陷，而是**边界与并发**上的疏漏 —— 修起来都不贵。

### 2.2 第三方样式/主题 = 任意代码执行（设计层面，需在界面明示）

- 契约文档已诚实标注（`docs/42` §8.4「安全边界（诚实说明）」），但**安装路径上没有任何技术限制**：`packSource` 默认指向 GitHub raw，用户可改成任意地址；`internal/bootstrap/config.go:767-778` 的 `NormalizePackSource` **只判断 `https://` / `http://` 前缀**，`http://evil.example/plugins` 会被原样接受（中危，已确认）。
- 恶意样式包能做的事 = 应用能做的事（读写配置、下载、触发更新、读曲库元数据），并且**独立样式包的 `skin.js` 与主应用同上下文**。
- 建议（按性价比排序）：① `packSource` 只接受 `https://`，`http://` 仅放行 `127.0.0.1` / `localhost`（本地调试）并在 UI 明确警告；② 安装第三方样式前弹一次「这是代码，不是主题」的一次性确认；③ 中期给清单加签名（Ed25519，公钥内置二进制），把 `sha256` 从防呆升级为真边界。

### 2.3 更新链的哈希「自证」（高危，已确认）

- `internal/update/checker.go:333-379` 的 `FetchText` 用 `Candidates(url, ChannelAuto)[:3]` 取校验清单 —— 前三个候选就是「直连 + ghproxy.net + ghfast.top」；而 `Download`（`:409-462`）用**同一份代理名单**取 `.exe`。
- 结果是：当直连拿不到 GitHub 时（国内是常态），清单与安装包必然来自同一个第三方代理。此时 `sha256` 的一致性**完全由该代理决定**，界面上却显示「已校验」。
- 另外 `Install` 路径不检查 `Verified` 字段，`expectedSize` 恒为 0（低危），也就是「没拿到清单」时仍然会安装。
- 建议：校验清单**只允许直连 `github.com`**（拿不到就明确告知「无法校验，是否继续」并要求用户确认）；彻底方案是发布产物签名 + 内置公钥验签。

### 2.4 AI 端点零校验却承载真密钥（高危，已确认）

- `services_ai.go:147-150`：

  ```go
  base := strings.TrimRight(strings.TrimSpace(cfg.AIBaseURL), "/")
  if !strings.Contains(base, "://") { base = "https://" + base }
  ```

### 2.5 CSP 允许任意 WebSocket 外连（本次独立发现，中危）

`frontend/src/index.html:7-9`：

```html
default-src 'self'; img-src 'self' data: blob: file:; media-src 'self' blob: file:;
style-src 'self' 'unsafe-inline'; script-src 'self'; connect-src 'self' ws:
```

`connect-src` 里的裸 `ws:` 是**允许任意目标的 WebSocket**（`ws://evil.example` 也放行）。CSP 其余部分确实把 `fetch`/`img` 锁死在同源（这也是「封面必须走代理」的原因），于是 `ws:` 成了唯一的数据外发通道 —— 对「会在同源执行的第三方样式代码」来说，这恰好是最需要堵的一条。此外缺少 `object-src 'none'`、`base-uri 'self'`、`form-action 'none'`、`frame-ancestors 'none'`。
建议：`connect-src 'self'`（开发期若 HMR 需要，用构建期常量区分），并补齐上述四项。

## 3. 稳定性

### 3.1 崩溃级（1 条，必须先修）

**除零导致进程退出（严重）** —— `internal/meta/meta.go:131`、`:176`、`:315`、`:425` 都是同一形状：

```go
if ms > 0 {
    bitrate = int(st.Size() * 8 / (ms / 1000))   // ms ∈ [1,999] 时 ms/1000 == 0 → panic
}
```

`internal/library/library.go:882-904` 的 worker 没有 `defer recover()`（全仓 `recover` 只出现在 `internal/metacache/embed.go:134`），所以这不是「一首歌解析失败」，而是**整个应用退出**。触发条件极低：用户曲库里任意一个 < 1 秒的音频（铃声、切片、损坏文件）。
修复：`bitrate = int(st.Size() * 8 * 1000 / ms)`（先乘后除），收敛成一个辅助函数；worker 加 `recover` 把单文件异常降级为该文件元数据缺失；补一条 < 1 秒样本的单测。

### 3.3 并发与死锁（4 条高危/中危）

| 问题 | 位置 | 后果 |
| :--- | :--- | :--- |
| **试听缓存写失败 → 转发永久阻塞**（高危） | `services_online.go:601-632`（旁路 goroutine） | `WriteTo` 第一步失败即 `return`，既不读也不关 `pipe` 读端 → `TeeReader` 的 `pw.Write` 永久阻塞 → `io.Copy(w, body)` 不返回。**用户点「清空试听缓存」可稳定触发**（它会把正在写的 `.part` 删掉） |

### 3.4 扫描与文件系统（2 条高危）

- **junction / 符号链接根静默 0 首且报 `ok`**（高危）：`os.Lstat(junction).Mode()` 在 Windows 上是 `ModeIrregular`（不是 `ModeSymlink`），而 `walkFolder` 与 `addRecursive` 都以 `IsDir()` 为门槛。实测 `mklink /J` 之后，链接根与被包含链接子目录的真实根都返回 **0 首 + ok**，用户视角是「新加的目录一首歌都没有，还不报错」。建议：非普通项补一次 `os.Stat` 解引用后再决定是否下钻，并用真实路径去重防自指环。
- **扫描根自身读失败被吞仍报 `ok`**（中危）：`os.ReadDir` 失败时 `walkDir` 会二次回调并返回 `SkipDir`，被外层吞掉 —— `internal/library/library.go:675`、`:1155-1162`、`:1191-1200`。扫描根自身不可读同样是「0 首 + ok」，而 `:675` 会用这份空结果**整体替换**该文件夹的歌；`walkFolder` 因此只会返回 `missing` 或 `ok`，`:1191-1200` 的 `denied`/`error` 分支是死代码。

### 3.5 音频引擎（高危 1 + 中危 2）

- **`Load` 未按 `startFrame` 定位 feeder**（高危）：`internal/audioplay/engine.go:922-1006` 只 `Seek(headerSize)`，`startFeedLocked` 的 `startFrame` 参数**全文未被使用**。实测「以 1.9 秒为起点装载 2 秒 WAV」后 `Buffered` 仍是 2000ms —— 跳过开头静音不生效、位置整体超前、尾部区间永远听不到。
- **feeder 在非 4 字节对齐短读上永久空转**（中危）：`internal/audioplay/engine.go:1044-1071` —— `ringBuffer.write` 在 `len(pcm)/FrameSize == 0` 时返回 0，写循环遇 0 只 `sleep 5ms` 后 `continue`，`written` 不前进使内层 `for` 永不退出；PCM 长度为非 4 整数倍（尾部剩 1~3 字节）即命中，后果是**整条播放链无声且无日志**。
- **`PrepareSwitch` 留下「假装在播」的静音态**（中危）：`internal/audioplay/engine.go:535-557` —— 停 feeder、重置 ring、`setClosed(false)` 但不动 `playing`，回调读 0 帧且 `closed` 为假直接 return，不推进位置也不报 EOF；前端对 `failedSongId` 直接 return，连 `Pause` 都发不到后端。

### 3.7 其余稳定性发现（中低危，共 60 余条）

### 4.4 格式化门禁名存实亡（中危）

- `package.json` 有 `format:check`，`AGENTS.md` §2 也把它列为可用命令，但 **`npm run format:check` 当前对 104 个文件报警**。
- 分布：`frontend/src/js/**` 13 个、`frontend/tests/**` 13 个、`tools/**` 15 个、`docs/**` 30+ 个、`frontend/.vite/deps/_metadata.json`（构建缓存应当忽略）等。
- 根因是 `.prettierignore` 的注释自陈的：忽略范围从「整个 `frontend/src/`」被**精确收窄**成 `frontend/src/styles/` + `frontend/src/*.html`（理由充分），但**收窄之后没有跑过一次 `prettier --write`**，于是这些文件永远处于「不在忽略名单里、也从来没被格式化」的状态，`npm run format` 一旦被人执行就会产生 104 个文件的巨型 diff，把真实改动淹掉。
- 建议（二选一，别放着）：① 跑一次 `prettier --write` 并把 `format:check` 加进 `npm run check` / CI；② 明确把 `frontend/src/js/**`、`frontend/tests/**`、`tools/**`、`docs/**`、`frontend/.vite/` 写回忽略名单，并在注释里写清「本仓库不统一格式化 JS」。**推荐 ①**，因为这个仓库对一致性的要求很高。

- **过滤规则双真源**（中危）：`store.js:2308-2363` 的 `SYNCED_KEYS` 里**没有** `filterRules`，规则只走本地快照的单一写通道（`:2403-2405`、`:2428`）；而 `applyPatch`（`services.go:2368-2387`）接收端齐备，启动时 `:2563` 还会用后端非空的默认规则**覆盖本地** —— 用户改完规则，重启后可能被后端旧值盖回去。这与 §3.2 的空正则问题是同一处的两面，**应当一起修**（把 `filterRules` 加进 `SYNCED_KEYS`，或明确规则只是展示层并删掉扫描路径上的 `filter.Apply`）。

- **`services.go` 单文件混排 8 个服务 + 两套窗口状态机**（低危，但它是 §4.1 里体量问题的根）。
- **两只「注入型副作用」各写一遍**：`audio.js` 与 `store.js` 之间靠 `register` 钩子互相注入，注释里承认「理由同上面的 probe」—— 这类隐式依赖没有类型/接口约束，是重构时最容易崩的地方（低危）。

## 7. 值得保留与推广的工程实践

这份代码库有若干**高于其规模应有水平**的做法，建议在后续迭代中刻意保持：

1. **「注释写清代价」的文化**：`internal/update/checker.go:488-500` 解释为什么下载 Transport 要 `DisableKeepAlives`（附实测 8 通道各卡 25 秒的现象），`internal/media/server.go:182-202` 解释为什么启动时要清 `tc_*.wav`，`internal/coverfetch/http.go:166-176` 解释为什么封面代理要单独一个 client —— 这些都是「三个月后的自己会感谢」的东西。
2. **凡是不可信输入都有上限**：`LimitReader` 几乎无处不在，且注释里写了「为什么是这个数」。
3. **契约到处有守卫测试**：配置键三处同步、`StableID` 两端一致、CSS 视觉令牌、桥接键名、Go 事件名与前端订阅名一致 —— 这些测试的价值远高于覆盖率数字。
4. **构建可复现**：本次实测重建 `frontend/dist` 与 `bindings` 后 `git status` 干净，入库产物没有腐烂。
5. **平台差异用文件名后缀表达**（`*_windows.go` / `*_other.go`），并保证 `_other` 分支能编译。
6. **写用户文件的代码「证明不了安全就不写」**：`metacache/embed.go` 的白名单 + 放弃写入 + 原子改名，配合 `embed_offset_test.go`，这是整个仓库里最专业的一段。
7. **诚实的安全说明**（`docs/42` §8.4「安全边界」）：明确承认「安装第三方样式 = 运行代码」，并写明 UI 必须提示 —— 大多数项目在这里会含糊其辞。
