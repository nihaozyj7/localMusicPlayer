# 本地音乐播放器 Go 后端 只读安全与健壮性审查报告

> 审查范围：仓库根目录 Go 文件 + `internal/**`（已排除 `build\ffmpeg\`、`node_modules`、`.task`、`.git`）
> 技术栈：Go 1.25 / Wails v3 beta.14（本机工具链 go1.27.0 windows/amd64）
> 审查方式：**纯只读**。未修改任何业务文件。所有行号均来自实际读取的代码。
> 结论编号：C=CONFIRMED（已核实）、S=SUSPECTED（存疑/未完全证实）、U=无法确定。

## 0. 执行摘要

整体安全姿态**明显好于同类 Electron/Tauri 项目**：`internal/skins`、`internal/theme`、
`internal/covercache`、`internal/coverfetch`、`internal/metacache/safeFileID` 这几处的路径穿越防护
是**真的做对了**（Clean + `withinDir` 前缀校验 + 白名单正则 + 删除前二次确认），SSRF 白名单也
做到了逐跳复检。**没有发现可直接利用的任意文件读取或目录穿越**。

真正的风险集中在两处：

1. **`internal/metacache/embed.go`**（写回用户音乐文件）——这是全仓最危险的文件。解析长度
   未 clamp 会 **panic**，`size==0`/`size==1` 未处理会**按错误偏移重写用户文件**，`os.Rename`
   失败无回退且**全程没有任何备份**。这是唯一可能导致**用户音频文件永久损坏/丢失**的模块。
2. **网络客户端卫生**——`services_download.go:550` 与 `services_online.go:428` 使用
   `http.DefaultClient`（无超时），且落盘/转发**没有任何字节上限**。

另有若干 P2/P3：AI API Key 通过 Wails 绑定回传前端、AI Key 明文存盘、token 出现在 Referer、
CORS 通配、`bytes.Buffer` 无界收集 ffmpeg stderr、watcher 停止后无法重启等。

**最需要优先处理的三项**：`embed.go` 的 panic/错位重写（P0）→ `writeFileAtomic` 无回退（P0）
→ 网络客户端与字节上限（P1）。

## 1. 路径穿越 / 任意文件读取（焦点 1）

### 结论：**未发现可利用的目录穿越。以下防护经核实是有效的。**

#### ✅ C-1. `internal/covercache/covercache.go:55` —— 正则未转义，但**不可利用**

```go
var namePattern = regexp.MustCompile(`^[0-9a-f]{16}.(jpg|png|gif|webp|avif|bmp|tiff?)$`)
```

中间的 `.` **未转义**（应为 `\.`），初看像是防线漏洞。我用 Go 实际编译并运行了该正则做验证：

```
match=false  input="../boot-frame.jpg"          → join="C:\cache\boot-frame.jpg"
match=false  input="..\\boot-frame.jpg"         → join="C:\cache\boot-frame.jpg"
match=true   input="0123456789abcdef.jpg"       → 正常
match=true   input="0123456789abcdefXjpg"       → join="C:\cache\covers\0123456789abcdefXjpg"
```

**为什么不可利用**：`{16}` 定长量词已把前缀钉死为恰好 16 个 `[0-9a-f]` 字符，因此 `.`
能匹配的只剩**第 17 个字符**这一个位置；该位置之后必须紧跟已知扩展名并立即 `$` 结尾。
`../` 需要至少两个额外字符（`.` 和 `/`），塞不进这个单字符槽位；`..\boot-frame.jpg`
同理。`covercache.go:137-146 Path()` 与 `:187-192 handle()` 都经过 `ValidName` 过滤，
且 `:141` 的 `filepath.Join` 不会逃逸。

**修复（低优先级，防御性）**：把 `.` 改成 `\.`，并加 `(?i)` 以便与 `:288` 的
`strings.ToLower(filepath.Ext(name))` 口径一致。当前写法只是"幸运地安全"，语义应显式表达。

## 2. 本地 HTTP 服务鉴权（焦点 2）

### 2.1 token 强度：够用

`internal/media/server.go:72`：

```go
token: bootstrap.RandomID("tk"),
```

`internal/bootstrap/ids.go:34-40`：

```go
func RandomID(prefix string) string {
	buf := make([]byte, 8)
	if _, err := rand.Read(buf); err != nil {
		return prefix + "_" + hex.EncodeToString([]byte(strconv.FormatInt(0, 10)))
	}
	return fmt.Sprintf("%s_%s", prefix, hex.EncodeToString(buf))
}
```

8 字节 `crypto/rand` = 64 bit，每进程启动随机。对**本机回环**场景足够（在线爆破 2^64 不可行）。

> ⚠️ **S-1（存疑，低危）**：`ids.go:36-38` 的失败回退路径返回
> `prefix + "_" + hex("0")` = 形如 `tk_30` 的**固定可预测 token**。
> `crypto/rand.Read` 在 Windows 上失败概率极低，因此我判定这条**实际不可达**，
> 但"随机源失败时退化为常量"是危险设计模式。建议改为 `panic` 或返回 error，
> 而不是静默降级为常量。

### 2.2 token 恒定时间比较：非恒定，但不可利用

`services_online.go:355-357`：

```go
func (s *OnlineService) checkToken(r *http.Request) bool {
	return r.URL.Query().Get("t") == s.token
}
```

`media/server.go:248`、`covercache.go:183` 同样是 `!=` / `==` 直接比较。
Go 的字符串比较会短路，理论上有时序侧信道。但：token 是 64 bit、服务只监听
`127.0.0.1`（`server.go:113`）、且没有可用的高频探测通道 —— **P3，实践上不可利用**。
建议若追求严谨可用 `crypto/subtle.ConstantTimeCompare`。

### 2.3 ⚠️ C-7【P1】token 通过 URL query 泄露到 Referer / 日志 / DTO

`internal/media/server.go:195-202`：

```go
return fmt.Sprintf("%s%s?t=%s", AudioPrefix, songID, s.token)
```

`services_online.go:120-121, 149, 227`：

```go
"streamUrl":   onlinePrefix + "audio?id=" + bvid + "&t=" + s.token,
"downloadUrl": onlinePrefix + "download?id=" + bvid + "&t=" + s.token,
...
"url":       onlinePrefix + "cover?src=" + url.QueryEscape(cover.URL) + "&t=" + s.token,
```

**为什么重要**：
1. token 被嵌入**返回给前端的 DTO**（搜索结果、封面列表），因此必然进入渲染进程内存与
   DevTools 网络面板；
2. 这些 URL 是页面内 `<img src>` / `<audio src>` 的目标，浏览器在加载**第三方**资源时
   （若页面存在任何外链）会把完整 URL 作为 `Referer` 发出 —— token 随之外泄；
3. query string 常被各类代理/日志系统记录（此处无代理，但 `services.go` 有日志路径）。

**缓解事实**：服务只绑 `127.0.0.1`，且页面 CSP 为 `img-src 'self'`，限制了外链。
**修复**：改用自定义请求头（如 `X-LMP-Token`）+ 一次性短期票据；或至少改用
`Sec-Fetch-Site`/`Origin` 校验替代 query token。若必须保留 query token，
在服务端显式设置 `Referrer-Policy: no-referrer`。

### 2.4 ⚠️ C-8【P1】`/online/` 代理对任意源开放 CORS

`services_online.go:438`（在 `proxyStream` 内）：

```go
h.Set("Access-Control-Allow-Origin", "*")
```

**为什么重要**：与 `media/server.go:293-303 setCORS`（回显 Origin + `Vary: Origin`，
至少是有意设计并配了 `Vary`）不同，这里是**无条件 `*`**。`/online/audio`、
`/online/download`、`/online/cover` 都走 `proxyStream`。虽然 `checkToken` 先执行，
但结合 C-7（token 通过 DTO 暴露给渲染进程），任何能读到该 token 的本机页面
都能跨源读取音频流与封面内容。

**修复**：删除该行，或改为与 `setCORS` 一致的 Origin 回显 + 白名单
（只允许 `http://wails.localhost`）。

## 3. 静态密钥（焦点 3）

### 3.1 ⚠️ C-11【P1】AI API Key 通过 Wails 绑定明文回传前端

`main.go:177`：

```go
application.NewService(NewConfigService(store)),
```

`services.go:899-901`：

```go
func (s *ConfigService) Get() bootstrap.Config {
	return s.store.Get()
}
```

`internal/bootstrap/config.go:235`：

```go
AIAPIKey   string `json:"aiApiKey"`
```

`ConfigService` 是**注册给前端的 Wails 服务**（`main.go:177`），而 `Get()` 返回**整个
`Config` 结构体**，其中 `AIAPIKey` 是导出字段且带 JSON tag → **密钥原样进入渲染进程**。

同时 `services.go:904-912 Set()` 返回值也是完整 `Config`，`Reset()`（`:918-930`）同理。

**为什么重要**：渲染进程是 WebView2。任何 XSS、恶意皮肤（注意 `/skins/` 提供的是
**用户可写目录里的 JS**，见 `skins.go:11-12` 的注释"皮肤是一个完整的样式包：一段 JS"）、
或被注入的第三方内容，都能直接读取 API Key。而皮肤机制**明确设计为从用户目录加载任意 JS**，
这大幅提升了前端被注入的现实可能性。

**修复（三选一，建议 1+2 并用）**：
1. 在 `ConfigService.Get/Set/Reset` 返回前**打码**：`cfg.AIAPIKey = maskKey(cfg.AIAPIKey)`，
   只回传 `"sk-…abcd"` 形式的尾 4 位；前端提交时若值为掩码串则保留原值不覆盖。
2. 新增专用 `AiService.SetAPIKey(key string)` 单向写入接口，`Get` 永不返回明文。
3. 至少给 `AIAPIKey` 加 `json:"-"`，改用独立的 `GetAIKeyMasked()`。

### 3.2 ⚠️ C-12【P1】配置文件权限宽松，密钥明文落盘

`internal/bootstrap/config.go:984-1021 saveLocked()`：

```go
tmp := fmt.Sprintf("%s.%d.tmp", s.cfg.ConfigPath, atomic.AddUint64(&s.tmpSeq, 1))

```

```go

```

**为什么重要**：`0o644` 在 Windows 上语义有限（Windows 用 ACL 而非 POSIX mode，
Go 会尽力映射），但在**多用户 Windows**或数据目录被同步到云端/共享盘时，
密钥以**明文 JSON** 存储且权限宽松。`config.json` 是单一文件，
一旦被读取即完全失守。

**修复**：
- 短期：改 `0o600`（`os.WriteFile` 的 perm 参数在新建文件时生效）。
- 正解：用 Windows DPAPI（`CryptProtectData`，用户范围）加密 `AIAPIKey` 后再落盘，
  读取时解密。这样即使文件被拷走也无法直接使用。

## 4. 命令注入 / 进程生成（焦点 4）

### 结论：**未发现命令注入。**所有子进程都用参数数组传参，无 shell 拼接。

逐一核对全部 `executil.Command*` 调用点：

| 位置 | 参数来源 | 注入风险 |
|---|---|---|
| `internal/ffmpeg/ffmpeg.go:413` `Probe` | `"-i", path` | ✅ 数组传参，`exec.CommandContext` 不经过 shell |
| `internal/ffmpeg/ffmpeg.go:460` `SoundDurationMS` | `"-i", path` | ✅ |
| `internal/ffmpeg/ffmpeg.go:513` `TranscodeToWAV` | `"-i", src` | ✅ |
| `internal/loudness/loudness.go:600` `analyse` | `"-i", path` | ✅ |
| `services.go:1854` | `executil.Command(exe, os.Args[1:]...)` | ✅ 重启自身 |
| `services.go:1920-1924` | `"explorer", path` | ✅ 见下 |

`internal/executil/executil.go:18-22` 是 `exec.CommandContext` 的薄封装（加隐藏窗口标志），
**没有** `sh -c` / `cmd /c` 拼接。Go 的 `exec` 在 Windows 上使用 `CreateProcess`
并自行处理引号，参数数组**不可注入**。

**`revealPath`（`services.go:1915-1925`）的风险评估**：`path` 来自用户配置的文件夹路径，
传给 `explorer.exe`。由于是数组传参，`explorer` 不会把它当参数解析出额外开关；
但 `explorer` 本身对**以 `/` 或 `-` 开头的路径**有特殊解析（可能被当成开关）。
这属于 P3 边界情况，且路径来自用户自己配置的目录，**不构成注入**。

### 4.1 ⚠️ C-13【P2】ffmpeg stderr 无界缓冲（转码路径）

`internal/ffmpeg/ffmpeg.go:523-524`：

```go
var stderr bytes.Buffer
cmd.Stderr = &stderr
```

对比同文件 `Probe`（`:429`）与 `SoundDurationMS`（`:469`）**都用了限长收集器**：

```go
stderr := newBoundedBuffer(maxStderrBytes)  // maxStderrBytes = 8 << 10 (ffmpeg.go:309)
```

`Probe` 的注释（`:427-428`）明确解释了为什么必须限长：

> 用限长收集器而不是 bytes.Buffer：容器元信息全在头部，尾部（逐帧进度）
> 对解析毫无用处，却会无上限地吃内存。

**但 `TranscodeToWAV`（`:506-546`）走了例外**：它用的是裸 `bytes.Buffer`。

### ⚠️ C-18【P1】符号链接被替换为普通文件（非跟随）

#### 🔴 C-36【P1】下载的 TOCTOU：`uniquePath` 的防覆盖保护被绕过

`services_download.go:778-790` 明明是为了"避免覆盖同名文件"：

```go

	candidate := filepath.Join(dir, base+ext)
	if !fileExists(candidate) {
		return candidate, nil
	}
```

但它在 `:426` 被调用取名后，要经过**整个网络下载过程**才在 `:535` 执行改名：

```go
target, err := uniquePath(dir, name, "."+ext)   // :426  取名
...
size, err := s.fetchTo(ctx, stream, target, ...) // :439  下载（可达数分钟）
...
if err := os.Rename(tmp, target); err != nil {   // :535  改名
```

**为什么重要**：这个窗口可长达数分钟（`:406` 的 ctx 上限是 20 分钟）。期间若同名文件

**会替换目标**，**静默销毁已存在的文件**。而"不覆盖同名文件"正是 `uniquePath`

**修复**：下载前用 `os.OpenFile(candidate, os.O_CREATE|os.O_EXCL, 0o644)` **原子抢占**目标名
