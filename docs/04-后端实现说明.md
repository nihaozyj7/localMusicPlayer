> 总体方案见 `docs/03-技术方案.md`。本文只讲**已经落地的后端实现**。

## 1. 代码结构

```
main.go                     应用入口：装配配置、主题、曲库、音频服务、窗口与服务注册
services.go                 7 个 Wails 服务（前端直接调用的接口层）
internal/
├── bootstrap/
│   ├── config.go           数据模型 + 配置读写（%APPDATA%\MusicPlayer\config.json）
│   └── ids.go              稳定 id（与前端同一算法）+ 音频扩展名 / 转码判定
├── filter/filter.go        过滤规则引擎（与前端 store.js 语义逐条对齐）
├── library/
│   ├── library.go          扫描、元数据缓存、增量重扫、文件夹状态
│   └── watcher.go          fsnotify 递归监听 + 500ms 事件防抖
├── meta/meta.go            标签解析（dhowden/tag）+ 自写时长解析（mp3/flac/wav/m4a）
├── lyrics/lyrics.go        .lrc 文件 → 内嵌歌词，按设置里的优先级
├── media/server.go         本地音频 HTTP 服务（Range 支持 + ffmpeg 转码流）
└── theme/theme.go          主题目录扫描、内置主题同步、文件头指令解析
```

## 3. 数据落盘

| 文件 | 位置 | 内容 |
| --- | --- | --- |
| `config.json` | `%APPDATA%\MusicPlayer\` | 全部设置、文件夹列表、过滤规则、歌单、我喜欢 |
| `metadata-cache.json` | 同上 | 元数据缓存（path/size/mtime 命中即复用，重扫几乎零成本） |

## 4. 需求落地对照（后端部分）

| 需求 | 实现 |
| --- | --- |
| A1 多个本地音乐路径 | `config.json#folders`；`AddFolder` 调系统目录选择器，去重、校验可访问性 |
| A2 监听文件夹自动更新 | `library.Watcher` 递归 `fsnotify`，新建目录动态补登记，500ms 防抖合并后增量重扫，结果通过 `scan:done` 事件推给前端 |
| A3 按文件大小过滤 | `filter.Match`：`size/lt/10240/B`，支持 KB/MB/GB 换算 |
| A4 按正则过滤 | `filter.Match`：同时匹配完整路径与文件名，忽略大小写，非法正则只跳过自身并在设置界面标红 |
| A5 深浅主题 | `ThemeService` + `Config.theme/themeMode`，配置落盘 |
| A8 用户自定义主题 | `theme.NewManager` 把内置主题写入用户目录并扫描；文件头 `@theme-name/@theme-mode/@theme-swatch` 指令解析；新增文件即可在设置界面出现 |
| B2 重新扫描 | `Library.Scan` 异步执行，`scan:start/progress/done/failed` 事件驱动进度与 Toast |
| B6 「我喜欢」不可删除 | `Playlist.Delete/Rename` 对 `liked` 直接返回错误；`ToggleLike` 是唯一入口 |
| B4 播放列表拖拽排序 | 前端即时生效 + `Playlist.Reorder` 持久化 |
| C 播放 | `media.Server`：原生格式走 `ServeContent`（支持 Range → 精确 seek）；ape/wma 等由 ffmpeg 转 WAV 流；地址带随机 token，仅监听 127.0.0.1 |
| — 歌词 | `lyrics.Load`：同名 `.lrc`（含 `song.zh.lrc`）→ 音频内嵌歌词 |

测试覆盖（`internal/*/**_test.go`）：

- **id 兼容性**：`StableID` 与前端 `utils.js#stableId` 逐条比对（含中文路径）。
  这条最关键 —— 一旦不一致，重扫后歌单/收藏/播放队列会集体失效。
- **过滤引擎**：大小、正则、组合规则（「排除小于 10KB 的 .mp4」）、
  排除优先于仅包含、非法正则跳过、单位换算、无规则全保留。
- **曲库**：真实 WAV 文件的扫描与时长解析、文件夹缺失状态、
  元数据缓存复用、增量重扫、**fsnotify 真实触发**（写入文件后 5 秒内曲库更新）。
- 音频服务实测：`http://127.0.0.1:60400`（随机端口），`canTranscode: true`
  （自动在 `%USERPROFILE%\Application\ffmpeg-*\bin` 找到 ffmpeg）。

## 6. 两个踩过的坑（改代码前务必知道）

1. **`StableID` 必须按 UTF-16 码元计算**
   JS 的 `charCodeAt` 按 UTF-16 取值，中文占 2 个码元。Go 若直接遍历 UTF-8 字节，
   同一路径会算出不同 id。实现里用 `utf16.Encode`，并有测试守着。

2. **`fsnotify` 不递归**
   必须对每个子目录分别 `Add`，并在 `Create` 事件里判断是否是目录、递归补登记，
   否则新建子文件夹里的歌永远不会被扫到。
