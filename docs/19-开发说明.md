# 音乐播放器

本地音乐播放器 · **Go + Wails3** · 前端仍是原生 HTML/CSS/JS（**没有框架**，但有构建与检查：Vite + npm workspaces + ESLint + tsc 类型检查 + 单测）

当前状态：**界面 + 后端都已实现，可编译运行**。

- 界面：浏览器里就能预览与评审（不需要 Go）
- 后端：扫描 / 文件夹监听 / 过滤 / 元数据 / 封面 / 歌词 / 音频播放 / 配置落盘，见 `docs/04-后端实现说明.md`
- 播放界面样式（皮肤）：抽成独立包 `frontend/packages/player-skins/`，第三方样式可放进数据目录扩展

## 前端工程化

前端**没有引入框架**（界面代码仍是可直接阅读的原生 ESM），但加上了开发所需的工程设施：

```powershell
npm install            # 只做一次：安装 Vite / ESLint / Prettier / TypeScript
npm run dev            # Vite 开发服务器（HMR），等价于 wails3 task dev:frontend
npm run build          # 构建到 frontend/dist（= node tools/build-frontend.mjs）
npm run lint           # ESLint（含 no-unused-vars / prefer-const / eqeqeq…）
npm run format:check   # Prettier 检查（npm run format 直接改）
npm run typecheck      # tsc 类型检查（JSDoc + checkJs，逐个文件收紧，见 tsconfig.json）
npm test               # node:test 单测（皮肤包的 LRC 解析 / 契约 / 注册表）
npm run check          # lint + typecheck + test，提交前跑这个

npm run dev:static     # 静态预览（等价于 tools/dev-server.js；第三方包走 node_modules 的 /vendor 映射）
```

同一套流程也挂在 Taskfile 上（`build` 会自动跑 Vite 构建，缺 `node_modules` 时先 `npm install`）：

```powershell
wails3 task build               # = frontend:deps → generate:bindings → ffmpeg:build → build:frontend → go build
wails3 task frontend            # 只重新构建 frontend/dist
wails3 task check               # = npm run check（ESLint + tsc + 单测）
wails3 task dev:frontend        # Vite 预览（HMR）
wails3 task dev:frontend:static # 静态预览（自检脚本请用这个）
```

> 构建入口 `wails3 task build` 的退出码是有意义的：它现在返回 0。
> 之前本机 PowerShell 配置里的 `Set-PSReadLineOption` 在输出被重定向时会报错，
> 让最后的清理步骤（`powershell Remove-item *.syso`）把整个构建的退出码带成 1 ——
> 明明 exe 已经生成好了。现在那一步用 `powershell -NoProfile` 跑。

目录结构：npm workspaces 根包 + 两个工作区
（`frontend` = 应用壳，`frontend/packages/player-skins` = 播放界面样式包）。

几个刻意的取舍，避免以后被"工程化"反咬：

- **源码还是原生 JS**：打包器只负责依赖解析与产物哈希，不引入 JSX/TS。
  需要类型的地方用 JSDoc（`tsc --checkJs` 能吃到），保持「打开文件就能读」。
- **类型检查是"逐个文件收紧"**：`checkJs: false` 时 tsc 仍然会做**全量语法检查**，
  只有文件顶部写了 `// @ts-check` 才会做类型检查。新代码（皮肤包、playerhost）都带这个标记，
  历史文件等有空再补 —— 一个永远红着的检查等于没有检查。
- **Prettier 暂不覆盖 `frontend/src`**（见 `.prettierignore` 里的说明）：那里很多数值是量出来的，
  `index.html` 里行内元素的空格还有语义。ESLint 仍然覆盖它。
- **Vite 只负责 `frontend/src` 与工作区包**：Wails 生成的 `frontend/bindings` 是**运行时**
  按 URL import 的（`bridge.js` 里用变量说明符 + `@vite-ignore`），因此不参与打包，
  由 `tools/build-frontend.mjs` 原样拷进 `frontend/dist/bindings`。

## 运行应用

```powershell
# 首次构建前先编译内置 ffmpeg（精简版约 6MB，只需一次，约 6~10 分钟）
# 需要 MinGW-w64（gcc/nasm/mingw32-make）+ 一个 bash（Git for Windows 自带）
node tools/build-ffmpeg.mjs

# 构建（会同步前端产物 + 生成绑定 + 编译，带上内置 ffmpeg 约 18MB）
wails3 build
.\bin\musicplayer.exe

# 跑后端测试
go test ./...

# 看看内置 ffmpeg 的体积/许可证/实际编进去的能力
node tools/build-ffmpeg.mjs --info

# 打包 Windows 安装程序（需要本机安装 NSIS）
wails3 task package
```

首次运行会在 `%APPDATA%\MusicPlayer\` 生成 `config.json` 与 `themes\`（内置主题会同步过去）。
添加音乐文件夹后，扫描与监听都会自动生效。

**ffmpeg 是内置的**：首次启动会把编译进 exe 的 ffmpeg 解包到
`%LOCALAPPDATA%\MusicPlayer\bin\`（约 6.0MB，按内容哈希命名，只解包一次）。
因此用户机器上不需要预装 ffmpeg；`ape/wma/dsf` 等格式能直接播放。
如果本机已装了 ffmpeg 也可以指定：

```powershell
$env:MUSICPLAYER_FFMPEG = "D:\ffmpeg\bin\ffmpeg.exe"   # 优先使用它
$env:MUSICPLAYER_FFMPEG_DIR = "D:\mp-bin"              # 改内置版本的解包位置
```

> 内置的是 GPL 构建版 ffmpeg，许可证随二进制放在
> `internal/ffmpeg/bin/FFMPEG-LICENSE.txt`，再分发时请一并保留。

## 窗口行为：单实例 / 托盘 / 图标 / 首屏

- **单实例**：第二次双击图标不会再开一个进程，而是把已经在跑的那个窗口显示出来并抢焦点
  （Wails 的 `SingleInstanceOptions`，UniqueID = `com.musicplayer.app`；第二个进程通知完
  自己立刻退出）。
- **关闭到托盘**：设置 → 外观 →「关闭时最小化到托盘」。打开后点关闭按钮只把窗口收进系统
  托盘（左键直接显示、右键菜单有「显示主界面 / 退出」），音乐继续播放；关掉这个开关，
  点关闭就是真正退出。
  托盘图标只在开关打开时创建（`WindowService.ensureTray`）；拦截关闭用的是主窗口
  `WindowClosing` 的 **Hook + Cancel**（钩子比监听器先跑，否则 Wails 内建的
  「关闭 = 销毁窗口」已经执行了）。
- **应用图标**：`build/appicon.png`（参考 `音乐.svg` 的粉底白色音符）→
  `wails3 task generate:icons` 生成 `build/windows/icon.ico` 与 `build/darwin/icon.icns`，
  构建时由 `generate:syso` 把 ico 打进 exe；系统托盘直接 embed 同一个 PNG。
- **首屏不白闪、也不黑闪**：分三层解决，缺一层就会看到「白一下 / 黑一下 / 空一下」。
  1. 主窗口 `Hidden: true` 创建 —— 不隐藏时 Wails 会用带 `WS_VISIBLE` 的样式创建窗口，
     WebView2 在页面渲染出第一帧前会先亮一块白底（首屏那一下白闪）。
  2. 应用一跑起来就给它打上 DWM 的隐身标记（`DWMWA_CLOAK`），**先显示出来、但遮住**：
     `WS_VISIBLE` 让 WebView2 正常合成出帧、rAF 正常派发，而用户什么都看不见；
     前端把首帧画好后再摘掉遮罩，于是窗口「出现」的那一帧已经是画好的帧
     （见 `window_reveal_windows.go` 与 `services.go#showPrepared`）。
     ★ 这里有个坑：**窗口真隐藏时不能用 `requestAnimationFrame` 等首帧** ——
     WebView2 不派发 BeginFrame，rAF 永远不执行，而 `document.visibilityState`
     仍是 `visible`，从 JS 侧完全看不出来。遮罩方案正是为了让这个前提不成立。
  3. 露面时看到的画面是**上次退出时缓存的上一帧**：退出时用 `PrintWindow`
     （`PW_RENDERFULLCONTENT`）抓一张 JPEG 写进缓存目录，启动时由 `/boot-frame.jpg`
     提供给 `index.html#boot-splash`，真正的界面装配好再淡出 —— 观感就是「窗口一
     出现就是刚才那个界面」（见 `boot_frame.go` / `js/main.js`）。
     首次启动、抓帧失败或非 Windows 时，同一层就是加载动画那一形态（缓存图加载
     失败时浏览器会画一个「碎图标」，所以它默认 `opacity: 0`，只有确认加载出来了才
     打上 `data-hasframe` 露出来 —— 见 `index.html#boot-splash-style`）。
  4. 遮罩期间窗口虽然已经 `WS_VISIBLE`，但会先被摘掉任务栏按钮
     （`WS_EX_TOOLWINDOW`，露面时换回 `WS_EX_APPWINDOW`）—— 否则任务栏图标会比
     窗口早出现几百毫秒，看着就像「点了半天没反应」。
  5. 「首帧画好了」这句信号走的是**普通 HTTP 请求**（`/boot/reveal`），不是 Wails 的
     JS→Go 绑定：启动阶段宿主主线程正忙着初始化 WebView2，绑定消息实测会被压后近一秒
     （窗口就白等这么久）；HTTP 走网络栈，几十毫秒内到。前端在模块的第一句可执行代码里
     就把它发出去，所以窗口露面几乎与首帧同时发生。
     兜底仍在：Go 侧 1.5s / 4s 各补一次 `MarkReady`，前端另有 12s（撤下过渡层）的定时器；
     `MarkReady` 只在「还没真正显示过」时动手，重复调用不会抢焦点。
     实测冷启动：窗口（连带任务栏图标）约 1.0~1.2s 出现，露的就是缓存的那一帧。
- **托盘唤起 / 第二次启动**：窗口会显式刷一次 z 序并抢前台（`raiseNativeWindow`），
  而不是只依赖 Wails 的 `Focus()`（它内部只有一句 `SetForegroundWindow`，对「不是当前
  前台进程」的调用会被系统拒绝，表现就是窗口出来了却还压在其他窗口下面）。
- **主窗口圆角**：设置 → 外观 →「窗口圆角」（跟随系统 / 标准 / 小圆角 / 直角）。
  圆角与 Aero 阴影都来自 DWM（`DwmExtendFrameIntoClientArea` +
  `DWMWA_WINDOW_CORNER_PREFERENCE`，只有这几档、没有任意半径）。原来它只在
  `WM_ACTIVATE` 里设置，而遮罩方案下这次激活可能被跳过（表现就是窗口没阴影、没圆角），
  所以现在每次露面都会显式重设一次；圆角改完立刻生效，不需要重启。

## 响度均衡（音量一致化）

不同来源的音乐响度差得很远。实测你的曲库（53 首 m4a）：

```
实测响度范围: -23.25 ~ -8.51 LUFS  →  相差 14.74 LU
补偿增益范围: +4.67 dB ~ -7.49 dB
```

也就是说切歌时音量可能突然跳 15 dB。开启响度均衡后，每首歌会被补偿到同一个
目标响度（默认 **-16 LUFS**），切换歌曲音量保持稳定。

- 在 **设置 → 响度均衡** 里选择模式：`关闭` / `逐曲均衡` / `同专辑统一`
- **不需要预先扫描**：播到哪首就算哪首，算好的补偿会缓存下来，之后播放零延迟
- 改了 **目标响度** 后旧补偿会自动失效，并按新标准重算
- 「预先把全部歌曲算好」只是可选的批量预热，正常使用不需要点

实现要点：

- 整合响度与真峰值由**纯 Go 实现**的 ITU-R BS.1770-4 / EBU R128 计算
  （K 加权 + 400ms 门限块 + 真峰值 4 倍过采样），与 ffmpeg 的 `loudnorm`
  在真实曲库上平均偏差 0.040 LU、最大 0.066 LU，在标准允差内
- 补偿采用**静态线性增益**（`目标响度 − 实测响度`）而不是动态归一化：保留原始动态范围，且结果是个恒定 dB，前端可以用 GainNode 实时套用、切歌零延迟
- **真峰值保护**：增益后真峰值不超过 -1 dBTP，避免抬升导致削波
- 缓存有效性 = 文件未变 && 算法版本未变 && **补偿标准未变**
- 回放链路：`<audio>` → `MediaElementSource` → `GainNode`（用户音量 × 响度补偿）→ 输出

> **响度均衡不修改任何源文件。** 补偿只在**播放时**由 GainNode 实时套用，
> 唯一的磁盘写入是缓存目录下的 `<cacheDir>/loudness/<songID>.json`（外加写入时的 `.tmp`）。
> `internal/loudness` 里没有一处写回歌曲文件的地方，所以「开过均衡之后源文件被改坏/被
> 归一化过」这件事不会发生；关掉均衡，听到的就和原始文件一模一样。
>
> 至于「前奏很响、后面变轻」：那不是均衡造成的，也不是文件被改过 ——
> 那是**源音频本身**的动态（原曲就是这样）。均衡用的是整首歌的**静态**增益，
> 动态范围一点没动（这正是刻意选的方案，见上一条）。想要「把响的地方压下来」
> 需要的是动态范围压缩（DRC），属于另一件事，目前没做。

> **音频必须与页面同源。** 实测（Windows 11 + WebView2 152）从
> `http://wails.localhost` 页面加载 `http://127.0.0.1:port` 的媒体会被
> Chromium 直接拒绝：`MEDIA_ELEMENT_ERROR: Media load rejected by URL safety check`，
> 请求连发都不会发出去。因此音频走 Wails 自己的 asset server：
> `http://wails.localhost/audio/<songID>?t=<token>`，
> 由 `main.go` 里的 asset middleware 转发到 `internal/media`。
> 同源后 CORS / `crossorigin` / Web Audio 跨源取数限制都不再是问题。

### 关于内置 ffmpeg 的体积

内置的是**自己编译的精简构建**：只包含本项目真正用到的组件，
单个二进制 6.0MB（对照：第三方通用静态构建 155MB）。
打包产物因此从 **167.6MB 降到 18.4MB**，许可证也从 GPLv3 变成 **LGPL-2.1-or-later**
（编译时没有 `--enable-gpl`/`--enable-nonfree`，而 FFmpeg 的 AAC 解码器与
`loudnorm` 滤镜本身都是 LGPL）。

在此基础上又做了一步纯体积优化：**嵌进 exe 的是 gzip 压缩后的 ffmpeg**
（`internal/ffmpeg/bin/ffmpeg.exe.gz`，由 `tools/build-ffmpeg.mjs` 编译完顺手生成）。
6.0MB → 2.2MB，产物再少约 3.8MB（实测 **16.2MB**）；而运行时的解压只在
「缓存目录里还没有这一份」时发生一次 —— 热启动连解压都不做，缓存文件名来自
压缩数据的摘要，「能否复用」用 gzip 尾部的解压后长度判断（见 `internal/ffmpeg`）。

能力清单是唯一事实来源，写在 `build/ffmpeg/features.env`：
`build-minimal.sh` 照它生成 configure 参数，`--info` 照它核对实际产物，
两边不会漂移。清单是这样的：

| 用途 | 编进去的组件                                                                                    |
| ---- | ----------------------------------------------------------------------------------------------- |
| 解码 | aac, alac, ac3, eac3, dca, mp3, flac, vorbis, opus, wmav1/2, wmapro, ape, dsd__, wavpack, pcm__ |
| 滤镜 | **loudnorm**（EBU R128 测量）、aresample、aformat、anull、volumedetect                          |
| 编码 | pcm_s16le、flac                                                                                 |
| 封装 | pcm_s16le/pcm_f32le（裸 PCM）、wav、flac、null                                                  |
| 协议 | file、pipe                                                                                      |

明确关掉：所有视频编解码器、所有硬件加速、网络、字幕、设备输入输出，
以及全部第三方外部库（x264/x265/libvpx/fdk-aac/opus…）。

重新编译：

```powershell
node tools/build-ffmpeg.mjs            # 已有产物则跳过
node tools/build-ffmpeg.mjs --force    # 强制重新编译
node tools/build-ffmpeg.mjs --download # 只下载解压源码
node tools/build-ffmpeg.mjs --info     # 体积 + 许可证 + 能力清单核对
```

**响度测量已经不再依赖 ffmpeg** —— 那部分改成了纯 Go 实现的 ITU-R BS.1770
（见下一节）。ffmpeg 现在只负责**解码**：

| 用途                               | 能否纯 Go         | 说明                                                                          |
| ---------------------------------- | ----------------- | ----------------------------------------------------------------------------- |
| 响度测量（LUFS / 真峰值）          | ✅ 已实现         | `internal/loudness/bs1770.go`                                                 |
| WAV / FLAC / MP3 / OGG / Opus 解码 | ✅ 有成熟纯 Go 库 | go-audio/wav、mewkiz/flac、hajimehoshi/go-mp3、jfreymuth/oggvorbis、pion/opus |
| **AAC / M4A 解码**                 | ❌ 没有纯 Go 实现 | 而本机曲库全是 .m4a                                                           |
| ape / wma / dsf 转码               | ❌                | 依赖 ffmpeg 的对应解码器                                                      |

所以要彻底去掉 ffmpeg，下一步得走 **Windows Media Foundation**
（系统自带 AAC 解码，COM 调用，不增加分发体积，但是 Windows 专有且实现量大）。

### 标题栏拖动（Wails v3 的写法）

v3 不再读 `-webkit-app-region`，而是读 CSS 自定义属性：

```css
.titlebar {
  --wails-draggable: drag;
}
.titlebar__btn {
  --wails-draggable: no-drag;
}
```

运行时判定是 `getComputedStyle(el).getPropertyValue("--wails-draggable").trim() === "drag"`，
所以按钮区域必须显式 `no-drag`，否则点击会变成拖窗口。

### 窗口原生材质（Mica / Acrylic）

设置 → 外观 → **窗口原生材质**，可选 `关闭 / 自动 / Mica / Acrylic / Tabbed`。
材质由系统 DWM 绘制在窗口背后，桌面壁纸会透过面板隐约可见，比纯 CSS 毛玻璃更"贴系统"。

实现要点（改这块之前先看 `backdrop.go` 的注释）：

- Wails v3 **只能在创建窗口时**通过结构体选项指定材质，运行期没有接口：
  `WebviewWindowOptions.BackgroundType = BackgroundTypeTranslucent` +
  `Windows.BackdropType = Mica/Acrylic/Tabbed`。两者缺一不可 —— 只设材质而窗口
  仍是不透明的，材质会被网页自己的底色挡得严严实实。
- 因此设置里的改动**需要重启应用**才生效：界面会说清"窗口当前生效的是什么"、
  "已保存的值是什么"，并给一个「立即重启应用」按钮（`WindowService.Restart`）。
- 判定标准与 Wails 内部一致（Build ≥ 22621）。更低的系统（Win10 / 早期 Win11）
  会退化成 `ACCENT_ENABLE_BLURBEHIND` 的一层背景模糊，仍然是半透明窗口。
- 窗口底色走令牌，不写死在组件里：`--bg-window`（tokens.css 里由主题的 `--bg-app` 派生）铺 `body` 与 `.playerview`；
  开启材质时 tokens.css 的 `:root[data-backdrop]` 把 `--bg-window` 换成 `--bg-window-material`（默认 `transparent`）。
  主题想在材质上留一层"面纱"，只覆盖 `--bg-window-material` 即可（例如 `rgba(8, 8, 10, 0.5)`），
  不需要在主题文件里写任何选择器 —— 组件 CSS（base/layout）里只有 `var(--token)`，没有颜色字面量。
- 页面侧由 `js/backdrop.js` 在启动时问后端"窗口真正生效的材质"，再给 `<html>` 写 `data-backdrop`。
  这样即使配置和窗口状态不一致（刚改完还没重启），界面也不会先变透明露出窗口底色。

> 注意 `WindowIsTranslucent` 是 Wails **Linux** 窗口的字段，Windows 上对应的是
> `BackgroundType: BackgroundTypeTranslucent`；`BackdropType` 也只挂在
> `WebviewWindowOptions.Windows`（`WindowsWindow`）下。

## 在线歌曲（搜索 / 封面 / 下载 / 试听）

搜索入口在**标题栏的搜索图标**（也可以按 `Ctrl+F`）：

1. 点搜索图标 → 弹出**搜索弹层**，光标自动落在弹层顶部的搜索框里；
2. 输入关键词按回车 → 结果就出现在同一个弹层里；
3. 结果层有两个标签：`在线歌曲`（默认）与 `本地曲库`；
4. 在线结果可以直接 **试听** 或 **下载**；本地结果点一下就地起播；
5. 搜索框右侧的 **清空按钮** 会同时清掉输入与结果；
   不点清空时结果**不会销毁**，关掉弹层再打开还是上次的结果（DOM 与已加载的封面都不重建）。

> 为什么搜索框在弹层里而不是标题栏：早期版本把它放在标题栏、结果放在另一个浮层，
> 两个东西分处两地，要先点图标再点输入框，还和窗口按钮抢位置。合成一个弹层之后，
> 「输入 → 回车 → 看结果」在同一个面板里完成。

### 试听只进播放列表

在线歌曲试听时**不会混进「本地歌曲」**：

- `state.songs` = 本地曲库（扫描到的本地文件），「本地歌曲」视图只显示它；
- 在线曲目登记在 `state.onlineSongs`（Map，不落盘，链接有时效），
  试听只把它的 id 追加到**播放队列**；
- 底栏、播放界面、队列面板通过 `store.songById()` 统一解析，
  所以在线曲目照样有封面、能拖进度、能切歌。

### 单击歌曲的行为

默认**单击 = 加入下一首播放**（不打断当前播放），双击始终是「立即播放这一首」。

可以在 设置 → 播放 → **单击歌曲时的行为** 里改成「立即播放」或「加入列表末尾」。
把它做成设置而不是写死，是因为这两种预期都很常见：一边是「我想排个队」，
另一边是「我只想听这首」。

### 封面

第三方接口地址、参数、可用性都会变，所以**所有联网封面逻辑单独成包**
（`internal/coverfetch`），上游只调 `Aggregator.Find`；某个源失效时只改一个文件。

| 来源                            | 说明                                                                                                                                        |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| iTunes Search                   | 无需鉴权、响应快。**坑：不要带 `country` 参数**，实测 `country=cn/us` 会让接口返回 0 条                                                     |
| 网易云                          | 华语覆盖最好。用公开的专辑搜索接口拿现成的 `picUrl`，**不逆向 picId 编码**（那套私有编码失效时只会静默 404，很难发现）                      |
| QQ 音乐                         | 华语覆盖好、接口稳定（实测 100~300ms）。由 `songmid`/`albummid` 拼封面地址，图床在 **`y.gtimg.cn`**（`.cn`，白名单与 Referer 都要单独放行） |
| Deezer                          | `cover_xl` 就是 1000×1000；实测大陆网络常整条超时，靠单来源超时 + 熔断兜住                                                                  |
| MusicBrainz + Cover Art Archive | 覆盖广、有稳定实体 ID；限流 1req/s，放在最后                                                                                                |

**「经常搜不到封面/歌词」的两个真正原因**（都实测过，不是网络玄学）：

1. **熔断没接到面板这条路径上**：`Aggregator.Find` 会上报来源成败，但换封面面板走的是
   `FindAll`（→ `ResolveAll`），而它既不上报、也不跳过熔断中的来源。于是一个整条超时的
   来源（Deezer 在大陆网络下连 TLS 都过不去）会在**每次**搜索里稳定吃掉一个单来源超时。
   现在两条路径共用同一套「跳过 + 上报」逻辑，死掉的来源 2 次之后会被跳过 5 分钟（半开自动恢复）。
   同时**「没命中」不再算失败** —— 早期实现里连续两首冷门歌就能把一个健康来源停用 5 分钟。
2. **查询与下载共用一个超时预算**：一次封面搜索分成「并发查各来源」与「把候选图下载回来体检」
   两段，早期共用一个 9s 预算。只要有来源吃满 6s 的单来源超时，留给下载的就只剩 3s，
   网络稍慢就整批候选超时 —— 用户看到的是「一张封面都搜不到」。现在两段各有预算
   （`DefaultTotalTimeout` 10s / `DefaultDownloadBudget` 14s），并且**第一张可用图到手后
   只再等 2.5s 就返回**，不再为了等一个慢图床让界面转十几秒。

另外两处「静默失败」也一并修掉了：

- **HTTP 200 不等于成功**：网易的搜索接口被限流时返回的是
  `{"code":405,"msg":"操作频繁，请稍候再试"}`。以前只看 HTTP 状态码，于是它被当成「没搜到」，
  既没有提示也不会熔断。现在业务状态码非 0/200 一律当失败（网易封面、网易歌词、QQ 音乐三处都查）。
- **只声明自己能解码的图片格式**：QQ 图床会按 `Accept` 协商，原来照抄浏览器的
  `image/avif,image/webp,…` 会让它回 **WebP**，而标准库没有 WebP 解码器 ——
  表现是「这个来源明明搜到了候选，却一张都显示不出来」。现在优先声明 jpeg/png/gif。

**改封面**有两个入口：播放详情页「返回」右侧的**封面按钮**，或任意歌曲的
「更多」菜单 → **更换封面…**。弹层里可以：

- **一次列出所有来源的候选**（`Cover.LookupAll`）：iTunes 的 `entity=song` 与
  `entity=album` 两路 + 网易云 + Deezer + MusicBrainz 的结果都会下载、校验后并排显示，
  缩略图下标出来源与尺寸，用户自己挑 —— 而不是被动接受某一家返回的第一张；
- **按别的关键词搜索**：下载下来的文件本来没有标签（标题是从文件名推的），
  直接搜基本不可能命中，这里可以手填歌曲名/歌手再搜；
- **选择本地图片**（`Cover.PickLocal`）：与「联网搜索」同一行，后端弹系统文件
  选择器读回图片并体检，然后和联网候选并排显示 —— 两者走完全相同的
  「勾选 → 应用」流程，不需要为本地图单开一条路径；
- **默认勾选策略**：联网搜索的结果默认**全不选**（一次列出十几张，替用户全选
  等于往封面集合里塞噪声），本地选的图默认**全选**（那是用户刚刚明确的决定）。

弹层标题是「封面管理」：它不只有搜索，还要管这首歌已经有的多张封面
（设为当前 / 删除 / 把文件内嵌封面收进缓存）。

几个关键设计：

- **空白占位图必须丢掉**：很多图床在「没有封面」时返回一张**纯白图**，
  尺寸和状态码都正常，前端渲染出来就是「封面总是白的」。
  `coverfetch.InspectImage` 解码后算均色与方差，**纯色且均色 ≥ 246**（约等于白）的直接丢弃
  （纯黑封面刻意保留），小于 64px 的也丢；候选全被丢掉时给一句明确提示，
  而不是把白图当成功结果。
- **元数据里的占位值要当成「没有」**：扫描时无标签文件会被填成 `未知歌手 / 未知专辑`，
  拿它去搜只会污染结果，`isPlaceholderMeta` 会先滤掉。
- **必须有封面代理**：页面 CSP 是 `img-src 'self' data:`，第三方图片直连会被浏览器拒绝；
  而且多数图床校验 Referer。所以封面统一走 `/online/cover?src=…`（同源），
  下载时还会按域名补一个 `Referer`（网易云 / B 站等不带就 403）。
- **MIME 按字节嗅探**：有些图床返回的 `Content-Type` 是错的或缺失
  （`image/jpg`、`application/octet-stream`…），`NormalizeMIME` 一律以文件头为准。
- **图床白名单**：`/online/cover` 是一个「把任意 URL 内容回给前端」的接口，
  不加限制就是 SSRF。`coverfetch.AllowedImageURL` 只放行各家公开图床域名，
  并额外挡掉 IP 字面量。
- **确认命中（`confirmMatch`）**：标题必须有实质重合才采用；标题强命中（相等/包含）时不再看歌手
  （「晴天」vs「晴天(女版)」是最常见的可用结果）。没有这道关，查一个不存在的歌名也会返回一张封面 ——
  错的封面比没有封面更糟。
- **查不到就不显示封面**：接口返回 `available=false`，前端渲染一个安静的图标，
  绝不留浏览器破图。
- **熔断**：某个来源连续失败 2 次后冷却 5 分钟（半开自动恢复），
  避免慢站点每次搜索都白等一个超时。失败只算「连不上/超时/接口报错」，
  「没查到这首歌」不累计 —— 否则冷门歌会把健康来源一起停掉。

### 在线歌词来源

歌词搜索/自动匹配由 `internal/lyricsfetch` 聚合，默认三个来源：

| 来源    | 说明                                                                                                                 |
| ------- | -------------------------------------------------------------------------------------------------------------------- |
| LRCLIB  | 国际化最好，且是唯一提供逐行时间轴的稳定来源。**先试精确接口 `/api/get`**（按歌手+曲名+专辑+时长对齐），再补全文搜索 |
| 网易云  | 华语覆盖最好；网页搜索接口会被限流（见上文的 `code:405`）                                                            |
| QQ 音乐 | 华语覆盖同样好、接口稳定。歌词里转义过的 `&apos;` / `&amp;` 会还原成正常字符                                         |

只有两个来源（且其中一个随时可能被限流）时，在线歌词实际上常常只剩 LRCLIB 一个可用，
中文新歌的覆盖就会很难看 —— 这就是「歌词搜索经常失败」的直接原因。

另外两处与成功/失败有关的行为：

- **「没搜到」不再等于「搜索失败」**：三个来源都正常但没有这首歌时后端返回**空列表**，
  界面显示「没有找到候选歌词」；只有真的全部失败（网络/限流）才把错误抛上来。
- **手动搜索会把 keyword 与 title/artist 一起传**：keyword 用于搜索，title/artist 用于**打分排序**。
  早期只传了 keyword，所有候选都落在同一个基础分上，翻唱/Live 版会排在原唱前面。
- 拿到「强命中」后只再等 1.5s 就返回，不再为一个卡住的来源白等一个 8s 超时；
  同分时按来源声明顺序（即优先级）排序，结果不会随网络快慢飘。

### 下载

- 默认保存到 **系统音乐目录 / downloads**（`%USERPROFILE%\Music\downloads`）；
- 设置 → 在线歌曲 → **下载保存位置** 可以改（目录选择器，或恢复默认），
  值存在 `config.json` 的 `downloadDir`；
- 下载在**后端**做（不是前端 `<a download>`）：只有后端知道真实路径、能反馈进度、能复用
  音频流解析；写入用 **临时文件 + 原子改名**，中途失败不会留下看起来正常的半成品；
- 同名文件自动加序号（`歌名 (2).m4a`），不会覆盖已有文件；
- 进度通过 `download:progress / done / failed` 事件推送，前端复用同一条 toast；
- **标题栏有一个下载入口，存在下载任务时才出现**，角标显示正在下载的数量；
  点开是「下载任务」面板：进度条 / 已完成（文件大小与文件名）/ 失败原因都留在面板里，
  还能清除已完成、打开下载目录、点某条已完成的任务在文件夹中定位。

**改下载位置时会问要不要迁移**：弹窗里告诉你旧目录有多少首歌、多大、目标目录已有多少，
可以选「迁移并更改」或「不迁移，只更改位置」。同名的不会被覆盖（跳过并统计），
单个文件失败不影响其他文件。迁移完成后会自动重扫，歌立刻出现在「本地歌曲」里。

### 下载目录就是扫描根

`Config.EffectiveFolders()` = 用户配置的文件夹 + 下载目录。
所以**下载完的歌直接出现在「本地歌曲」里，不需要用户手动添加文件夹**；
同时会判重：用户如果把 `Music` 整个目录加进来了，下载目录不会再重复添加。
下载目录不出现在设置的文件夹列表里（用户删不掉它），它的唯一真相来源是 `downloadDir`。

### 封面与歌词的缓存

封面与歌词默认都放在**缓存目录**里（设置 → 在线歌曲 → 缓存目录可以看到占用与位置，
也能单独打开 covers / lyrics 子目录）：

```
<cacheDir>/meta/covers/<songID>.jpg     封面原图
<cacheDir>/meta/covers/index.json       songID → {file, mime, source, at}
<cacheDir>/meta/lyrics/<songID>.lrc     歌词文本
<cacheDir>/meta/lyrics/index.json       songID → {file, source, at}
```

**缓存就是真相来源**，所以下面两件事必须做对（都踩过坑）：

- **重启后要把缓存回填到界面**：用户换过的封面存在缓存里，前端的 `coverOverrides`
  只是一张内存表。启动时调 `Cover.CachedPreviews` 把已有封面灌回去，否则「换过的封面
  重启后就没了」（除非开了写进文件）。歌词不用回填 —— 每次都是从后端 `Lyrics.Load` 读。
- **在线曲目的 id 不能直接当文件名**：试听曲目的 id 形如 `bili:BV1xx411c7mD`，
  冒号在 Windows 上是**非法文件名字符**，直接落盘会报
  `rename … The parameter is incorrect`，于是「试听时匹配到的歌词/封面」永远存不下来。
  `metacache.safeFileID` 把非法字符转义成 `_xxxx` 并在改动过时追加短哈希，
  本地 id（本来就是十六进制串）保持原文件名不变。

设置里可以开启**「把封面/歌词写进歌曲文件」**（默认关闭）：

- 默认关闭是刻意的 —— 这会在用户的音乐文件上做修改，必须是明确选择；
- 开启后换封面/下载时会**同时**写进文件标签，这样把文件拷到别的播放器上也能看到封面与歌词；
- **打开这个开关时，如果缓存里已经存着封面/歌词，会弹一个确认框问「要不要把已有的缓存
  一并写进歌曲文件」**（缓存里没东西就不打扰，只提示一句）。同一件事旁边还有一个常驻的
  「写入缓存到文件」按钮，之后想补写随时可以点。真正动文件之前一定会确认一次。
  后端入口是 `CoverService.WriteCacheToFiles`，返回写入 / 跳过 / 失败的明细
  （跳过的原因会列出来给用户看，多半是「这个格式不支持写标签」）。
- 实现见 `internal/metacache/embed.go`：m4a 是**在原有 moov 里长出一个 `covr`
  与 `©lyr`**（不动 mdat、不动任何 chunk 偏移，写盘用临时文件 + 原子改名），
  FLAC 是重写 metadata 区块插入 `PICTURE`，并把 `LYRICS` 合并进 VORBIS_COMMENT
  （小端长度，原有 TITLE / ARTIST 等注释原样保留）。mp3 / wav 等格式明确返回
  「暂不支持」而不是冒险写坏文件（内置的精简 ffmpeg 只编进了 wav/flac/null
  三个封装器，做不到通用 remux）。
- 一次操作就要把封面与歌词一起写：分成两次写会把整个文件读两遍、moov 重建两遍，
  而且封面会被覆盖两次。所以对外只有 `EmbedMeta(path, mime, cover, lyrics)` 一个入口，
  `EmbedCover` / `EmbedLyrics` 都是它的薄封装。

## 只预览界面（不需要编译 Go）

```powershell
npm run dev                 # 推荐：Vite（HMR + 依赖解析），默认 http://127.0.0.1:5173/
# 或用零构建的静态服务器（第三方包如 SortableJS 会被映射到 /vendor/*，因此仍需一次 npm install）
node tools/dev-server.js 5173
```

预览用假数据渲染，改 CSS / JS 后刷新页面即可（Vite 下会自动热更新）。两种服务器
同时也提供 `/bindings/*`（生成的前端绑定）与 `/wails/runtime.js` 桩，
因此 `bridge.js` 的降级逻辑和打包后完全一致。

静态那套（`tools/dev-server.js`）会自己把源码改写成「浏览器原生 ESM 能直接跑」的样子：
把 `import "@musicplayer/player-skins"` 这种工作区包名换成同源路径，
把 `import "sortablejs"` 这种第三方裸包名换成 `/vendor/*`（固定白名单，指向 `node_modules`），
（裸说明符浏览器不认识，而 import map 是**内联脚本**，会被页面 CSP `script-src 'self'` 拦掉），
并把包里的 `import "./x.css"` 摘掉改用 `<link>`（浏览器原生 ESM 不能 import CSS）。
所以**跑自检脚本请用它**：`ui-interact.mjs` 之类会在页面里
`import("./js/store.js")` 读状态，Vite 会给模块 URL 加查询串，动态 import 会拿到
**另一个空实例**（断言全部读到 `songs=0`，看着像功能坏了）。脚本已加环境自检：
真发生会直接报「store 不是同一个实例」并以退出码 2 结束。

### 用 URL 参数定格任意界面状态

| 参数              | 作用                       | 示例                                             |
| ----------------- | -------------------------- | ------------------------------------------------ |

## 设计约束（改代码时请遵守）

1. **HTML 里不写样式**：不加 `style="…"`、不加 `<style>` 内容；类名走 `styles/components/`。
2. **组件 CSS 不写颜色字面量**：一律 `var(--token)`，颜色只在 `tokens.css` 与 `themes/*.css` 出现。
3. **主题文件只声明令牌**：写选择器/组件样式会破坏「布局固定」这一需求。
4. **布局关键尺寸全部令牌化**：`--h-titlebar` / `--w-sidebar` / `--h-playerbar` / `--h-header` / `--row-h`。
5. **动态样式用 CSSOM**：运行时改主题相关变量请用 `runtime-tokens.js` 的 `setRuntimeToken()`，不要直接写 `element.style.setProperty("--x", …)`（会被 CSP 判为内联样式）。
6. **`StableID` 两端必须一致**：Go 的 `bootstrap.StableID` 与前端 `utils.js#stableId` 有测试逐条比对，改成不一致会让歌单/收藏/队列在重扫后集体失效。
7. **依赖第三方网络接口的东西单独成包**：`internal/bilibili` / `internal/lyricsfetch` / `internal/coverfetch`
   各自独立，上游只依赖聚合器的方法。这些接口随时会变，隔离之后失效范围只有一个文件。
8. **前端发往 `Config.Set` 的键必须同时加进 Go 的 `applyPatch`**：漏一个键不会报错，
   只会静默丢弃（「改了设置重启就没了」就是这么来的）。
   `internal/bootstrap/config.go` 的字段 + `services.go` 的 `applyPatch` + `store.js` 的
   `SYNCED_KEYS` 三处必须同步；`config_service_test.go` 会跨进程读盘验证。
9. **搜索分两处，别混在一起**：① 在线搜索在弹层里（`searchpanel.js`），弹层独立于内容区，
   输入框不会被重绘；② 本地曲库筛选是内容区头部下方的独立筛选条（`#content-filter`，
   在 `index.html` 里静态存在，`shell.js#syncFilterBar` 只改计数与清空按钮的可见性）。
   **不要**把输入框放进内容区工具条 —— 工具条是整块 `innerHTML` 重绘的，
   输入框长在那里就会「每输入一个字符被重建一次」。
10. **写用户文件的代码（`internal/metacache/embed.go`）必须遵守两条**：
    ① 只在原结构里做**最小插入**（例如往 moov 里加一个 `covr`），不改动音频数据、
    不改动任何偏移；② 写盘走「临时文件 + 原子改名」，中途失败不能留下半成品。
    不支持的格式要**明确返回不支持**，不要赌一把写坏用户的东西。
11. **不要靠读配置来决定一次性的动作**：配置是前端防抖（400ms）同步过来的，
    「刚改完设置立刻做某件事」时后端很可能还没收到新值（换封面写文件就踩过这个坑）。
    这类选择由调用方**显式传参**（见 `CoverService.ApplyWith`）。
12. **给 `[hidden]` 元素写样式时，别让 `display` 把它复活**：
    `[hidden]` 的默认 `display: none` 只是**元素选择器级别**的默认样式，
    组件里任何一句 `display: flex/grid/…` 都会把它盖掉 —— 元素虽然 hidden，
    却仍然占位、仍然接收指针事件。我们的搜索/设置/封面三个弹层就因此透明地
    铺满整窗、吃掉所有点击（界面表现是「点任何按钮都没反应」，而且完全看不出原因）。
    `utilities.css` 里已加一道 `[hidden] { display: none !important }` 兜底，
    但**改动弹层样式后请务必跑 `tools/hitcheck.mjs` 或 `ui-round2.mjs`**：
    它们会用 `Input.dispatchMouseEvent` 做真实的命中测试，
    而 `element.click()` / `dispatchEvent` 是直接投递给目标元素的、**绕过了命中测试**，
    这类 bug 在旧写法下能一路绿灯溜过去。
13. **弹窗（`.modal-backdrop`）的层级必须用 `--z-modal-top`，不能和设置层同为 `--z-modal`**：
    设置层 / 封面层 / 搜索层虽然也是 `fixed`，但它们是 `.app`（`z-index: 10`，自成
    层叠上下文）的孩子，而弹窗是 `body` 的孩子；两者数值相同时**设置层会盖在弹窗上面** ——
    弹窗看得见、按钮却点不动（真实鼠标命中测试才会暴露这个问题，`element.click()` 测不出来）。
    改层级相关样式后跑 `tools/probe-live-settings.mjs`，它会真实点一遍设置里的确认框。
14. **设置层里的分组状态要存在渲染之外**：设置内容是一整块 `innerHTML` 重绘的，
    任何「当前选中的分区」这类状态若只写在渲染结果里，重绘后就会回到默认值
    （表现是「点设置里任何按钮，导航栏的选中项都跳回第一个」）。
    现在由 `settings.js#activeSection` 持有，重绘时再写回。
15. **界面上的按钮写在 `index.html` 里，不要在运行时 inject**：底栏「歌词」
    按钮曾经是 `online.js` 在自己模块顶层 `document.createElement` 插进去的 ——
    结果那个模块没被任何地方 import，按钮就**静默消失**了，而且从 HTML 里
    完全看不出少了什么。现在按钮是静态标签，`lyrics-panel.js` 只做绑定，并在
    `main.js` 里显式 `import "./lyrics-panel.js";`（带注释说明为什么要留着这行）。
    `tools/check-playerbar-tools.mjs` 会盯着这一类「按钮被谁悄悄删掉/加回来」的回归。
16. **「当前播放 / 选中 / 当前封面」各自只能有一个真源**：
    - 选中行 = `state.currentId`（列表只把它画出来，见 `tracks.js` 与 `main.js#paintTrackSelection`）；
    - 当前封面 = `store.coverSets` 里的 `active`（列表、底栏、详情页、写回文件都读它）；
    - 轮播开关 = 全局 `config.coverCarousel`（**不是**每首歌的属性，否则会出现「这首开那首关」两份真相）。
      新增任何"当前是哪个"的界面元素时，先想清楚它的真源在哪，不要在 DOM 里再存一份。
17. **样式包不要 import 应用内部模块**：`frontend/packages/player-skins` 里只允许依赖
    `contract.js` 暴露的 `ctx`（数据靠宿主推、动作走 `ctx.actions`）。
    第三方样式是运行时从 `/skins/` import 的，一旦它们依赖 `store.js` 之类的东西，
    接口就没法演进，第三方也会随内部重构一起碎掉。
18. **第三方样式必须自己限定 CSS 作用域**（`.playerview[data-skin="<id>"]` 开头）：
    所有样式共用一张样式表，不限定就会改到别人的界面。示例见
    `internal/skins/template/skin.css`。
