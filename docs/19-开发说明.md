# 本地音乐播放器

本地音乐播放器 · **Go + Wails3** · 前端是 **Lit 3**（自定义元素 + light DOM，只负责模板与增量 diff）

- 原生 ESM + Vite + npm workspaces + ESLint + tsc 类型检查 + 单测

当前状态：**界面 + 后端都已实现，可编译运行**。

- 界面：浏览器里就能预览与评审（不需要 Go）
- 后端：扫描 / 文件夹监听 / 过滤 / 元数据 / 封面 / 歌词 / 音频播放 / 配置落盘，见 `docs/04-后端实现说明.md`
- 播放界面样式：契约与运行时零件在包 `frontend/packages/player-skins/`；
  **内置样式本身是数据**（`internal/skins/resources/player-skins/`，只读资源目录），
  与第三方样式同构、走同一条加载路径 —— 见 `docs/42-播放器样式插件系统设计方案.md`（契约 v3）

## 前端工程化

前端已迁移到 **Lit 3**（渲染全部由 Lit 模板完成，`main.js` 的每帧 paint 主循环已删除），
界面代码仍是可直接阅读的原生 ESM，工程设施如下：

```powershell
npm install            # 只做一次：安装 Vite / ESLint / Prettier / TypeScript
npm run dev            # Vite 开发服务器（HMR），等价于 wails3 task dev:frontend
npm run build          # 构建到 frontend/dist（= node tools/build-frontend.mjs）
npm run lint           # ESLint（含 no-unused-vars / prefer-const / eqeqeq…）
npm run format:check   # Prettier 检查（npm run format 直接改）—— ★ 代码与配置全量纳入；
                       #    Markdown 正文按 .prettierignore 里的实测理由排除（见 §设计约束）
npm run typecheck      # tsc 类型检查（JSDoc + checkJs，逐个文件收紧，见 tsconfig.json）
npm test               # node:test 单测（皮肤包的 LRC 解析 / 契约 / 注册表）
npm run check          # format:check + lint + typecheck + test，提交前跑这个（CI 同一套）
npm run check:plugins  # 校验 plugins/*/index.json 与磁盘一致（CI 也会跑）

npm run dev:static     # 静态预览（等价于 tools/dev-server.js；第三方包走 node_modules 的 /vendor 映射）
```

同一套流程也挂在 Taskfile 上（`build` 会自动跑 Vite 构建，缺 `node_modules` 时先 `npm install`）：

```powershell
wails3 task build               # = frontend:deps → generate:bindings → ffmpeg:build → build:frontend → go build
wails3 task frontend            # 只重新构建 frontend/dist
wails3 task check               # = npm run check（prettier --check + ESLint + tsc + 单测）
wails3 task dev:frontend        # Vite 预览（HMR）
wails3 task dev:frontend:static # 静态预览（自检脚本请用这个）
```

> 构建入口 `wails3 task build` 的退出码是有意义的：它现在返回 0。
> 之前本机 PowerShell 配置里的 `Set-PSReadLineOption` 在输出被重定向时会报错，
> 让最后的清理步骤（`powershell Remove-item *.syso`）把整个构建的退出码带成 1 ——
> 明明 exe 已经生成好了。现在那一步用 `powershell -NoProfile` 跑。

目录结构：npm workspaces 根包 + 两个工作区
（`frontend` = 应用壳，`frontend/packages/player-skins` = 播放界面样式包）。

几个刻意的取舍，避免以后被"工程化"反咬：

- **源码还是原生 JS**：打包器只负责依赖解析与产物哈希，不引入 JSX/TS。
  需要类型的地方用 JSDoc（`tsc --checkJs` 能吃到），保持「打开文件就能读」。
- **类型检查是"逐个文件收紧"**：`checkJs: false` 时 tsc 仍然会做**全量语法检查**，
  只有文件顶部写了 `// @ts-check` 才会做类型检查。新代码（皮肤包、playerhost）都带这个标记，
  历史文件等有空再补 —— 一个永远红着的检查等于没有检查。
- **Prettier 只跳过两处**（见 `.prettierignore` 里的说明）：`frontend/src/styles/` 里很多数值是量出来的，
  而 `frontend/src/*.html` 里行内元素的空格有语义。其余前端源码（含 `frontend/src/js/`）**都在格式化范围内**。
- **Vite 只负责 `frontend/src` 与工作区包**：Wails 生成的 `frontend/bindings` 是**运行时**
  按 URL import 的（`bridge.js` 里用变量说明符 + `@vite-ignore`），因此不参与打包，
  由 `tools/build-frontend.mjs` 原样拷进 `frontend/dist/bindings`。

## 运行应用

```powershell
# 首次构建前先编译内置 ffmpeg（精简版约 6MB，只需一次，约 6~10 分钟）
# 需要 MinGW-w64（gcc/nasm/mingw32-make）+ 一个 bash（Git for Windows 自带）
node tools/build-ffmpeg.mjs

# 构建（会同步前端产物 + 生成绑定 + 编译，带上内置 ffmpeg 约 18MB）
wails3 task build
.\bin\lmplayer.exe

# 跑后端测试
# ★ 不要写 `go test ./...`：那会把 node_modules/flatted 自带的 Go 源码也算成一个包。
wails3 task test        # = go test . ./internal/... ./tools/...

# 漏洞扫描（与 CI 同一命令；有命中时退出码 3）
go run golang.org/x/vuln/cmd/govulncheck@latest . ./internal/... ./tools/...

# 「跳过数 > 0 即失败」门禁（与 CI 同一步）：跑一遍后端测试，把每条 t.Skip
# 连同原因列出来；没在 tools/skipped-tests-allowlist.json 里登记的跳过会让它失败。
# 为什么要它：容器里没有声卡，PlayerService 的编排用例会被整批静默跳过 ——
# go test -race 只保证「跑了的都过」，这个门禁负责「没跑的有账」。
node tools/check-skipped-tests.mjs          # 或 npm run check:skipped
node tools/check-skipped-tests.mjs --list   # 只列出当前会跳过的用例

# 看看内置 ffmpeg 的体积/许可证/实际编进去的能力
node tools/build-ffmpeg.mjs --info

# 打包 Windows 安装程序（需要本机安装 NSIS）
wails3 task package
```

首次运行会在 `%APPDATA%\LocalMusicPlayer\` 生成 `config.json` 与 `themes\`（内置主题会同步过去）。
添加音乐文件夹后，扫描与监听都会自动生效。

**ffmpeg 是内置的**：首次启动会把编译进 exe 的 ffmpeg 解包到
`%LOCALAPPDATA%\LocalMusicPlayer\bin\`（约 6.0MB，按内容哈希命名，只解包一次）。
因此用户机器上不需要预装 ffmpeg；`ape/wma/dsf` 等格式能直接播放。
如果本机已装了 ffmpeg 也可以指定：

```powershell
$env:LMPLAYER_FFMPEG = "D:\ffmpeg\bin\ffmpeg.exe"   # 优先使用它
$env:LMPLAYER_FFMPEG_DIR = "D:\mp-bin"              # 改内置版本的解包位置
```

> 内置的是**自编译的精简 LGPL 构建**（没有 `--enable-gpl` / `--enable-nonfree`），
> 许可证结论与编译选项随二进制放在
> `internal/ffmpeg/bin/FFMPEG-LICENSE.txt`，再分发时请一并保留。
> （本节下方「关于内置 ffmpeg 的体积」有完整的体积与许可证说明。）

## 窗口行为：单实例 / 托盘 / 图标 / 首屏

- **单实例**：第二次双击图标不会再开一个进程，而是把已经在跑的那个窗口显示出来并抢焦点
  （Wails 的 `SingleInstanceOptions`，UniqueID = `com.localmusicplayer.app`；第二个进程通知完
  自己立刻退出）。
- **关闭到托盘**：设置 → 外观 →「关闭时最小化到托盘」（**首次启动默认开启**）。打开后点关闭
  按钮只把窗口收进系统
  托盘（左键直接显示、右键菜单有「显示主界面 / 退出」），音乐继续播放；关掉这个开关，
  点关闭就是真正退出。
  托盘图标只在开关打开时创建（`WindowService.ensureTray`）；拦截关闭用的是主窗口
  `WindowClosing` 的 **Hook + Cancel**（钩子比监听器先跑，否则 Wails 内建的
  「关闭 = 销毁窗口」已经执行了）。
- **应用图标**：`build/appicon.png`（参考 `音乐.svg` 的粉底白色音符）→
  `wails3 task generate:icons` 生成 `build/windows/icon.ico` 与 `build/darwin/icon.icns`，
  构建时由 `generate:syso` 把 ico 打进 exe；系统托盘直接 embed 同一个 PNG。
  ★ **底板必须是正方形**：最初那版 1024×1024 图里，粉色圆角底板是 810×724
  （宽高比 1.119），在任务栏 / 托盘 / Alt-Tab 里就是一个「高度被压瘪的长方形」。
  修法是**整张图横向收窄 724/810、纵向不动再水平居中**（底板 723×724，四周留白 150px），
  字形与底板的比例关系不变、只是不再被横向拉长。改完跑 `wails3 task common:generate:icons`
  重生成 ico/icns，并确认每个尺寸的底板宽高比都是 1.0（16/32/48/64/128/256）。
- **首屏不白闪、也不黑闪**：分三层解决，缺一层就会看到「白一下 / 黑一下 / 空一下」。
  1. 主窗口 `Hidden: true` 创建 —— 不隐藏时 Wails 会用带 `WS_VISIBLE` 的样式创建窗口，
     WebView2 在页面渲染出第一帧前会先亮一块白底（首屏那一下白闪）。
  2. 应用一跑起来就给它打上 DWM 的隐身标记（`DWMWA_CLOAK`），**先显示出来、但遮住**：
     `WS_VISIBLE` 让 WebView2 正常合成出帧、rAF 正常派发，而用户什么都看不见；
     前端把首帧画好后再摘掉遮罩，于是窗口「出现」的那一帧已经是画好的帧
     （见 `window_reveal_windows.go` 与 `services.go#showPrepared`）。
     ★ 这里有个坑：**窗口真隐藏时不能用 `requestAnimationFrame` 等首帧** ——
     WebView2 不派发 BeginFrame，rAF 永远不执行，而 `document.visibilityState`
     仍是 `visible`，从 JS 侧完全看不出来。遮罩方案正是为了让这个前提不成立。
  3. 露面时看到的画面是**上次退出时缓存的上一帧**：退出时用 `PrintWindow`
     （`PW_RENDERFULLCONTENT`）抓一张 JPEG 写进缓存目录，启动时由 `/boot-frame.jpg`
     提供给 `index.html#boot-splash`，真正的界面装配好再淡出 —— 观感就是「窗口一
     出现就是刚才那个界面」（见 `boot_frame.go` / `js/main.js`）。
     首次启动、抓帧失败或非 Windows 时，同一层就是加载动画那一形态（缓存图加载
     失败时浏览器会画一个「碎图标」，所以它默认 `opacity: 0`，只有确认加载出来了才
     打上 `data-hasframe` 露出来 —— 见 `index.html#boot-splash-style`）。
  4. 遮罩期间窗口虽然已经 `WS_VISIBLE`，但会先被摘掉任务栏按钮
     （`WS_EX_TOOLWINDOW`，露面时换回 `WS_EX_APPWINDOW`）—— 否则任务栏图标会比
     窗口早出现几百毫秒，看着就像「点了半天没反应」。
  5. 「首帧画好了」这句信号走的是**普通 HTTP 请求**（`/boot/reveal`），不是 Wails 的
     JS→Go 绑定：启动阶段宿主主线程正忙着初始化 WebView2，绑定消息实测会被压后近一秒
     （窗口就白等这么久）；HTTP 走网络栈，几十毫秒内到。前端在模块的第一句可执行代码里
     就把它发出去，所以窗口露面几乎与首帧同时发生。
     兜底仍在：Go 侧 1.5s / 4s 各补一次 `MarkReady`，前端另有 12s（撤下过渡层）的定时器；
     `MarkReady` 只在「还没真正显示过」时动手，重复调用不会抢焦点。
     实测冷启动：窗口（连带任务栏图标）约 1.0~1.2s 出现，露的就是缓存的那一帧。
- **托盘唤起 / 第二次启动**：窗口会显式刷一次 z 序并抢前台（`raiseNativeWindow`），
  而不是只依赖 Wails 的 `Focus()`（它内部只有一句 `SetForegroundWindow`，对「不是当前
  前台进程」的调用会被系统拒绝，表现就是窗口出来了却还压在其他窗口下面）。
- **主窗口圆角**：设置 → 外观 →「窗口圆角」（跟随系统 / 标准 / 小圆角 / 直角）。
  圆角与 Aero 阴影都来自 DWM（`DwmExtendFrameIntoClientArea` +
  `DWMWA_WINDOW_CORNER_PREFERENCE`，只有这几档、没有任意半径）。原来它只在
  `WM_ACTIVATE` 里设置，而遮罩方案下这次激活可能被跳过（表现就是窗口没阴影、没圆角），
  所以现在每次露面都会显式重设一次；圆角改完立刻生效，不需要重启。

## 响度均衡（音量一致化）

不同来源的音乐响度差得很远。实测你的曲库（53 首 m4a）：

```
实测响度范围: -23.25 ~ -8.51 LUFS  →  相差 14.74 LU
补偿增益范围: +4.67 dB ~ -7.49 dB
```

也就是说切歌时音量可能突然跳 15 dB。开启响度均衡后，每首歌会被补偿到同一个
目标响度（默认 **-16 LUFS**），切换歌曲音量保持稳定。

- 在 **设置 → 响度均衡** 里选择模式：`关闭` / `逐曲均衡` / `同专辑统一`
- **不需要预先扫描**：播到哪首就算哪首，算好的补偿会缓存下来，之后播放零延迟
- 改了 **目标响度** 后**不需要重算**：测量结果与挡位无关，换挡位只是按新目标
  重新做一次减法（见下面「测量与挡位是两件事」）
- 「预先把全部歌曲算好」只是可选的批量预热，正常使用不需要点

实现要点：

- 整合响度与真峰值由**纯 Go 实现**的 ITU-R BS.1770-4 / EBU R128 计算
  （K 加权 + 400ms 门限块 + 真峰值 4 倍过采样），与 ffmpeg 的 `loudnorm`
  在真实曲库上平均偏差 0.040 LU、最大 0.066 LU，在标准允差内
- 补偿采用**静态线性增益**（`目标响度 − 实测响度`）而不是动态归一化：保留原始动态范围，且结果是个恒定 dB，后端可以实时套用、切歌零延迟
- **真峰值保护**：增益后真峰值不超过 -1 dBTP，避免抬升导致削波
- 缓存有效性 = 文件未变 && 算法版本未变（**目标响度不在其中**）
- 回放链路（**已迁到 Go 后端**）：`services_player.go` → `internal/audioplay`（环形缓冲 + malgo/WASAPI）→ 声卡；
  增益在音频回调里逐样本插值套用（用户音量 × 响度补偿）

### 测量与挡位是两件事（2024 重构）

整合响度(LUFS) / 真峰值(dBTP) / LRA / 相对门限是**音频文件本身的固有属性**，
与用户选哪个目标响度毫无关系；补偿增益才是挡位相关的。所以：

```
一首歌无论用户在几个挡位之间怎么切，都只测量一次
每多用一个挡位，只多出一条几个字节的增益记录
```

缓存因此分两张表（磁盘格式 version 2）：

| 表 | key | 内容 | 失效条件 |
| :--- | :--- | :--- | :--- |
| `entries` | 路径+大小+修改时间 | 固有量（LUFS / dBTP / LRA / 门限） | 文件变了、算法版本变了 |
| `gains` | songID → 挡位 → `{target, db}` | 各挡位的补偿增益 | 测量记录失效、算法升版 |

一万首歌 × 四个挡位 = 四万条增益，序列化后约 1MB —— 所以不做淘汰，
只保证**同一挡位绝不重复测量第二遍**。

> 早期实现把 `target` 当作**测量记录**的有效性条件，换挡位时旧记录整条作废，
> 还被 `InvalidateTarget` 直接删掉。用户侧的体验就是「从较响改回默认时，
> 以前在较响算好的补偿丢了」。现在 `InvalidateTarget` 保留签名但**什么都不删**
> （返回 `dropped=0`），旧格式缓存会在首次加载时自动迁移
> （见 `internal/loudness/cache.go#migrateLegacyLocked`），升级不丢数据。

### 测量的两条路径

```
主路径（零额外成本）  media.Server 转码 → ffmpeg.TranscodeToWAVWithScan
                      → 同一份 PCM 喂给 ffmpeg.LoudnessScanner
                      → LoudnessService.StoreMeasurement → 落盘

兜底路径（按需）      LoudnessService.Measure → 播放优先队列
                      → ffmpeg ebur128 分析（不产生输出，只扫描）
```

**主路径**是提速的关键：后端播放本来就要把整首歌转成 PCM WAV，
那份 PCM 是整首歌唯一一次完整流过我们代码的机会 —— 响度测量挂在它上面，
就不必再起一个 ffmpeg 把同一个文件解码第二遍。实测（240 秒曲目）：

| 步骤 | 耗时 |
| :--- | :--- |
| 改造前：`ffmpeg loudnorm` 单独测量 | 6,750 ms |
| 改造后：`ffmpeg ebur128` 兜底测量 | 977 ms |
| 转码成 PCM（起播本来就做） | 193 ms |
| **顺手扫描（额外成本）** | **549 ms** |

即每首歌从「额外 6.7 秒」降到「额外 0.5 秒」，省掉约 92%。

### 资源占用

测量是**后台**工作，跑起来时用户往往正在听歌。实测（8 核 16 线程）同时跑
8 个 ffmpeg 时，单进程分析速度从 21.7x 实时掉到 4.1x —— 多开的进程没换来
成比例的吞吐，只是把 CPU 铺满、风扇狂转，顺带拖慢前台播放的音效链。
所以并发上限刻意压到 **2**（`MaxConcurrency = 4` 只是硬上限）：

```
internal/loudness/manager.go
  DefaultConcurrency = 2
  MaxConcurrency     = 4
```

调度走**播放优先队列**：正在播的那首歌永远排在最前（插到队首），
后台批量预热每提交下一首之前检查 `YieldIfPending`，有人在排队就让出槽位。
所以即使用户在预热进行到一半时切歌，那首歌也只需要等**当前这一首**测完。

> **音频为什么在后端出声。** 早期版本用前端 `<audio>` 播放：解码与输出跑在
> WebView2 的渲染进程里，网页一卡（主线程被布局/绘制占满、GPU 进程抖动）
> 音频线程就拿不到时间片，听感上是**卡顿 / 沙哑**；而且声音从 WebView2
> 进程发出，Windows 音量合成器里显示的是 `webview2` 而不是本程序。
> 现在音频由 Go 侧的独立线程驱动（见 `internal/audioplay`），
> 网页再卡也不影响出声，合成器里也是本程序。
>
> 与此配套的两处变化：
>
> - **进度用「锚点 + 前端外推」**：后端每 500ms 推一次
>   `{positionMs, atMs}`，前端按 `performance.now()` 自己外推显示位置。
>   若改成「后端每帧推位置、前端照单全收」，WebView2 一卡就会在队列里积压，
>   恢复后进度会跳变 —— 那等于把「音频卡顿」换成「界面卡顿」。
> - **频谱由后端算**：`internal/audioplay/spectrum.go` 逐语义复刻了原来
>   AnalyserNode 的算法（同样的对数分桶指数 1.7、同样的字节域平滑），
>   皮肤观感与迁移前一致。（后来契约修订：皮肤改为**拉取式** `ctx.spectrum()`
>   取固定 128 段全谱，读到才采样 —— 见 `docs/42` §D 定案 4 与 `spectrum.js`。）
>
> **样式契约是 v3**（`SKIN_API_VERSION = "3.0"`）：`ctx.audio` 早已移除（后端播放时
> 前端没有 `<audio>` 可给）；元数据以清单 `skin.json` 为准，插件零 import，
> 公共零件走 `ctx.sdk`；配色由清单 `colors` 声明、宿主派生并兜底对比度；
> 插件 CSS 被宿主强制包进 `@layer skin` + `@scope`。详见 `docs/42` 与
> `frontend/packages/player-skins/README.md`。


> **响度均衡不修改任何源文件。** 补偿只在**播放时**由 Go 音频回调逐样本插值套用
> （用户音量 × 响度补偿，见 `internal/audioplay`；legacy `<audio>` 回退路径上才是 GainNode），
> 唯一的磁盘写入是缓存目录下的 `<cacheDir>/loudness/<songID>.json`（外加写入时的 `.tmp`）。
> `internal/loudness` 里没有一处写回歌曲文件的地方，所以「开过均衡之后源文件被改坏/被
> 归一化过」这件事不会发生；关掉均衡，听到的就和原始文件一模一样。
>
> 至于「前奏很响、后面变轻」：那不是均衡造成的，也不是文件被改过 ——
> 那是**源音频本身**的动态（原曲就是这样）。均衡用的是整首歌的**静态**增益，
> 动态范围一点没动（这正是刻意选的方案，见上一条）。想要「把响的地方压下来」
> 需要的是动态范围压缩（DRC），属于另一件事，目前没做。

> **音频必须与页面同源。** 实测（Windows 11 + WebView2 152）从
> `http://wails.localhost` 页面加载 `http://127.0.0.1:port` 的媒体会被
> Chromium 直接拒绝：`MEDIA_ELEMENT_ERROR: Media load rejected by URL safety check`，
> 请求连发都不会发出去。因此音频走 Wails 自己的 asset server：
> `http://wails.localhost/audio/<songID>?t=<token>`，
> 由 `main.go` 里的 asset middleware 转发到 `internal/media`。
> 所以音频、皮肤、封面代理**都必须**走 Wails 的 asset server 同源路由 ——
> 「独立端口 + 跨源」那套实验已经作废，不要再照着它写代码。

### 关于内置 ffmpeg 的体积

内置的是**自己编译的精简构建**：只包含本项目真正用到的组件，
单个二进制 6.0MB（对照：第三方通用静态构建 155MB）。
打包产物因此从 **167.6MB 降到 18.4MB**，许可证也从 GPLv3 变成 **LGPL-2.1-or-later**
（编译时没有 `--enable-gpl`/`--enable-nonfree`，而 FFmpeg 的 AAC 解码器与
`loudnorm` 滤镜本身都是 LGPL）。

在此基础上又做了一步纯体积优化：**嵌进 exe 的是 gzip 压缩后的 ffmpeg**
（`internal/ffmpeg/bin/ffmpeg.exe.gz`，由 `tools/build-ffmpeg.mjs` 编译完顺手生成）。
6.0MB → 2.2MB，产物再少约 3.8MB（实测 **16.2MB**）；而运行时的解压只在
「缓存目录里还没有这一份」时发生一次 —— 热启动连解压都不做，缓存文件名来自
压缩数据的摘要，「能否复用」用 gzip 尾部的解压后长度判断（见 `internal/ffmpeg`）。

能力清单是唯一事实来源，写在 `build/ffmpeg/features.env`：
`build-minimal.sh` 照它生成 configure 参数，`--info` 照它核对实际产物，
两边不会漂移。清单是这样的：

| 用途 | 编进去的组件 |
| :--- | :--- |
| 解码 | aac, alac, ac3, eac3, dca, mp3, flac, vorbis, opus, wmav1/2, wmapro, ape, dsd__, wavpack, pcm__ |
| 滤镜 | **loudnorm**（EBU R128 测量）、aresample、aformat、anull、volumedetect |
| 编码 | pcm_s16le、flac |
| 封装 | pcm_s16le/pcm_f32le（裸 PCM）、wav、flac、null |
| 协议 | file、pipe |

明确关掉：所有视频编解码器、所有硬件加速、网络、字幕、设备输入输出，
以及全部第三方外部库（x264/x265/libvpx/fdk-aac/opus…）。

重新编译：

```powershell
node tools/build-ffmpeg.mjs            # 已有产物则跳过
node tools/build-ffmpeg.mjs --force    # 强制重新编译
node tools/build-ffmpeg.mjs --download # 只下载解压源码
node tools/build-ffmpeg.mjs --info     # 体积 + 许可证 + 能力清单核对
```

**响度测量已经不再依赖 ffmpeg** —— 那部分改成了纯 Go 实现的 ITU-R BS.1770
（见下一节）。ffmpeg 现在只负责**解码**：

| 用途 | 能否纯 Go | 说明 |
| :--- | :--- | :--- |
| 响度测量（LUFS / 真峰值） | ✅ 已实现 | `internal/loudness/bs1770.go` |
| WAV / FLAC / MP3 / OGG / Opus 解码 | ✅ 有成熟纯 Go 库 | go-audio/wav、mewkiz/flac、hajimehoshi/go-mp3、jfreymuth/oggvorbis、pion/opus |
| **AAC / M4A 解码** | ❌ 没有纯 Go 实现 | 而本机曲库全是 .m4a |
| ape / wma / dsf 转码 | ❌ | 依赖 ffmpeg 的对应解码器 |

所以要彻底去掉 ffmpeg，下一步得走 **Windows Media Foundation**
（系统自带 AAC 解码，COM 调用，不增加分发体积，但是 Windows 专有且实现量大）。

## 在线歌曲（搜索 / 封面 / 下载 / 试听）

搜索入口在**标题栏的搜索图标**（也可以按 `Ctrl+F`）：

1. 点搜索图标 → 弹出**搜索弹层**，光标自动落在弹层顶部的搜索框里；
2. 输入关键词按回车 → 结果就出现在同一个弹层里；
3. 结果层有两个标签：`在线歌曲`（默认）与 `本地曲库`；
4. 在线结果可以直接 **试听** 或 **下载**；本地结果点一下就地起播；
5. 搜索框右侧的 **清空按钮** 会同时清掉输入与结果；
   不点清空时结果**不会销毁**，关掉弹层再打开还是上次的结果（DOM 与已加载的封面都不重建）。

> 为什么搜索框在弹层里而不是标题栏：早期版本把它放在标题栏、结果放在另一个浮层，
> 两个东西分处两地，要先点图标再点输入框，还和窗口按钮抢位置。合成一个弹层之后，
> 「输入 → 回车 → 看结果」在同一个面板里完成。

### 试听只进播放列表

在线歌曲试听时**不会混进「本地歌曲」**：

- `state.songs` = 本地曲库（扫描到的本地文件），「本地歌曲」视图只显示它；
- 在线曲目登记在 `state.onlineSongs`（Map，不落盘，链接有时效），
  试听只把它的 id 追加到**播放队列**；
- 底栏、播放界面、队列面板通过 `store.songById()` 统一解析，
  所以在线曲目照样有封面、能拖进度、能切歌。

### 单击歌曲的行为

默认**单击 = 播放这一首**（并把它加进播放列表，不动现有列表），双击始终是「立即播放这一首」。

可以在 设置 → 播放 → **单击歌曲时的行为** 里改成「播放当前列表」或「下一首播放」。
把它做成设置而不是写死，是因为这几种预期都很常见：一边是「我想排个队」，
另一边是「我只想听这首」。

### 封面

第三方接口地址、参数、可用性都会变，所以**所有联网封面逻辑单独成包**
（`internal/coverfetch`），上游只调 `Aggregator.Find`；某个源失效时只改一个文件。

| 来源 | 说明 |
| :--- | :--- |
| iTunes Search | 无需鉴权、响应快。**坑：不要带 ****`country`**** 参数**，实测 `country=cn/us` 会让接口返回 0 条 |
| 网易云 | 华语覆盖最好。用公开的专辑搜索接口拿现成的 `picUrl`，**不逆向 picId 编码**（那套私有编码失效时只会静默 404，很难发现） |
| QQ 音乐 | 华语覆盖好、接口稳定（实测 100~300ms）。由 `songmid`/`albummid` 拼封面地址，图床在 **`y.gtimg.cn`**（`.cn`，白名单与 Referer 都要单独放行） |
| Deezer | `cover_xl` 就是 1000×1000；实测大陆网络常整条超时，靠单来源超时 + 熔断兜住 |
| MusicBrainz + Cover Art Archive | 覆盖广、有稳定实体 ID；限流 1req/s，放在最后 |

**「经常搜不到封面/歌词」的两个真正原因**（都实测过，不是网络玄学）：

1. **熔断没接到面板这条路径上**：`Aggregator.Find` 会上报来源成败，但换封面面板走的是
   `FindAll`（→ `ResolveAll`），而它既不上报、也不跳过熔断中的来源。于是一个整条超时的
   来源（Deezer 在大陆网络下连 TLS 都过不去）会在**每次**搜索里稳定吃掉一个单来源超时。
   现在两条路径共用同一套「跳过 + 上报」逻辑，死掉的来源 2 次之后会被跳过 5 分钟（半开自动恢复）。
   同时\*\*「没命中」不再算失败\*\* —— 早期实现里连续两首冷门歌就能把一个健康来源停用 5 分钟。
2. **查询与下载共用一个超时预算**：一次封面搜索分成「并发查各来源」与「把候选图下载回来体检」
   两段，早期共用一个 9s 预算。只要有来源吃满 6s 的单来源超时，留给下载的就只剩 3s，
   网络稍慢就整批候选超时 —— 用户看到的是「一张封面都搜不到」。现在两段各有预算
   （`DefaultTotalTimeout` 10s / `DefaultDownloadBudget` 14s），并且**第一张可用图到手后
   只再等 2.5s 就返回**，不再为了等一个慢图床让界面转十几秒。

另外两处「静默失败」也一并修掉了：

- **HTTP 200 不等于成功**：网易的搜索接口被限流时返回的是
  `{"code":405,"msg":"操作频繁，请稍候再试"}`。以前只看 HTTP 状态码，于是它被当成「没搜到」，
  既没有提示也不会熔断。现在业务状态码非 0/200 一律当失败（网易封面、网易歌词、QQ 音乐三处都查）。
- **只声明自己能解码的图片格式**：QQ 图床会按 `Accept` 协商，原来照抄浏览器的
  `image/avif,image/webp,…` 会让它回 **WebP**，而标准库没有 WebP 解码器 ——
  表现是「这个来源明明搜到了候选，却一张都显示不出来」。现在优先声明 jpeg/png/gif。

**改封面**有两个入口：播放详情页「返回」右侧的**封面按钮**，或任意歌曲的
「更多」菜单 → **更换封面…**。弹层里可以：

- **一次列出所有来源的候选**（`Cover.LookupAll`）：iTunes 的 `entity=song` 与
  `entity=album` 两路 + 网易云 + Deezer + MusicBrainz 的结果都会下载、校验后并排显示，
  缩略图下标出来源与尺寸，用户自己挑 —— 而不是被动接受某一家返回的第一张；
- **按别的关键词搜索**：下载下来的文件本来没有标签（标题是从文件名推的），
  直接搜基本不可能命中，这里可以手填歌曲名/歌手再搜；
- **选择本地图片**（`Cover.PickLocal`）：与「联网搜索」同一行，后端弹系统文件
  选择器读回图片并体检，然后和联网候选并排显示 —— 两者走完全相同的
  「勾选 → 应用」流程，不需要为本地图单开一条路径；
- **默认勾选策略**：联网搜索的结果默认**全不选**（一次列出十几张，替用户全选
  等于往封面集合里塞噪声），本地选的图默认**全选**（那是用户刚刚明确的决定）。

弹层标题是「封面管理」：它不只有搜索，还要管这首歌已经有的多张封面
（设为当前 / 删除 / 把文件内嵌封面收进缓存）。

几个关键设计：

- **空白占位图必须丢掉**：很多图床在「没有封面」时返回一张**纯白图**，
  尺寸和状态码都正常，前端渲染出来就是「封面总是白的」。
  `coverfetch.InspectImage` 解码后算均色与方差，**纯色且均色 ≥ 246**（约等于白）的直接丢弃
  （纯黑封面刻意保留），小于 64px 的也丢；候选全被丢掉时给一句明确提示，
  而不是把白图当成功结果。
- **元数据里的占位值要当成「没有」**：扫描时无标签文件会被填成 `未知歌手 / 未知专辑`，
  拿它去搜只会污染结果，`isPlaceholderMeta` 会先滤掉。
- **必须有封面代理**：页面 CSP 是 `img-src 'self' data:`，第三方图片直连会被浏览器拒绝；
  而且多数图床校验 Referer。所以封面统一走 `/online/cover?src=…`（同源），
  下载时还会按域名补一个 `Referer`（网易云 / B 站等不带就 403）。
- **MIME 按字节嗅探**：有些图床返回的 `Content-Type` 是错的或缺失
  （`image/jpg`、`application/octet-stream`…），`NormalizeMIME` 一律以文件头为准。
- **图床白名单**：`/online/cover` 是一个「把任意 URL 内容回给前端」的接口，
  不加限制就是 SSRF。`coverfetch.AllowedImageURL` 只放行各家公开图床域名，
  并额外挡掉 IP 字面量。
- **确认命中（`confirmMatch`）**：标题必须有实质重合才采用；标题强命中（相等/包含）时不再看歌手
  （「晴天」vs「晴天(女版)」是最常见的可用结果）。没有这道关，查一个不存在的歌名也会返回一张封面 ——
  错的封面比没有封面更糟。
- **查不到就不显示封面**：接口返回 `available=false`，前端渲染一个安静的图标，
  绝不留浏览器破图。
- **熔断**：某个来源连续失败 2 次后冷却 5 分钟（半开自动恢复），
  避免慢站点每次搜索都白等一个超时。失败只算「连不上/超时/接口报错」，
  「没查到这首歌」不累计 —— 否则冷门歌会把健康来源一起停掉。

### 在线歌词来源

歌词搜索/自动匹配由 `internal/lyricsfetch` 聚合，默认四个来源：

| 来源 | 说明 |
| :--- | :--- |
| LRCLIB | 国际化最好，也是唯一提供稳定精确接口的来源。**先试 ****`/api/get`**（按歌手+曲名+专辑+时长对齐），再补全文搜索；只有行级 |
| 网易云 | 华语覆盖最好；网页搜索接口会被限流（见上文的 `code:405`）。带逐字的 `yrc`/`klyric` 字段对匿名请求一律是空的 |
| QQ 音乐 | 华语覆盖同样好。**主路径走 musicu（POST）**，老 cgi（`c.y.qq.com`）只作回退 —— 本机实测老 cgi 两个接口一律 HTTP 500 空 body。歌词里转义过的 `&apos;` / `&amp;` 会还原成正常字符；`qrc:1` 拿到的是**逐字 QRC**（hex + 私有 3DES，见 `qq_qrc.go`），没 QRC 时退行级 |
| 酷狗音乐 | 能匿名拿到逐字歌词（KRC）。搜索 → `krcs` 反查（必须带 hash）→ 下载 `fmt=krc`，没有 KRC 时退到 `fmt=lrc` |

只有两个来源（且其中一个随时可能被限流）时，在线歌词实际上常常只剩 LRCLIB 一个可用，
中文新歌的覆盖就会很难看 —— 这就是「歌词搜索经常失败」的直接原因。

**逐字（字级）歌词优先**（需求：有逐字就播逐字，没有就播逐行）落在三个地方，缺一处用户就看不到逐字：

1. **同一个来源的返回里**优先取字级字段（`neteaseLyricText` 依次看 `yrc` → `klyric` → `lrc`）；
2. **自动匹配**在拿到行级结果后，会为声明了字级能力的来源（`WordProvider`，目前是 QQ 与酷狗）
   再多花**一次**请求（见 `Aggregator.Match`）—— 代价有上限，切歌路径不会被拖长；
3. **本地读到的是行级时**，前端后台调一次 `Lyrics.UpgradeWordLyrics`：后端只在真拿到字级
   时才写缓存（老缓存里的行级歌词因此会被"升级"），`internal/lyrics#Load` 的规则是
   「字级结果优先于行级结果」，写进去之后每次打开都优先用它。同一首歌一次运行只试一次。

歌词搜索界面上，每个候选都带一个**格式标签**（逐字 / 逐行 / 未知 / 检测中…）：
格式在抓取之前无从知道（同一个来源有的歌有逐字、有的没有），所以搜索完成后前端
**逐条**调 `Online.ProbeLyricsFormat` 去问（并发打第三方接口会被限流；网易云排最后，
它被限流时会连着失败）。探测结果按候选缓存在聚合器里，用户随后点「使用」是命中缓存、
不会重复下载同一份歌词。

**逐字的画法是「从左到右连续填充」，不是「一个字整块变色」**（需求原话：要文字从左到右
逐渐变颜色）。契约与实现分工如下，改这一块时四处要一起看：

| 位置 | 职责 |
| :--- | :--- |
| `player-skins/src/lrc.js` | `wordEndsOf(starts, nextLineTime)` 把「每个字素的起始时刻」补成**区间**：下一个字的起始就是上一个字的结束；最后一个字按中位间隔推一个尾部（`max(400, 中位间隔×2)`，上限 1400ms），重复时刻给 60ms 下限。`wordFill(start, end, pos)` 返回 0..1，量化到 1% |
| `player-skins/src/lyrics-view.js` | 每帧给**当前行**的每个 `.lyric__word` 写 `--w`（值没变就不写、每帧不读 DOM）。`data-active`（离散的「唱到没唱到」）照旧保留 —— 那是第三方皮肤与自检脚本在用的对外契约，平滑填充是**叠加**上去的 |
| `player-skins/src/lyrics.css` | `background-image: linear-gradient(90deg, var(--accent) 0 calc(var(--w)*100%), <压暗的正文色> calc(var(--w)*100%) 100%)` + `background-clip: text` + `-webkit-text-fill-color: transparent`。两个同位置的色标 = 硬边界，所以边界能落在**一个字素内部**；没唱到的一侧取该样式自己的 `--lyric-dim` |
| `frontend/src/js/ui/desktop-lyrics.js` | 桌面歌词是**另一个窗口页**、拿不到 store：主窗口把 `{chars, words, wordEnds, posMs, atMs}` 一起推过去（`desktop_lyrics.go` 透传，`desktop-lyrics.js` 负责去重与量化），窗口用**锚点 + 自己的 rAF** 外推（上限 700ms），一个字素一个 `.dl__word`；译文另起一行（拼回主行会破坏字素与 `words` 的一一对应） |

两套内置样式（经典 / 沉浸）共用上面这份 `lyrics.css`，所以两边观感一致；第三方皮肤
走同一个 `createLyricsView` 也会自动获得该效果，但**离散契约没有变**，它们不会因此坏掉。

另外两处与成功/失败有关的行为：

- **「没搜到」不再等于「搜索失败」**：来源都正常但没有这首歌时后端返回**空列表**，
  界面显示「没有找到候选歌词」；只有真的全部失败（网络/限流）才把错误抛上来。
- **手动搜索会把 keyword 与 title/artist 一起传**：keyword 用于搜索，title/artist 用于**打分排序**。
  早期只传了 keyword，所有候选都落在同一个基础分上，翻唱/Live 版会排在原唱前面。
- 拿到「强命中」后只再等 1.5s 就返回，不再为一个卡住的来源白等一个 8s 超时；
  同分时按来源声明顺序（即优先级）排序，结果不会随网络快慢飘。

### 下载

- 默认保存到 **系统音乐目录 / downloads**（`%USERPROFILE%\Music\downloads`）；
- 设置 → 在线歌曲 → **下载保存位置** 可以改（目录选择器，或恢复默认），
  值存在 `config.json` 的 `downloadDir`；
- 下载在**后端**做（不是前端 `<a download>`）：只有后端知道真实路径、能反馈进度、能复用
  音频流解析；写入用 **临时文件 + 原子改名**，中途失败不会留下看起来正常的半成品；
- 同名文件自动加序号（`歌名 (2).m4a`），不会覆盖已有文件；
- 进度通过 `download:progress / done / failed` 事件推送，前端复用同一条 toast；
- **标题栏有一个下载入口，存在下载任务时才出现**，角标显示正在下载的数量；
  点开是「下载任务」面板：进度条 / 已完成（文件大小与文件名）/ 失败原因都留在面板里，
  还能清除已完成、打开下载目录、点某条已完成的任务在文件夹中定位。

**改下载位置时会问要不要迁移**：弹窗里告诉你旧目录有多少首歌、多大、目标目录已有多少，
可以选「迁移并更改」或「不迁移，只更改位置」。同名的不会被覆盖（跳过并统计），
单个文件失败不影响其他文件。迁移完成后会自动重扫，歌立刻出现在「本地歌曲」里。

### 下载目录就是扫描根

`Config.EffectiveFolders()` = 用户配置的文件夹 + 下载目录。
所以**下载完的歌直接出现在「本地歌曲」里，不需要用户手动添加文件夹**；
同时会判重：用户如果把 `Music` 整个目录加进来了，下载目录不会再重复添加。
下载目录不出现在设置的文件夹列表里（用户删不掉它），它的唯一真相来源是 `downloadDir`。

### 封面与歌词的缓存

封面与歌词默认都放在**缓存目录**里（设置 → 在线歌曲 → 缓存目录可以看到占用与位置，
也能单独打开 covers / lyrics 子目录）：

```
<cacheDir>/meta/covers/<songID>.jpg     封面原图
<cacheDir>/meta/covers/index.json       songID → {file, mime, source, at}
<cacheDir>/meta/lyrics/<songID>.lrc     歌词文本
<cacheDir>/meta/lyrics/index.json       songID → {file, source, at}
```

**缓存就是真相来源**，所以下面两件事必须做对（都踩过坑）：

- **重启后要把缓存回填到界面**：用户换过的封面存在缓存里，前端的 `coverOverrides`
  只是一张内存表。启动时调 `Cover.CachedPreviews` 把已有封面灌回去，否则「换过的封面
  重启后就没了」（除非开了写进文件）。歌词不用回填 —— 每次都是从后端 `Lyrics.Load` 读。
- **在线曲目的 id 不能直接当文件名**：试听曲目的 id 形如 `bili:BV1xx411c7mD`，
  冒号在 Windows 上是**非法文件名字符**，直接落盘会报
  `rename … The parameter is incorrect`，于是「试听时匹配到的歌词/封面」永远存不下来。
  `metacache.safeFileID` 把非法字符转义成 `_xxxx` 并在改动过时追加短哈希，
  本地 id（本来就是十六进制串）保持原文件名不变。

设置里可以开启\*\*「把封面/歌词写进歌曲文件」\*\*（默认关闭）：

- 默认关闭是刻意的 —— 这会在用户的音乐文件上做修改，必须是明确选择；
- 开启后换封面/下载时会**同时**写进文件标签，这样把文件拷到别的播放器上也能看到封面与歌词；
- **打开这个开关时，如果缓存里已经存着封面/歌词，会弹一个确认框问「要不要把已有的缓存
  一并写进歌曲文件」**（缓存里没东西就不打扰，只提示一句）。同一件事旁边还有一个常驻的
  「写入缓存到文件」按钮，之后想补写随时可以点。真正动文件之前一定会确认一次。
  后端入口是 `CoverService.WriteCacheToFiles`，返回写入 / 跳过 / 失败的明细
  （跳过的原因会列出来给用户看，多半是「这个格式不支持写标签」）。
- 实现见 `internal/metacache/embed.go`：m4a 是**在原有 moov 里长出一个 `covr`
  与 `©lyr`**（不动 mdat、不改动音频数据；但 `moov` 因此变大之后，`stco` / `co64` 里记录的
  绝对偏移**必须按 delta 同步**，否则 faststart 的 m4a 会被直接写坏 —— 见「设计约束」第 10 条；
  写盘用临时文件 + 原子改名），
  FLAC 是重写 metadata 区块插入 `PICTURE`，并把 `LYRICS` 合并进 VORBIS_COMMENT
  （小端长度，原有 TITLE / ARTIST 等注释原样保留）。mp3 / wav 等格式明确返回
  「暂不支持」而不是冒险写坏文件（内置的精简 ffmpeg 只编进了 wav/flac/null
  三个封装器，做不到通用 remux）。
- 一次操作就要把封面与歌词一起写：分成两次写会把整个文件读两遍、moov 重建两遍，
  而且封面会被覆盖两次。所以对外只有 `EmbedMeta(path, mime, cover, lyrics)` 一个入口，
  `EmbedCover` / `EmbedLyrics` 都是它的薄封装。

### 试听缓存的空闲清理（以及来源台账）

试听缓存放在**系统临时目录** `<TEMP>\LocalMusicPlayer\online\<bvid>.<ext>`，
它是**可丢弃的派生数据**：下载是用户的文件（下载时是**复制**，缓存留着，播放仍走缓存），
缓存则随时可以被回收 —— 系统清理临时目录、或者这里说的空闲清理。

清理器在 `online_cache_cleanup.go`（根包）。它**不是**「定时清空」，而是一组判据：

| 维度的判据 | 取值 | 为什么 |
| :--- | :--- | :--- |
| 多久没声音算空闲 | 5 分钟 | 一首歌 3~5 分钟；再短会在「暂停一下去倒水」时动手 |
| 启动后宽限 | 3 分钟 | 启动期在扫库、算响度、解包 ffmpeg，别凑热闹 |
| 检查间隔 | 1 分钟 | 一跳只读一次判据，开销可忽略；**必须远小于空闲门槛**（否则判据边界会吃掉一整轮机会：曾经间隔就是 5 分钟，实测「空闲 9 分钟一个字节都没回收」） |
| 两次清理最小间隔 | 30 分钟 | 清理不是越勤越好 |
| 闲置多久才允许删 | 7 天 | 一周没再被碰过、又不在任何引用里，才是真正的长尾 |
| 磁盘压力条款 | 缓存超预算时降到 24 小时 | 满了才放宽，平时保守 |
| 单次上限 | 64 个文件 / 128MB | 空闲不等于可以长时间占磁盘，剩下的下一轮再删 |

「不能删」的集合由三处合成，**缺一处就会误删**：

1. **歌单与「我喜欢」**：后端配置里读得到（`Config.Playlists[].SongIDs` + `LikedIDs`）；
2. **播放队列**：队列**只在前端**（`state.queue` 随快照写 localStorage），所以前端在队列变化时
   把在线 id 推给 `OnlineService.ProtectIDs`（`frontend/src/js/online-cache.js`，
   全量替换而不是累加 —— 累加的话清空队列后那些歌的缓存就永远清不掉了）；
3. **当前装载/正在播放的那首**：清理器每一跳现查 `PlayerService.State()`，
   **暂停着的那首也算**（用户点一下继续就能听，删掉就等于让他重新下载一遍）。

另外，**「已下载」与「缓存」的来源都记账**：`<数据目录>\online-sources.jsonl` 一行一条
（`internal/onlinesource`），记录 bvid、类型（`cache` / `download`）、路径、来源（缓存 / 网络）、时间。
搜索结果的「已下载」标注读的就是它，而且**每次读取都重新 stat 一遍文件**：
用户把下载的那首歌删掉之后，界面上的标注会自动消失（`exists: false`）。
台账监听不到用户的删除动作，所以不能在写入时就下结论 —— 结论必须在使用的那一刻成立。

#### 手动清理（设置里的按钮）与「收藏即下载」

后台空闲清理之外还有一条**用户主动**的入口：设置 → 在线歌曲 → 试听缓存 →
「清理未引用的缓存」（`OnlineService.CleanupCache` → `onlineCacheCleanup.runAll`）。
它与后台共用**同一套引用判据**，但不受那两条保守条款约束：

| 维度 | 后台空闲清理 | 手动按钮 |
| :--- | :--- | :--- |
| 触发 | 空闲判据全部满足 | 用户点击 |
| 闲置门槛 | 7 天（压力条款 24 小时） | **0**：只看有没有被引用 |
| 单轮上限 | 64 个 / 128MB | 无 |
| 引用保护 | 有（三处合成） | 有（同一份） |

手动路径把年龄门槛归零是刻意的：后台那 7 天是为了少让用户重下（他可能过十分钟又来听同一首），
而按下按钮意味着他此刻要的是空间；保留单轮上限则会让「点一次只清一半」。回执里会说出
「保留 N 个还在播放列表 / 歌单 / 喜欢里的」—— 用户点清理时最想确认的就是「我收藏的没被删」。

**收藏「只有试听缓存」的在线歌曲时自动补一份本地文件**（`frontend/src/js/auto-download.js`，
配置键 `autoDownloadOnCollect`，默认开）：试听缓存是可丢弃的派生数据，收藏 / 加入歌单却是
长期意图 —— 不补这一份，收藏夹里会混进一批「过几天就打不开」的歌。判据四条同时成立才下载：
开关开着、是在线曲目（`bili:` / bvid）、台账里**缓存存在**（说明真的试听过）、**还没有下载**。
「缓存存在」这条是需求里「没有下载的**缓存**歌曲」的落点，也避免用户只是收藏就凭空产生流量；
两个 `exists` 都由后端当场 stat，下载目录里那份被删掉后会重新补。store 侧只提供
`setCollectHook`（`toggleLike` 新增收藏 / `addSongsToPlaylist` 真正新增的那几首各通知一次，
取消收藏与重复添加都不通知），下载模块在 `main.js` 装配 —— store 是底层状态模块，
不该反过来 import 网络与下载。

### 新下载置顶（临时置顶 + 「新」角标）

需求原文：「新下载的歌曲排序让其靠前，并添加一个『新』的角标，这些角标和歌曲排序顺序
在下次排序时失效（相当于手动插入到最前面并添加角标，在用户重启，重新排序后失效恢复到正常排序）」。

实现全在 `store.js` 的一段模块级状态里（`markDownloaded` / `adoptDownloaded` /
`hoistFreshDownloads` / `dropFreshDownloads`，`main.js` 的 `download:done` 调第一个）：

- **凭什么认定「刚下载」＝ 路径**，不是时间窗。`download:done` 带的 `path` 就是最终落盘路径
  （Go 侧先发事件、紧接着 `onFileAdded` 才把文件塞进曲库；下载后的 AI 整理是**原地写回标签**、
  不改名），所以按路径一一对应既准确又不会误伤 —— 用「最近 N 分钟新增」那种判据会把
  「刚导入的一堆歌」也标成刚下载。比较前统一归一化（大小写 + 斜杠方向，`normDownloadPath`）。
- **置顶是「插入」而不是重排**：`hoistFreshDownloads` 只把命中的几首挪到最前面（后下载的在前），
  其余保持排序结果里的相对顺序；它返回新数组、不改入参数组。
- **只在列表视图生效**：队列视图的顺序本身就是数据，不参与置顶（与 `computeVisible` 里
  「队列不排序」同一条理由）。
- **什么时候失效**：用户任何一次主动排序（点表头 / 排序面板 / 换方向 → `dropFreshDownloads`）
  或重启应用。状态是模块级的、**不落盘**，所以重启天然失效 —— 这正是需求要的语义。
- **角标怎么画**：行标题渲染成 `data-new="1"`，`新` 字由 CSS 伪元素
  （`.track__title[data-new="1"]::before`）画出来。**不能**把「新」拼进
  `.track__title` 的文本里：`tools/verify-sort.mjs` 等 7 个自检脚本按 textContent 比对标题。
  伪元素放在文字**前面**是因为标题是 nowrap + ellipsis，放尾巴上会被裁掉。
- 自检：`tools/verify-lit.mjs` 的 `fresh-download`（置顶 + 角标 + 点击表头后失效 + 刷新后不残留）
  与 `frontend/tests/fresh-download.test.js`（置顶不改其余顺序 / 路径归一化）。

### 歌词区标题（单行 + 溢出跑马灯）

需求原文：「歌词区域里面，歌曲的标题太长会占据多行内容，帮我改成单行不换行，超出区域
使用横向跑马灯滚动」。原来的行为是**折行 + 最多 3 行 + 纵向滚动**（两款内置样式都这么写）。

- **零件在宿主**：`ctx.sdk.marqueeText(el, text)`（`frontend/packages/player-skins/src/marquee.js`）
  - 布局在骨架样式表 `marquee.css`（`.mp-marquee` / `.mp-marquee__text`）。它是宿主零件表、
    **不带 `@layer`**，而插件 CSS 一律落在 `@layer skin` 里 —— 所以皮肤自己再写
    `overflow-y:auto` / `text-align:center` 也压不过它，「单行」这件事不靠皮肤自觉。
  - 长度只能**量**（CSS 判不出文本宽过盒子），量完还要在换歌 / 窗口缩放 / 面板变宽后重量，
    所以用 ResizeObserver 收口在零件里，皮肤侧只有一行调用；`marqueeText` 幂等。
  - 放不下才滚：`--mp-marquee-shift`（滚多远）与 `--mp-marquee-dur`（滚多久）逐元素量出来写在
    元素自己的自定义属性上，速度固定 `42px/s`（长标题不会滚得飞快）。放得下就只居中，一点都不动。
  - 动画是**来回滚 + 两端停顿**（`alternate` + 关键帧 0~10% / 90~100% 停住），不是「滚出去再跳回来」；
    `prefers-reduced-motion: reduce` 下不滚，退化成「单行 + 裁掉」。
- **宽度必须是确定值**（这次改动的真正难点）：单行 = `nowrap`，而 `nowrap` 会把
  `min-content` 抬成**整段文字**的宽度。父容器若按 `fit-content` / `align-items:center` 排，
  盒子就会一路被撑到几千像素、贯穿整个窗口（`overflow:hidden` 根本无从截起）。
  - 经典：`.classic__info` 的列宽是确定的（歌词那一列 624px），标题 `align-self: stretch` 即可。
  - 沉浸：卡片 `min(760px,100%)` 有确定宽度，但 `.immersive__info` 自己按 fit-content 排 ——
    实测长标题把它撑到 **1901px**（超出窗口），所以这一列也要 `align-self: stretch`。
    更隐蔽的是**舞台的隐式列**：宿主默认舞台是 `display:grid; place-items:center`，没写列定义时
    那一列按 `max-content` 算，同样被撑到 1900px —— 卡片自己只有 760px，却按这个超宽列居中，
    表现是「整块内容偏到窗口右边」。沉浸的 CSS 因此补了 `grid-template-columns: minmax(0, 1fr)`
    （经典本来就有显式列定义，没这个问题）。
  - 这两处都是自检 `boxW <= colW` + `docScrollWidth <= innerWidth` + 「标题盒中心 ≈ 窗口中心」
    抓出来的：光看 `#pv-title` 高度是「一行」，破窗和偏心都看不出来。
- 自检：`tools/check-player-host.mjs` 第 9 组（长标题单行 / 真的在滚 / 短标题不受影响 / 沉浸同样成立）。
  「在滚」的判据是**隔一段时间采两次 `transform` 必须不同**（关键帧两端有停顿，所以要给它时间动起来），
  只看到挂了个 class 不算数。另外两条是几何断言：文档不许被撑出横向滚动、标题盒中心要在窗口中心。

## 设计约束（改代码时请遵守）

> **这是 19 条约束的详细版**；仓库根 `AGENTS.md` §6 是同一份清单的速查版，**编号一一对应**。
> 改这里请同步改那边 —— 这两份清单曾经各写各的，同一条约束在两处说法不同，
> 照着哪一份改都可能做错。

 1. **配置键必须三处同步**：`internal/bootstrap/config.go` 的字段 + `services.go#applyPatch`

    - `store.js#SYNCED_KEYS`。漏一个键不会报错，只会**静默丢弃**
      （表现为「改了设置，重启就没了」）。`config_service_test.go` 会跨进程读盘验证。

    **例外：服务自己管的键**（`updateChannel` / `skippedVersion` / `packSource`）不进 `applyPatch`
    与 `SYNCED_KEYS`，而是由对应服务直接 `store.Update(...)` 落盘、并另配一个 getter 给前端读。
    理由见第 14 条：前端推配置有 400ms 防抖，而「刚改完通道立刻检查更新」这类动作等不起 ——
    走 `applyPatch` 就会出现「按钮点下去用的还是旧值」。判断标准是**这个键是不是被前端当作
    普通表单字段在推**：是 → 三处同步；是「某个动作的参数，动作的同时要立刻生效」→ 服务管理。

 2. **`StableID` 两端必须一致**：Go 的 `bootstrap.StableID` 与前端 `utils.js#stableId` 有测试
    逐条比对（`internal/bootstrap/ids_test.go`），改成不一致会让歌单 / 收藏 / 队列在重扫后集体失效。

 3. **「当前」只能有一个真源**：

    - 选中行 = `state.currentId`（列表只把它画出来，见 `tracks.js`）；
    - 当前封面 = `store.coverSets` 里的 `active`（列表、底栏、详情页、写回文件都读它）；
    - 轮播开关 = 全局 `config.coverCarousel`（**不是**每首歌的属性，否则会出现「这首开那首关」两份真相）。

    新增任何「当前是哪个」的界面元素时，先想清楚它的真源在哪，不要在 DOM 里再存一份。

 4. **HTML 里不写样式；组件 CSS 只写布局，一切视觉效果归令牌（= 归主题）**：
    不加 `style="…"` / `<style>`；`components/*.css` 只写尺寸、间距、定位、栅格、过渡时长，
    凡是**不影响盒子尺寸与位置**的东西 —— 颜色、描边颜色、背景、渐变、阴影、模糊半径、
    滤镜、不透明度 —— 一律 `var(--token)`，字面量只出现在 `tokens.css` 与 `themes/*.css`。
    主题文件**只声明令牌**（写选择器 / 组件样式会破坏「布局固定」这一需求）。

    为什么这条要写死而不是「够用就行」：主题 CSS 是运行时注入的（在 `tokens.css` 之后进文档），
    组件里再写死一个颜色，同一处视觉就有了两个来源，谁生效取决于选择器特异性与注入顺序 ——
    表现为「用户复制一份主题改了令牌，界面只有一部分跟着变，而且从代码上看不出为什么」。
    反过来说，守住这条线之后，**改主题不可能移动任何元素**，改布局也不可能顺手改掉配色。

    视觉层的令牌按用途分组放在 `tokens.css`（遮罩 `--scrim-*`、封面虚化 `--cover-*`、
    浮层模糊 `--veil-blur`/`--scan-blur`/`--popover-blur`、单体阴影 `--thumb-shadow`、
    滤镜 `--accent-hover-filter`/`--slider-idle-filter`、视觉强度 `--op-*`、落点描边 `--locate-*`），
    `themes/_template.css` 是这份清单的「可复制版」，用户复制它改名即可换掉整套观感。
    **新增视觉值时必须同时补进这两处**，否则主题作者看不到这个旋钮。
    `frontend/tests/css-visual-tokens.test.js` 看着这条线：非主题 CSS 里出现颜色 / 硬编码滤镜 /
    不引用令牌的 `box-shadow` 会直接测试失败；引用了不存在的令牌（静默拿到空值）也会失败。

    例外只有一处：**桌面歌词窗口**（`desktoplyrics.css`）是独立透明页面，它刻意不加载主题，
    视觉常量集中在该文件顶部自己的 `:root { --dl-* }` 块里。

    布局关键尺寸全部令牌化：`--h-titlebar` / `--w-sidebar` / `--h-playerbar` / `--h-header` / `--row-h`。

    运行时改变量走 `runtime-tokens.js#setRuntimeToken()`：它写一条带 `!important` 的 `:root` 规则，
    能盖过 `early_theme.go` 留下的首帧**行内**值 —— 直接写 `element.style` 一来盖不过它，
    二来散落的内联副本没有一处能统一回收。

 5. **给 `[hidden]` 元素写样式时，别让 `display` 把它复活**：`[hidden]` 的默认 `display: none`
    只是**元素选择器级别**的默认样式，组件里任何一句 `display: flex/grid/…` 都会把它盖掉 ——
    元素虽然 hidden，却仍然占位、仍然接收指针事件。我们的搜索 / 设置 / 封面三个弹层就因此
    透明地铺满整窗、吃掉所有点击（界面表现是「点任何按钮都没反应」，而且完全看不出原因）。

    `utilities.css` 里已加一道 `[hidden] { display: none !important }` 兜底，但**改动弹层样式后
    请务必跑 `tools/hitcheck.mjs` 或 `ui-round2.mjs`**：它们用 `Input.dispatchMouseEvent`
    做真实的命中测试，而 `element.click()` / `dispatchEvent` 是直接投递给目标元素的、
    **绕过了命中测试**，这类 bug 在旧写法下能一路绿灯溜过去。

 6. **弹窗（`.modal-backdrop`）的层级必须用 `--z-modal-top`，不能和设置层同为 `--z-modal`**：
    设置层 / 封面层 / 搜索层虽然也是 `fixed`，但它们是 `.app`（`z-index: 10`，自成层叠上下文）的
    孩子，而弹窗是 `body` 的孩子；两者数值相同时**设置层会盖在弹窗上面** —— 弹窗看得见、
    按钮却点不动（真实鼠标命中测试才会暴露，`element.click()` 测不出来）。
    改层级相关样式后跑 `tools/probe-live-settings.mjs`，它会真实点一遍设置里的确认框。

 7. **设置层里的分组状态要存在渲染之外**：分组选中态由 **`ui/settings-view.js#_activeSection`**
    持有（**不是** `settings.js` —— 那里没有这个符号）。任何「当前选中的分区」这类状态若只写在
    渲染结果里，重渲染后就会回到默认值（表现是「点设置里任何按钮，导航栏的选中项都跳回第一个」）。

 8. **UI 的 `id` / `class` 是对外契约**：主题 CSS、皮肤包 CSS、`tools/*.mjs` 自检脚本都按它们查询。
    改名（或把静态节点换掉却不保留 id）会**静默破坏自检**，而且不会有任何报错。

 9. **无头自检必须对静态预览服务器跑**（`node tools/dev-server.js 5173`），不要对 Vite 跑：
    Vite 会给模块 URL 加查询串，脚本里的 `import("./js/store.js")` 会拿到**另一个空实例**
    （断言全读到 `songs=0`，看着像功能坏了）。

10. **插件零 import**：`frontend/packages/player-skins` 里只允许依赖包内模块；插件（内置与第三方
    同规）除包内相对路径的私有模块外**一个 import 都不许写**，数据只从 `ctx` 拿、动作只走
    `ctx.actions`、复用零件走 `ctx.sdk`。第三方样式是运行时从 `/skins/` import 的，
    一旦它们依赖 `store.js` 之类的东西，接口就没法演进，第三方也会随内部重构一起碎掉。

11. **插件的 CSS 作用域由宿主强制包裹**（`@layer skin { @scope (舞台) { … } }`，见 `wrapPluginCss`）：
    插件的选择器**相对舞台根**写（舞台自身用 `:scope`），**不要**再写
    `.playerview[data-skin="<id>"]` 前缀（在 `@scope` 里作用域根只能用 `:scope` 匹配，
    写全前缀可能匹配不到），也**碰不到**宿主 UI（标题栏 / 底栏 / 播放队列）——
    想影响宿主控件的观感，只有一条路：在清单 `colors` 里声明配色。
    正确写法见 `internal/skins/template/skin.css` 与《皮肤说明.md》。
    ★ **`@layer` 管不到自定义属性的继承**：图层只决定同一条声明谁赢，而 `--lyric-size` 这类
    自定义属性是普通继承 —— 祖先元素上的一句声明就近压过 `:root`，图层胜负根本轮不上。
    所以骨架样式表（`lyrics.css` 等）**不在元素上声明可定制量**，一律在使用点写兜底
    （`font-size: var(--lyric-size, 16px)`）；插件要改就写在自己的作用域（`:scope { … }`）上。
    宿主下发的用户设置（如歌词字号）**不许写死**，否则等于替用户关掉设置里的滑杆
    （历史故障：设置里拖歌词字号没反应）。详见 `docs/42` §8.2。
    **舞台安全区**：声明了 `capabilities.background` 的样式舞台会铺满整窗（`inset: 0`），
    而宿主的「标题栏 + 详情页头部行」（88px）与「底部播放控件栏」（86~92px）是浮在它**上面**的
    —— 宿主把这两条带子的高度写成 `--skin-inset-top` / `--skin-inset-bottom` 挂在舞台根上，
    插件里**要给人读的内容**（曲名 / 歌手 / 时间码 / 提示 / 歌词 / HUD）必须
    `calc(var(--skin-inset-top, 0px) + Npx)` 让开，装饰层不受限；兜底值只能写 `0px`
    （桌面背景歌词窗口把两者归零）。第三方样式包的签收条件 S11 要求自检**量出来**，
    规范正文见 `docs/42` §3.1、
    `frontend/packages/player-skins/README.md`、`internal/skins/template/皮肤说明.md`。

12. **写用户文件的代码（`internal/metacache/embed.go`）必须遵守三条**：① 只在原结构里做
    **最小插入**（例如往 moov 里加一个 `covr`），不改动音频数据、不改动任何 chunk 的语义与顺序；
    ② 容器头部因此变大时，记录数据块绝对位置的偏移（`stco` / `co64`）**必须按 delta 同步** ——
    这是唯一允许改动**数值**的地方，因为不同步就是把文件写坏（faststart 的 m4a 全都 `moov` 在前，
    必然命中）。判据是「能不能证明它安全」：只认白名单内的容器结构，遇到无法同步的
    （`moof` / `mfra` / `iloc` / `saio` / `stsh`、32 位溢出）就**放弃写入并保持原文件一字节不动**；
    ③ 写盘走「临时文件 + 原子改名」，中途失败不能留下半成品。不支持的格式要**明确返回不支持**，
    不要赌一把写坏用户的东西。细节见 `EmbedCover` / `EmbedLyrics` 的文档注释与
    `internal/metacache/embed_offset_test.go`。

13. **依赖第三方网络接口的东西单独成包**：`internal/bilibili` / `internal/lyricsfetch` /
    `internal/coverfetch` 各自独立，上游只依赖聚合器的方法。这些接口随时会变，
    隔离之后失效范围只有一个文件。

14. **不要靠读配置来决定一次性的动作**：配置是前端防抖（400ms）同步过来的，「刚改完设置立刻
    做某件事」时后端很可能还没收到新值（换封面写文件就踩过这个坑）。这类选择由调用方
    **显式传参**（见 `CoverService.ApplyWith`）。

15. **音频必须与页面同源**：页面从 `http://wails.localhost` 加载 `http://127.0.0.1:port` 的媒体
    会被 WebView2 直接拒绝（`Media load rejected by URL safety check`）。音频、皮肤、封面代理
    **都必须**走 Wails 的 asset server 同源路由；「独立端口 + 跨源」那套实验已经作废。

16. **音频在后端出声**（`internal/audioplay`，独立线程）：正常路径下前端不出声，所以 `ctx.audio`
    早已从皮肤契约移除。进度用「后端锚点 `{positionMs, atMs}` + 前端 `performance.now()` 外推」；
    频谱由后端计算、皮肤**拉取式** `ctx.spectrum()` 取。

    ⚠️ 别把「前端不再有 `<audio>`」读成「`audio.js` 里那段 `<audio>` 可以删」——`audio.js`
    仍保留一条**可达的 legacy 回退路径**（`Player.Available()` 为假时，例如浏览器预览或
    用户机器上 WASAPI 打不开）。它是保底，不是死代码：改播放链路时两条路径都要照顾
    （`tools/playtest.mjs` / `tools/loudtest.mjs` 也是两条都读）。

17. **CSS 与格式策略**：Prettier **不覆盖** `frontend/src/styles/` 与 `frontend/src/*.html`
    （那里的数值是量出来的，HTML 里行内元素的空格有语义），**其余前端源码都在格式化范围内**。
    源码是原生 JS，需要类型的地方写 JSDoc + 文件头 `// @ts-check`（tsconfig 是「逐个文件收紧」）。

18. **界面按钮由 Lit 模板渲染**（`ui/*.js`），不要再用运行时 `document.createElement` 注入。
    底栏「歌词」按钮曾经是某个模块在自己模块顶层 inject 进去的 —— 结果那个模块没被任何地方
    import，按钮就**静默消失**了，而且从 HTML 里完全看不出少了什么。
    `tools/check-playerbar-tools.mjs` 会盯着这一类「按钮被谁悄悄删掉 / 加回来」的回归。

19. **绑定返回的列表永远不能是 nil 切片**：Wails 把 Go 的 nil 切片序列化成 JSON `null`（不是 `[]`），
    而前端对 `songs` / `folders` 这类列表一律是「`if (Array.isArray(x))` 才更新状态」——`null` 被当成
    「这次没拿到数据」，于是**保留旧列表**，表现出来就是「重扫了但曲库没变」。真实故障：把下载目录里的歌
    删干净后重扫，后端曲库已经是空的，界面上的歌却还在，只有播放时才报「文件不存在」。
    空列表写 `make([]T, 0, n)`，不要 `append([]T(nil), …)`；回归测试断言的是**序列化形状**
    （`[]` 而不是 `null`），见 `internal/library/empty_list_json_test.go`。

**另外一条分工约定**（不在上面 19 条里，但同样别搞错）：

- **搜索分两处，别混在一起**：① 在线搜索在弹层里（`searchpanel.js` + `ui/search.js`），
  弹层独立于内容区；② 本地曲库筛选是内容区头部的独立筛选条（`#content-filter`，在 `index.html`
  里静态存在，`shell.js#syncFilterBar` 只改计数与清空按钮的可见性）。**不要**把本地筛选输入框
  挪进内容区工具条 —— 它和工具条同属一个 Lit 模板，混在一起会让输入与列表更新互相牵动。
