## 1. 技术选型

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 外壳 | Wails v3 (beta.14) | 原生窗口 + WebView2 渲染，安装包小、内存低；Go 侧可直接访问文件系统、进程、系统 API |
| 前端 | 原生 HTML / CSS / ES Module | 无构建步骤；满足「布局固定、样式全部写在 CSS 里、以主题命名」的需求 |
| 音频元数据 | `github.com/dhowden/tag`（ID3/Vorbis/MP4/FLAC） | 纯 Go，读取标题/歌手/专辑/内嵌封面 |
| 时长 / 采样率 | `github.com/tcolgate/mp3` + `github.com/go-audio/*`，flac 用 `mewkiz/flac` | 纯 Go 解析；避免依赖外部命令 |
| 文件夹监听 | `github.com/fsnotify/fsnotify` | 跨平台，支持递归监听（Windows 需逐目录 Watch） |
| 封面取色 | `github.com/EdlinOrg/prominentcolor` 或自写 k-means | 为 `cover-dark` 主题提供 `--seed` |
| 音频解码 | WebView2 原生解码优先；不支持的格式用 **ffmpeg 子进程转码** | 见 §6 |
| 配置存储 | JSON 文件（`%APPDATA%\MusicPlayer\config.json`） | 人类可读、便于用户手改 |

## 2.1 前端已经踩过的两个坑（后端接入时别再踩）

1. **CSP 与运行时样式**
   `index.html` 的 CSP 现为 `style-src 'self' 'unsafe-inline'`（已与用户确认）。
   Chromium 会拦截：动态创建 `<style>`、`<style>.textContent`、`<link href="blob:…">` 样式表，以及 `el.style.setProperty("--x", …)`（报 "Applying inline style violates …"）。
   约定：运行时改主题相关变量一律走 `js/runtime-tokens.js#setRuntimeToken()`（CSSOM `insertRule` 写入 HTML 里预置的空 `<style>`）。
   若后续想收紧 CSP，需要把所有运行时样式改成「切换 class」或「服务端生成 CSS 文件 + `<link href="/themes/x.css">`」。

2. **歌曲 id 必须由路径派生**
   预览数据用 FNV-1a 从文件路径生成稳定 id（`utils.js#stableId`）。后端也要保证「同一路径重复扫描得到同一 id」，否则歌单、播放队列、收藏会在重扫后集体失效。

## 4. 过滤引擎语义（A3 / A4 的关键实现）

前端 `store.js#matchRules` 已实现并在预览中可验证；后端 `library/filter.go` 必须与之**逐条对齐**（建议两端共用一份 JSON 规则数组，语义唯一来源写在本文档）：

```jsonc
{
  "id": "rule_size",
  "type": "size",        // size | regex
  "op": "lt",            // size: lt|lte|gt|gte|eq   regex: match
  "value": "10240",      // size: 数字（配合 unit）  regex: 正则源码
  "unit": "B",           // B | KB | MB | GB
  "scope": "exclude",    // exclude（排除命中项） | include（仅保留命中项）
  "enabled": true
}
```

判定顺序：

1. 过滤掉 `enabled == false` 的规则；
2. 任一 `exclude` 规则命中 → 该文件**排除**（短路返回，排除优先）；
3. 若存在启用中的 `include` 规则，则**至少命中一条**才保留；
4. 正则针对 `完整路径` 与 `文件名.扩展名` 两者做匹配，`i`（忽略大小写）；
5. 正则非法（编译失败）→ 该条规则视为失效并**在设置界面标红提示**，不影响其它规则。

覆盖需求里的例子：
- 「排除小于 10KB 的文件」→ `{type:size, op:lt, value:"10240", unit:"B", scope:exclude}`
- 「排除 *.mp4」→ `{type:regex, op:match, value:"\\.mp4$", scope:exclude}`
- 「排除小于 10KB 的 .mp4」→ 上面两条同时启用即等价（与关系由 exclude 短路天然满足）

## 5. 文件夹监听（A2）

1. 每个根目录启动一个 `fsnotify.Watcher` 实例，**递归**对子目录逐个 `Add`；
2. 事件类型：
   - `Create` → 若是音频且通过规则 → 新增；
   - `Remove/Rename` → 从索引移除；
   - `Write` → 重新读取元数据（文件可能只写了一半，延迟 500ms 防抖再读）；
3. 新建子目录 → 自动 `Add` 并立即扫描该目录；
4. 合并窗口：500ms 内的批量事件合并成一次 `library:changed`，避免大批量拷贝时刷屏；
5. 音频扩展名白名单：`mp3 flac wav m4a aac ogg opus wma ape`（ape/wma 标记为「需转码」）。

## 6. 音频播放的关键决策（需要你拍板）

WebView2（Chromium）原生能解码：**mp3 / wav / m4a(aac) / ogg / opus / flac**（Chromium 支持 FLAC）。
原生**不能**解码：**ape / wma / dsf / tak / cue 分割**等。

方案 A（默认推荐）：**后端流式转码**
- Go 侧调用本机 `ffmpeg`（已安装：`C:\Users\Example\Application\ffmpeg-master-latest-win64-gpl-shared\bin\ffmpeg.exe`）；
- 把不支持的格式转成 `f32le/48k/2ch` PCM 或直接 `-f wav` 流，经 `wails` 的自定义协议 `http://wails.localhost/audio/<songID>` 输出；
- 前端 `<audio src=...>` 直接播；支持 seek（需 `-ss` 分段或生成临时文件）；
- 优点：一个播放器吃下所有格式；缺点：首次播放有 ~200–500ms 转码延迟，seek 复杂一点。

方案 B：**只用原生可播格式**
- 遇到 ape/wma 时提示「暂不支持，需转码」；实现最简单。

方案 C：**后端常驻本地 HTTP 服务**（`127.0.0.1:随机端口`）提供文件与转码流
- 与 A 类似，但 seek 用标准 HTTP Range，最省心；代价是多一个监听端口。

> 建议先按 **A + 无 ffmpeg 时自动降级为 B** 实现：检测到 `ffmpeg` 就用 A，否则不可播格式只展示不播放。

其它播放相关：
- 播放状态由 Go 侧为权威源（`player:state` 事件），前端只做展示，避免前后端进度打架；
- 音量用前端 `<audio>.volume` 控制（简单可靠），不做 WASAPI 独占；
- 无缝衔接 / 淡入淡出：第二阶段再做。
