# 桌面背景歌词「启用时黑一下」修复

> 现象：打开「桌面背景歌词」时，桌面上先闪一块近黑色，之后皮肤与歌词才出现。

## 1. 成因

### 1.1 前一轮修的是什么、漏了什么

`docs/07-审查修复记录.md` 7.2 已经修过一次：原实现里
`attachDesktopWallpaperWindow` 硬写了 `WS_VISIBLE` 与 `SWP_SHOWWINDOW`，
窗口在挂进壁纸层的同一刻就可见了，而那一刻页面才刚开始加载 —— 于是先看到一块纯色。
那次把可见性拿掉，改成「页面把第一帧写进 DOM 之后调 `MarkDesktopWallpaperPainted` 再显示」。

这个判据只到 **DOM** 这一层。DOM 写完只说明内容进了文档树，
**样式 / 布局 / 绘制 / 合成器提交**都还没发生；而窗口是隐藏创建的，
WebView2 在 `controller.IsVisible == false` 时**不出帧**，页面的 rAF 也不派发。
所以 `Show()` 之后到「第一帧真的被合成出来」之间还有一段空档，
那段时间窗口里什么都没有，露出来的是窗口自己的底色 —— 就是那一下黑。

主窗口 (`services.go#showPrepared` + `window_reveal_windows.go`) 早就用
**DWM 遮罩（DWMWA_CLOAK）** 解决了同一个问题，但桌面背景歌词这段代码写在遮罩机制之前，
一直没跟上。

### 1.2 为什么不能照抄主窗口

主窗口是**顶层窗口**，DWM 只对顶层窗口负责，所以它可以直接
「遮住自己 → Show() → 就绪后摘掉遮罩」。
桌面背景歌词最终必须是壁纸层（WorkerW）的 **WS_CHILD** 子窗口，于是多了一重约束。

实测（本机 Win11 24H2，一次性探针，已删除）：

| 步骤 | 结果 |
| --- | --- |
| 隐藏创建 → `DWMWA_CLOAK=1` → `ShowWindow(SW_SHOW)` | `IsWindowVisible=true` 且 `DWMWA_CLOAKED=1`，`PrintWindow` 全黑 —— 窗口在出帧，但屏幕上看不见 |
| 在遮罩状态下 `SetParent(WorkerW)` 之后再摘遮罩 | `DwmSetWindowAttribute` 返回 **0x80070006 (E_HANDLE)**，`DWMWA_CLOAKED` 仍是 1 —— **子窗口上遮罩摘不掉** |

也就是说，「先挂载、后摘遮罩」这条路根本走不通。顺序必须是
**先摘遮罩（此时它还是顶层窗口）、再 SetParent**。

## 2. 方案：先在桌面之外把首帧渲染完，再放进桌面

   ① ensureDesktopWallpaper
        隐藏创建 → armDesktopWallpaperOffscreen（DWM 遮罩 + 按壁纸层尺寸摆好）
        → Show()  ← 用户看不见，但 WebView2 从这一刻开始正常出帧、rAF 正常派发

   ② 页面：皮肤挂上 + 主窗口的媒体快照到位（announcePainted）
        → 再等**两帧 rAF**（afterPaint，合成器确实拿到这一帧了）
        → MarkDesktopWallpaperPainted

   ③ showDesktopWallpaperNow
        revealAndAttachDesktopWallpaper：
          找壁纸层（会等资源管理器，此时仍遮着）
          → 顶层状态下摘遮罩（可验证，读回 0）
          → 立刻 改样式 + SetParent + 摆位置（不派发消息的三下）
        → 窗口出现的那一帧，就是页面已经画好的那一帧

几个刻意的取舍：

- **先在顶层状态下摘遮罩**：如上所述，这是唯一能摘掉遮罩的时机。
  它与随后的 `SetParent` 之间只有三下不派发消息的 Win32 调用，
  短到连一帧都凑不出来；即便真有哪一帧被合成出来，露出的也是**已经画好的**画面。
- **挂载前后尺寸完全一致**：`armDesktopWallpaperOffscreen` 就把窗口摆成壁纸层大小
  （并顺手改成没有非客户区的 `WS_POPUP`，让窗口矩形 == 客户区矩形），
  于是挂载时不发生任何尺寸变化，WebView2 不需要重建渲染表面。
- **不再清掉 `WS_VISIBLE`**：旧代码在挂载时写死 `style &^= wsVisible`，
  在新顺序下那等于把刚刚画好的首帧又藏起来。
  现在可见性由调用方决定：两阶段路径保持可见，旧路径（隐藏创建）保持隐藏。
- **摘遮罩之后才 `Show()` 一次（幂等）**：万一阶段 ① 那次 `Show()` 没落实
  （Wails 的窗口实现还在 `pendingRun` 里时，`Show` 会直接返回），这里补上。
- **挂载失败就把遮罩加回去**：宁可什么都不出现，也不要留下一块盖住整个桌面的
  无边框顶层窗口（那时窗口仍是顶层窗口，遮罩加得回来）。
- **遮罩期间加 `WS_EX_TRANSPARENT`**：那几百毫秒里它是个盖住整块屏幕的顶层窗口，
  而 DWM 遮罩只作用于显示层、命中测试照样会命中它。不穿透的话，用户点什么都落在
  一块看不见的窗口上（启动时恢复这个模式甚至有几秒）。挂载时会清掉这一位，
  所以最终的窗口样式与旧实现逐位一致。
- **本机遮不住就整体退回旧行为**：`armDesktopWallpaperOffscreen` 返回 false 时，
  走原来的「挂进壁纸层 → 页面画好后显示」。代价是那段空档藏不住，但功能照常可用；
  而且「找不到壁纸层」这类开不起来的错误仍然能在 `openDesktopWallpaperWindow`
  里同步报给前端（两阶段路径做不到）。

## 3. 改动清单

| 文件 | 改动 |
| --- | --- |
| `desktop_wallpaper.go` | `ensureDesktopWallpaper` 拆成「遮罩后台渲染」与「退回旧路径」两支；`showDesktopWallpaperNow` 改为走 `revealAndAttachDesktopWallpaper`（摘遮罩 + 挂载 + 幂等补 Show） |
| `desktop_wallpaper_windows.go` | 新增 `armDesktopWallpaperOffscreen` / `revealAndAttachDesktopWallpaper` / `wallpaperLayerSize`；`attachDesktopWallpaperWindowTo` 保留 `WS_VISIBLE`；挂载动作与「找壁纸层」拆开，好让找层排在摘遮罩之前 |
| `desktop_wallpaper_other.go` | 两个新函数的非 Windows 兜底（恒不支持） |
| `services.go` | `WindowService` 新增 `wallpaperCloaked` / `wallpaperAttached` 两个窗口级状态 |
| `frontend/src/js/desktop-wallpaper-window.js` | `announcePainted` 改为 `afterPaint`：**两帧 rAF** 之后再报，另加 150ms 定时器兜底（隐藏窗口不派发 BeginFrame，旧路径下 rAF 永远不会来） |
| `tools/verify-wallpaper-first-frame.mjs` | 断言前的等待从 120ms 提到 300ms（判据多了两帧 rAF） |

| 命令 | 验证什么 | 结果 |
| --- | --- | --- |
| `node tools/verify-wallpaper-first-frame.mjs` | 页面侧判据不回归（11 项）。另外把兜底定时器临时改成 100 秒重跑一遍仍然全过 —— 证明信号确实来自两帧 rAF，而不是超时兜底 | ✅ 11 项全过 |
| `gofmt -l .` / `go build ./...` / `go vet .` | 不回归 | ✅ 全绿 |
| `go test .` | 不回归 | ✅ |
| `npm run check`（ESLint + tsc + 单测） | 不回归 | ✅ 27 项 |

探针另有两条结论（用一次性的 Win32 小程序实测，跑完已删除）：

- `DWMWA_CLOAK` 对「隐藏创建 → 遮罩 → Show」的顶层 popup 生效：
  `IsWindowVisible=true`、`DWMWA_CLOAKED=1`、`PrintWindow` 全黑；
- `DwmSetWindowAttribute(DWMWA_CLOAK)` 在 WS_CHILD 上返回 E_HANDLE。

## 5. 性能

这一版**不增加**任何常驻开销，反而少了一次布局与一次表面重建：

- 页面仍然「不跑循环」，只是首帧信号从「一轮宏任务」变成「两帧 rAF」，
  多花约 32ms（一次性）。
- 窗口从创建起就按最终尺寸排版，挂载时尺寸不再变化 —— 省掉了
  「先按 1280×720 排版、挂载后再按全屏重排」那一次。
- 后台渲染这段时间里，WebView2 的合成器本来就要跑（它只是被遮住了），
  没有多画一份。
