# 11 · 性能对比报告（Lit 迁移前 / 后）

> 配套：[`09-Lit迁移方案.md`](./09-Lit迁移方案.md) · [`10-Lit迁移报告.md`](./10-Lit迁移报告.md)
> 测量脚本：[`tools/perf-lit.mjs`](../tools/perf-lit.mjs)（无头 Edge + CDP，可复跑）

---

## 1. 测量方法

同一台机器、同一个构建产物形态（`vite build` 的 minify 产物）、
同一个 1280×820 视口、同一套 mock 曲库、同一段脚本：

| 项             | 说明                                                                                                                                                                                             |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 基线（before） | `git worktree add .task/baseline HEAD` —— 迁移前的提交 `aae1c87` 单独构建                                                                                                                        |
| 现在（after）  | `frontend/dist`（迁移后）                                                                                                                                                                        |
| 服务方式       | 本地静态服务 + `/wails/runtime.js` 桩，两个构建完全相同的加载路径                                                                                                                                |
| DOM 统计       | 页面启动时装一个 `MutationObserver`，**按子树递归统计真实新增/移除节点**（只看 `addedNodes.length` 会把 `innerHTML = "<div>…</div>"` 记成「加了 1 个节点」，从而漏掉整块重建）                   |
| CPU 统计       | CDP `Performance.getMetrics` 的 `ScriptDuration / TaskDuration / LayoutDuration / RecalcStyleDuration`，取「播放中 3 秒」的差值（脚本会先确认 `state.playing === true` 且进度确实推进了 3000ms） |

## 2. 结论速览

| 指标                              | 迁移前   | 迁移后   | 变化                     |
| --------------------------------- | -------- | -------- | ------------------------ |
| 打开设置层（新增节点）            | 796      | **69**   | **−91.3%**               |
| 设置里拨一个开关（DOM 变动）      | 1528     | **37**   | **−97.6%**               |
| 设置里改列表密度，40 行列表跟着变 | 1539     | **30**   | **−98.1%**               |
| 设置里切「显示专辑列」            | 1541     | **45**   | **−97.1%**               |
| 切歌一帧（1000 首曲库）           | 41       | 41       | 持平（本来就是单行更新） |
| 单击一行（1000 首曲库）           | 26       | **15**   | −42%                     |
| 播放中 3 秒的 DOM 变动            | 168      | **135**  | −20%                     |
| 播放中 3 秒的属性写入             | 120      | **84**   | −30%                     |
| 播放中 3 秒脚本时间               | 3 ms     | **2 ms** | −33%                     |
| 首屏就绪（40 首，无头）           | 383 ms   | 412 ms   | +29 ms                   |
| 首屏 DOM 节点数（40 首）          | 1708     | 2466     | +758                     |
| 1000 首首次成表                   | 641.8 ms | 634.8 ms | 基本持平                 |
| 1000 首时 DOM 节点数              | 28451    | 28390    | 基本持平                 |

**一句话**：迁移的收益集中在「**一次状态变化会牵动多少 DOM**」上 ——
设置层从「整块重建 740 个节点、销毁 736 个」变成「改 8 个节点」，
列表级更新（密度 / 专辑列 / 设置开关）的 DOM 变动量下降到 **2%~3%**。
代价是首屏多约 30ms 与约 750 个 Lit 绑定标记节点（固定开销，
1000 首时相对量可忽略）。

## 3. 逐项数据

### 3.1 设置层（迁移前最大的性能问题）

| 操作                 | 指标            | 迁移前    | 迁移后   |
| -------------------- | --------------- | --------- | -------- |
| 打开设置层           | 新增节点        | 740       | 20       |
|                      | 移除节点        | 6         | 12       |
|                      | 总变动          | 796       | **69**   |
| 拨动「界面动画」开关 | 新增 / 移除节点 | 740 / 736 | 8 / 8    |
|                      | 总变动          | 1528      | **37**   |
|                      | 墙钟耗时        | 449.4 ms  | 405.3 ms |
| 切换列表密度         | 新增 / 移除节点 | 740 / 738 | 8 / 6    |
|                      | 总变动          | 1539      | **30**   |
| 切换「显示专辑列」   | 总变动          | 1541      | **45**   |

迁移前 `refreshSettingsLayer()` 会 `renderSettings(body)` ——
把 2600 行 HTML 重新拼一遍并整块替换，然后靠
「记住 scrollTop / 记住当前分区 / 记住焦点元素再补回去」把用户状态复位。
迁移后这两件事都不存在了：DOM 节点原地复用，滚动与焦点天然还在
（工具脚本里实测 `scrollBefore === scrollAfter`）。

### 3.2 播放中的持续开销（3 秒）

| 指标                | 迁移前  | 迁移后     |
| ------------------- | ------- | ---------- |
| DOM 新增 / 移除节点 | 24 / 24 | 24 / 24    |
| 属性写入            | 120     | **84**     |
| 文本写入            | 0       | 3          |
| 总变动              | 168     | **135**    |
| 脚本时间            | 3 ms    | **2 ms**   |
| 任务时间            | 126 ms  | **115 ms** |
| 布局时间            | 10 ms   | **8 ms**   |
| 样式重算            | 12 ms   | 14 ms      |

迁移前每帧 `tick()` 串行跑 13 个函数、其中 `paintPlayerBar()` 每帧
20 多次 `querySelector`；迁移后由组件的依赖数组决定谁更新，进度只驱动
`<mp-playerbar>` 与 `<mp-progress>` 的少数 part。

### 3.3 大曲库（1000 首）

| 操作           | 指标             | 迁移前   | 迁移后   |
| -------------- | ---------------- | -------- | -------- |
| 首次成表       | 墙钟             | 641.8 ms | 634.8 ms |
|                | 新增节点（累计） | 25967    | 29764    |
| 切歌一帧       | 总变动           | 41       | 41       |
| 单击某一行     | 总变动           | 26       | **15**   |
| 打开设置层     | 总变动           | 1518     | **57**   |
| 切换列表密度   | 总变动           | 1530     | **37**   |
| 切换显示专辑列 | 总变动           | 1541     | **45**   |
|                | 墙钟             | 535.8 ms | 514.1 ms |

1000 首时首屏新增节点里迁移后更多（+3797），原因是 Lit 会为每个绑定插一个
注释标记节点；但**最终 DOM 节点数两者相同**（28451 vs 28390），
因为列表一旦稳定就只做增量更新。

## 4. 产物体积

|                    | 迁移前                    | 迁移后                                    |
| ------------------ | ------------------------- | ----------------------------------------- |
| JS 合计            | 374.3 KB                  | 407.1 KB（+8.8%）                         |
| —— 其中 Lit 运行时 | 0                         | 40.1 KB（`assets/base-*.js`）             |
| CSS                | 157.8 KB                  | 158.2 KB（+0.4 KB，新增 `mp-*` 宿主规则） |
| `index.html`       | 42.7 KB（含全部静态骨架） | **23.1 KB**（-45.9%，骨架移入模板）       |
| 静态资源合计       | 574.8 KB                  | 588.4 KB（+2.4%）                         |

移除的手写 diff / 渲染代码基本抵消了 Lit 运行时的体积，
最终静态资源只增加 2.4%，而 `index.html` 小了一半。

## 5. 复跑方式

`@bash

# 迁移前的基线（已在本仓库验证过流程）

git worktree add .task/baseline HEAD
cmd /c "mklink /J .task\baseline\node_modules .\node_modules"
cd .task/baseline/frontend && node ../../node_modules/vite/bin/vite.js build && cd ../../..

# 两个构建各跑一次（结果落盘后再对比）

$env:PERF_OUT='.task/perf-baseline.json'; node tools/perf-lit.mjs .task/baseline/frontend/dist baseline
$env:PERF_OUT='.task/perf-lit.json'; node tools/perf-lit.mjs frontend/dist lit
`@

> 注意：无头浏览器里 `--disable-gpu` + 软件光栅，绝对耗时（ms）
> 会明显高于真实带 GPU 的应用；**相对差异与 DOM 变动量**才是这里要看的量。
> 每项测量都在同一进程、同一视口、同一数据下取得，两者可比。
