# 播放界面样式（插件）

这个目录里的每个**子目录**都是一个样式插件。应用启动时扫描一次，
在「设置 → 播放界面样式」里点「重新扫描样式」可以立刻重扫。

内置样式与你自己写的样式走**完全一样**的加载路径：应用自带的经典 / 沉浸
放在安装目录的 `resources/player-skins/` 下（只读），你放在这里的这份是
「用户自己写的」（可改、可删）。所以你可以直接把内置样式的目录整份拷过来当起点。

## 目录结构

```
player-skins/
  _template/          示例插件（下划线开头 = 不参与扫描，复制它改个名就能用）
    skin.json         清单（必需）
    skin.js           入口（必需，清单里的 entry 可改；带 JSDoc 类型）
    types.js          契约的 JSDoc 类型清单（**只给编辑器看，运行期不加载**）
    skin.css          外观（可选，清单不写 styles 时会自动带上目录里顶层的 *.css）
    assets/icon.svg   自带图标（可选；不写就用宿主图标）
    lib/…             自带的私有模块（可选；只允许插件目录内的相对 import）
  aurora/             你自己的样式（目录名 = id）
```

> 下划线 / 点开头的目录不会被扫描（`_template` 就是靠这条不出现按钮组里）。

## 四条硬规则

1. **零 import**：不要 import 应用的任何模块（`store` / `utils` / `bridge` /
   `@localmusicplayer/player-skins` 等），也不要用相对路径去够别人目录里的文件。
   公共零件从 `ctx.sdk` 拿（见下）。
2. **不用自己写 CSS 作用域前缀**：宿主会把你的 CSS 包成
   `@layer skin { @scope (<你的舞台>) { … } }` —— 你写不到标题栏 / 底栏 / 浮层，
   也不会污染别的界面。同时 `@layer skin` 让你压不过宿主壳（那本来就不该你管）。
3. **在清单里声明 `colors`**：宿主用它决定**自己的**控件栏与浮层配色，
   并保证对比度可读。跟随宿主主题的样式写 `{ "theme": true }` 即可；
   缺了也不报错，但会在设置页的样式卡片上出现一个警告图标。
4. **让开宿主壳（安全区）**：舞台铺满播放页，而宿主的**标题栏 + 头部行**与
   **底部播放控件栏**是浮在画面上、盖在你的画面之上的。任何**要给人读的内容**
   （曲名 / 歌手 / 时间码 / 提示文案 / 歌词）都不许画进这两条带子里 ——
   否则就是宿主 UI 叠在插件 UI 上，两边都看不清。让开的写法见下面「安全区」一节。

## 安全区（`--skin-inset-top` / `--skin-inset-bottom`）

宿主把两条 chrome 带子的高度作为两个自定义属性挂在舞台根上，值随窗口宽度与舞台类型变：

| 变量 | 含义 | 主窗口的典型值 |
| --- | --- | --- |
| `--skin-inset-top` | 顶部让开的高度 = 标题栏 + 详情页头部行 | 88px（36 + 52） |
| `--skin-inset-bottom` | 底部让开的高度 = 播放控件栏 | 86~92px（窗口越窄越矮） |

自己排版的 HUD 一律这样写：

```css
.hud {
  position: absolute;
  inset: 0;
  display: flex;
  flex-direction: column;
  justify-content: space-between;
  padding: calc(var(--skin-inset-top, 0px) + 20px) 26px calc(var(--skin-inset-bottom, 0px) + 18px);
}
```

- **兜底值必须写 `0px`**：桌面背景歌词窗口（`interactive:false` 的那个舞台）没有这两块
  chrome，宿主会把它们归零；写死 88px 的话那个窗口里会凭空空出一条边。
- 声明了 `capabilities.background: true` 的样式舞台是 `inset: 0`（铺满整窗），**必须读**；
  没声明的样式舞台本来就夹在两块 chrome 之间，读到的是 `0px`，照写不亏。
- **装饰层可以画到带子底下去**（背景图 / 渐变 / 粒子 / 光晕），**要读的文字不行**。
- ⚠️ 窄窗口与降级档的 `padding` 覆盖最容易把这两项吃掉
  （`.x[data-narrow="1"] .hud { padding: 20px }` 会把安全区一起抹掉）——
  改内边距时把 `calc(var(--skin-inset-*, 0px) + Npx)` 原样带过去。

## 清单（skin.json）

```json
{
  "id": "aurora",
  "name": "极光",
  "version": "1.0.0",
  "apiVersion": "3.0",
  "author": "你的名字",
  "description": "一句话说明",
  "entry": "skin.js",
  "styles": ["skin.css"],
  "icon": { "file": "assets/icon.svg" },
  "order": 200,
  "capabilities": { "spectrum": true, "background": true, "interactive": true },
  "colors": { "bg": "#0b1020", "fg": "#f2f4ff", "accent": "#7aa2ff" },
  "performance": { "budgetFps": 45 }
}
```

| 字段 | 说明 |
| --- | --- |
| `id` | 必须与目录名一致 |
| `apiVersion` | 契约版本。`major` 必须与宿主相同；`minor` 可以比宿主旧（宿主 3.2 能跑声明 3.0 的插件） |
| `entry` | 入口模块，默认 `skin.js` |
| `styles` | CSS 文件（相对插件目录）。不写就自动带上目录里顶层的 `*.css` |
| `icon` | `{"file":"assets/icon.svg"}` 自带图标（推荐）；也可 `{"sprite":"disc"}` 用宿主图标 |
| `order` | 按钮组排序：内置是 10~90，第三方建议 ≥ 200 |
| `capabilities.spectrum` | 要用实时频谱就写 `true`。数据是**拉取式**的（`ctx.spectrum()`，固定 128 段全谱、读到才采样）；不声明就一次都收不到、宿主也一次都不采 |
| `capabilities.background` | 需要整窗背景层（`ctx.backgroundRoot`）。声明后宿主会把标题栏/底栏/侧边栏退成半透明，**舞台同时变成铺满整窗** —— 于是你必须让开宿主壳（读 `--skin-inset-*`，见「安全区」） |
| `capabilities.interactive` | 默认 true。`false` 表示宿主可能把你挂到"只能看"的舞台（桌面背景歌词窗口） |
| `colors.bg` / `colors.fg` | **你的画面**的主底色 / 前景色。宿主据此决定自己的控件栏用深色还是浅色，并在对比度不足时自动纠正。只画舞台的样式（`background: false`）注意：宿主会把**标题栏 / 底栏 / 舞台底色**一并换成 `colors.bg`，所以这两个色同时是你的画面与宿主壳的配色；声明了整窗背景层的样式则由你自己的背景层铺满整窗 |
| `colors.theme` | 画面跟随宿主主题（与 bg/fg 二选一）。内置的经典 / 沉浸就是这么声明的 |
| `colors.accent` | 可选专色。宿主壳里"被强调"的地方（播放/暂停图标、进度条与音量条的填充、切换按钮的选中块、选中行）用它，并自动配一个画在它上面的文字色（对比度不足会纠正）。不写就用你自己的 `colors.fg` —— 壳会是一套单色画面，所以想让按钮有个专色就写上它 |

## 入口（skin.js）

```js
export default {
  id: "aurora",          // 与清单一致（可不写）
  mount(ctx) {},         // 必需：往 ctx.root 写 DOM
  update(ctx, patch) {}, // 可选：宿主推来的增量更新
  destroy(ctx) {},       // 可选：清定时器 / 监听 / 引用
};
```

**类型补全（`types.js`）**

模板目录里的 `types.js` 是契约（`frontend/packages/player-skins/src/contract.js`）
的一份**自包含副本**：插件规定零 import，数据目录里 `import("@localmusicplayer/player-skins")`
解析不到东西，所以没办法直接把那边的 typedef 当类型来源。用法：

```js
// @ts-check
/** @type {import("./types.js").SkinModule} */
const skin = { mount(ctx) { ctx.sdk.… }, … };
export default skin;
```

于是编辑器里 `ctx.*` / `patch.*` / `ctx.sdk.*` 都有补全与类型检查。
`types.js` 不会被运行期加载，删掉也不影响插件加载；契约升级时以
`contract.js` 为准，把新字段照抄进来即可（它不参与任何门禁，抄漏不会报错）。

**接口速查**

```
ctx.root / ctx.backgroundRoot
ctx.track()      { id, title, artist, album, duration, kind }
ctx.media()      { song, cover, covers, coverIndex, lyrics }     ← 聚合快照
ctx.lyrics()     { lines: [{ time, text, trans?, words? }], index, status, statusText, source, text }
                 ← 多语言歌词：同一时间戳的多行已折叠成一行，第一行是 text，
                   其余语言进 trans（一起高亮）；只能画一行时用 sdk.lyricDisplayText 拼起来
                 ← 字级（逐字）歌词：words 是每个**字素**一个起始毫秒，与
                   sdk.splitGraphemes(text) 一一对应；createLyricsView / createFxLyrics
                   会自己按字点亮（基线样式里就是从「已唱 / 未唱」的**平滑填充**：
                   渲染器每帧给当前行的字素写 `--w` 0→1，样式用 linear-gradient +
                   background-clip: text 吃它即可）；把 setPosition(pos, { playing })
                   一起喂上才会平滑推进；
                   自己画 canvas 的样式（示例见仓库的 plugins/style/magic-circle）
                   得自己按 words 点亮 —— 字素切分务必用 sdk.splitGraphemes，
                   并且 words.length 与字素数对不上时（多语言行 `原文 · 译文`
                   的 words 只对应原文）要整行回退成逐行歌词，不然会点错字；
                   自己按墙钟外推位置时**必须**过 sdk.steadyPosition（见下）
ctx.covers()     { list, index, current }
ctx.playback()   { position, duration, playing, volume, muted }
ctx.options()    { showLyrics, lyricsFontSize, animations, coverCarousel, …, interactive }
ctx.env()        { themeId, mode, width, height, dpr, reducedMotion, foreground }
ctx.spectrum()   { bands: Float32Array(128 段对数全谱, 0..1), at: 采样时刻 } | null
                 ← 拉取式：调用才采样（~30Hz 节流）；没在播放 / 没声明能力 = null
ctx.sdk          createLyricsView / createFxLyrics / createCamera / createBackgroundLayer /
                 marqueeText(el, text)（标题单行，放不下时横向跑马灯）/ applyFit /
                 steadyPosition / POSITION_HOLD_MS（逐字填充的位置防回退，见下）/ parseLrc /
                 splitGraphemes / findLyricIndex / formatLrcTime /
                 lyricDisplayText / html.{EMPTY_TRACK,escapeHtml,setCoverImage,subtitleOf,lyricsEmptyText} / util.{clamp,debounce}
ctx.actions      seek(ms) / seekBy(ms) / seekRatio(0..1) / togglePlay / next / prev /
                 toggleLike / openFolder / openCoverPanel / openLyricsPanel / reportBackdrop({bg,fg})
ctx.on(type, fn) 订阅一次更新（返回退订函数）
ctx.defaultCover / ctx.themeId / ctx.mode
```

`update(ctx, patch)` 与 `ctx.on(type, fn)` 收到同一份 patch，`patch.type` 取值：

| type | 载荷 | 什么时候来 |
| --- | --- | --- |
| `mount` | 全量快照 | 挂载之后立即一次 |
| `song` | `{ song, cover, covers, coverIndex, lyrics }` | 换歌 |
| `media` | `{ cover, covers, coverIndex }` | 封面变化 / 轮播切图 |
| `lyrics` | `{ lyrics }` | 歌词装载完成或匹配状态变化 |
| `progress` | `{ position, duration, playing, lyricIndex }` | 播放进度（已按帧节流；position 已外推且单调不减） |
| `state` | `{ playing, volume, muted }` | 播放 / 暂停 / 音量 |
| `options` | `{ options }` | 设置项变化 |
| `theme` | `{ themeId, mode }` | 主题 / 深浅色变化 |
| `resize` | `{ width, height }` | 舞台尺寸变化 |
| `close` | — | 详情页关闭（**要停帧就认这个**） |
| `destroy` | — | 即将卸载（`destroy` 之前最后一次） |

> 这张表就是 `contract.js` 的 `PATCH_TYPES`，`frontend/tests/skin-patch-contract.test.js`
> 会拿宿主源码里真正推的类型跟它逐项对账 —— 早期版本这里多列过
> `visibility` / `chrome` 两类宿主从来不推的补丁（照着写就是永远不触发的分支），
> 现已删掉。壳层配色不走补丁：宿主按你清单里的 `colors` 算好后写成
> `--chrome-bg` / `--chrome-fg` / `--chrome-accent` 等 CSS 变量挂在舞台根上，
> 直接 `var(--chrome-bg)` 用即可。

不确定某类更新时，直接用 `ctx.track()` / `ctx.lyrics()` / `ctx.playback()` 现取快照 ——
**任何一次推送之后，快照与刚推的载荷一定一致**。

**实时频谱没有补丁**：它是拉取式 `ctx.spectrum()` —— 在你自己的更新/帧循环里现取，
调用才会触发采样（不调 = 零开销，固定 128 段全谱、约 30Hz 刷新一次缓存）。
返回 `null` 有三种原因：没在播放、刚开播样本还没攒够、清单没声明
`capabilities.spectrum`（最后一种控制台会提醒一次）。`at` 是采样时刻，
连续两帧读到同一个 `at` 是正常的。

### 逐字填充的位置：一定要过 `sdk.steadyPosition`

宿主的 `patch.position` 已经按锚点外推到推送时刻、并且**单调不减**，
但引擎的 `Position()` 是按音频缓冲块推进的（48kHz / 1024 帧 ≈ 21ms 一跳），
而渲染侧一般又按墙钟连续外推。每 250ms 重新对齐时，位置可能比上一帧外推值
小半块 —— 如果直接拿它画逐字填充，填充边界会往回退，正好压在边界上的那个字
会「已经点亮 → 被取消 → 几十毫秒后又重新点亮」。

`createLyricsView` / `createFxLyrics` 内部已经处理好了；自己画 canvas / DOM
做逐字点亮时，把外推位置过一遍：

```js
const pos = ctx.sdk.steadyPosition(lastPos, ctx.playback().position + 外推毫秒);
lastPos = pos; // 下一次拿它当 prev
```

规则：小幅回退（≤ `ctx.sdk.POSITION_HOLD_MS`，默认 300ms）吸附到上一次；
大幅回退（用户 seek / 换歌）照单全收。

### 歌词零件的旋钮（`sdk.createLyricsView`）

画面的结构归你，字号归用户 —— 零件读这几个 CSS 变量，写在你自己的作用域里即可
（写在 `:scope { … }` 上最省事：它是舞台根，整棵子树都继承。
⚠ 是 `:scope`（伪类），**不是 `::scope`** —— `::scope` 不是合法伪元素，
浏览器会把**整条规则**丢掉，表现是"变量全是空的、依赖它们的整条 `background` 一起失效"，
而且控制台一声不吭）：

| 变量 | 含义 | 默认 |
| :--- | :--- | :--- |
| `--lyric-size` | **用户设置**的歌词字号（设置 → 歌词字号） | 宿主下发，16px |
| `--lyric-size-active` | 当前行的字号 | 正文字号 × 1.3125 |
| `--lyric-dim` | 非当前行压暗到多少 | `0.36` |
| `--lyric-pad` | 滚动区上下留白（把当前行顶到中间） | `34%` |
| `--lyric-measure` | 单行文字的最大宽度 | `760px` |

★ **不要写 `--lyric-size: <固定值>`**。自定义属性是普通继承，本元素的声明就近压过
祖先，你写死它，用户拖字号滑杆就再也不会有效果（内置样式曾经就是这个毛病）。
想让歌词比用户的设置更大 / 更小，改 `--lyric-size-active`（当前行）与
`--lyric-dim`（压暗程度）就够了；确实需要整体缩放，就在自己的舞台上按舞台尺寸算
（`calc(var(--你的舞台高) * 0.03)`），别把用户的值抄过来当常量。

## 排错

- 按钮组里没有你的样式：确认目录里有 `skin.json` + `entry` 指向的入口文件，
  且目录名不以 `_` / `.` 开头；
- 出现了但点开没变化：按 F12 看控制台，宿主会打印加载失败的原因；
  设置页的「播放界面样式」卡片里也会列出失败原因；
- 样式卡片上有警告图标：说明清单里的 `colors` 缺失或写法不对（悬浮看原因），
  宿主已降级用主题配色画自己的控件栏；
- 改了没生效：`/skins/` 的响应带 `no-store`，不会缓存；如仍是旧的，点一次
  「重新扫描样式」。

自带图标、贴图、字体的路径都相对插件目录写（`assets/bg.png`），
不能引用网络资源（CSP 会拦）。
