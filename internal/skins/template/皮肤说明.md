# 播放界面样式（皮肤）

这个目录里的每个**子目录**都是一个样式包。应用启动时扫描一次，
在「设置 → 播放界面」里点「重新扫描样式」可以立刻重扫。

## 目录结构

```
player-skins/
  _template/          示例样式（下划线开头 = 不参与扫描，复制它改名即可）
  aurora/             你自己的样式
    skin.json         可选清单
    skin.js           入口模块（必需）
    skin.css          样式（可选，不写清单时会自动带上目录里所有 .css）
```

## 最少要写什么

把 `_template/` 整个复制成你的目录名（例如 `aurora`），
然后把文件里的 `__SKIN_ID__` 全部替换成同样的 id 即可 —— 只有 `skin.js`
是必需的，目录名就是默认的样式 id 与名字：

```js
export default {
  id: "aurora",
  name: "极光",
  icon: "disc", // 图标 sprite 的 id，可省略
  order: 200, // 样式按钮组里的排序，小的在前
  mount(ctx) {}, // 建 DOM：往 ctx.root 里写
  update(ctx, patch) {}, // 宿主推来的更新（换歌 / 进度 / 歌词 / 设置 / 主题 / 尺寸）
  destroy(ctx) {}, // 清理
};
```

`ctx` 提供的数据与动作，以及 `patch.type` 的全部取值，都写在
`_template/skin.js` 的注释里（也可以看仓库里的
`frontend/packages/player-skins/src/contract.js`，那是接口的唯一定义）。

## 清单（skin.json）

```json
{
  "name": "极光",
  "version": "1.0.0",
  "module": "skin.js",
  "styles": ["skin.css"]
}
```

清单坏了不影响使用：会被忽略并按「没有清单」的默认约定处理。

## 三条必须遵守的约定

1. **样式要自己限定作用域**：所有选择器都用
   `.playerview[data-skin="<你的 id>"]` 开头。否则会改到应用其它地方。
2. **不要 import 应用内部模块**（store / bridge / utils），也不要直接操作
   `<audio>` 元素 —— 那些是宿主内部实现，接口只保证 `ctx` 这一层。
3. **别在样式里写定时器轮询数据**：宿主会主动推更新；用轮询会在换歌、
   暂停、切主题时出现一帧的旧数据。

## 排错

- 样式按钮组里没有出现你的样式：确认目录里有 `skin.js`（不是 `skin.js.txt`），
  且目录名不以 `_` 或 `.` 开头。
- 出现了但点开没变化：按 F12 看控制台，宿主会把加载失败的原因打出来；
  设置页的「播放界面」卡片里也会列出加载失败的样式与原因。
- 改了没生效：`/skins/` 的响应带 `no-store`，不会缓存；如果还是旧的，
  点一次「重新扫描样式」。
